# 三大框架上下文处理策略对比

本页对比 Google ADK、[[langchain]]、[[agentscope]] 三大框架对短期记忆上下文处理的实现方式，依据《AI Agent 记忆系统》（柳遵飞（翼严））第三章（该章引用三者官方文档佐证，参考列表 [2][3][4]）。三框架共同前提是 [[记忆会话边界二分]] 的会话级/跨会话级两分；本页聚焦其各自的上下文策略载体与集成方式差异。

## 对比表

| 维度 | Google ADK | LangChain | AgentScope |
|---|---|---|---|
| 策略载体 | `events_compaction_config`（App 级配置） | `SummarizationMiddleware`（中间件） | `autocontextmemory`（实现 Memory 接口的记忆组件） |
| 核心方法 | 事件压缩：`compaction_interval=3`、`overlap_size=1` | 摘要：4000 tokens 触发、摘要后保留最后 20 条消息 | 超阈值自动应用 6 种渐进式压缩策略 |
| 集成方式 | 压缩配置与 Session 数据存储**独立（解耦）** | 摘要配置与短期记忆数据存储**独立（解耦）** | 实现 Memory 接口，与 Agent 构建流程**无缝集成** |
| 历史可追溯性 | —（源文未展开） | —（源文未展开） | 四层存储架构（工作内存/原始内存/卸载上下文/压缩事件），支持完整历史追溯 |

## 代码实证

**Google ADK（事件压缩）：**

```python
from google.adk.apps.app import App, EventsCompactionConfig

app = App(
    name='my-agent',
    root_agent=root_agent,
    events_compaction_config=EventsCompactionConfig(
        compaction_interval=3,  # 每3次新调用触发压缩
        overlap_size=1          # 包含前一个窗口的最后一次调用
    ),
)
```

**LangChain（摘要中间件）：**

```python
from langchain.agents import create_agent
from langchain.agents.middleware import SummarizationMiddleware

agent = create_agent(
    model="gpt-4o",
    tools=[.],   # 原文如此，疑为 tools=[...] 的排版截断
    middleware=[
        SummarizationMiddleware(
            model="gpt-4o-mini",
            max_tokens_before_summary=4000,  # 4000 tokens时触发摘要
            messages_to_keep=20,  # 摘要后保留最后20条消息
        ),
    ],
)
```

**AgentScope（AutoContextMemory）：**

```java
AutoContextMemory memory = new AutoContextMemory(
    AutoContextConfig.builder()
        .msgThreshold(100)
        .maxToken(128 * 1024)
        .tokenRatio(0.75)
        .build(),
    model
);
ReActAgent agent = ReActAgent.builder()
    .name("Assistant")
    .model(model)
    .memory(memory)
    .build();
```

## 结论（源文主张）

1. ADK 与 LangChain 均采用"策略配置与记忆数据存储解耦"的路线，策略作为外挂配置存在；
2. AgentScope 的 [[autocontextmemory]] 直接实现 Memory 接口，压缩能力内嵌于记忆组件本身，集成最无缝；
3. AutoContextMemory 相比另两者的三点优势：更精细的 6 种渐进式压缩、Memory 接口集成、四层存储完整可追溯。
