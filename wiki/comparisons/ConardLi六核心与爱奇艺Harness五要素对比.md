# ConardLi 六核心与爱奇艺 Harness 五要素对比

两个独立来源几乎同期提出了"用工程化 harness 约束 agent"的方法论：爱奇艺数据库团队（[[harness-engineering]]，五要素，工程级口径）与独立创作者 ConardLi（六核心 + Skill 级落地，见 [[Harness六大核心部分]]）。

## 要素映射

| ConardLi 六核心 | 爱奇艺五要素 | 映射说明 |
|----------------|-------------|----------|
| 上下文管理 | 执行依据（部分） | 爱奇艺强调执行语义冻结的文档依据；ConardLi 强调"模型到底看到了什么"（分阶段文档+三文件记忆） |
| 工具系统 | 工具边界 | 几乎直接对应（能做什么 vs 边界约束） |
| 执行编排 | 任务入口 + 执行依据 | 单一入口分阶段流水线 vs 五要素流程化任务入口 |
| 状态与记忆 | 结果记录（部分） | outline.md 工作记忆 vs 结果留痕供进化 |
| 评估与观测 | 验证反馈 | 硬性自检+三级评审 vs 验证五层模型 |
| 约束与恢复 | 工具边界 + 验证反馈（部分） | 权限/重试/回滚/断点续跑 vs 门控与红线 |

## 关键差异

1. **层级谱系**：爱奇艺为工程级方法论（五要素架构模型、渐进演化、工具无关），ConardLi 证明六核心可以纯 Skill（文档+流程约定）形式落地——即 [[Skill级Harness论]] 的"Skill 级协作协议 vs 工业级运行系统"。ConardLi 明确澄清："做 Harness 不一定要从零搭 Agent。"
2. **"人的判断"地位**：ConardLi 的 [[Harness核心价值三元组织论]] 把"人的判断"显式列为流程组织对象（Plan 检查点、首章验收、全网页点验均为流程内门控）；爱奇艺五要素表述中人工节点隐含在验证反馈内，未上升为定义级要素。
3. **共同底层逻辑**：两者都是"包裹层"——用工程结构包裹 agent 行为，与"工程系统包裹层"的跨团队共识（美团规范、腾讯武器库、小红书记忆四件套）一致，并为 [[agent生产落地环境重构论]]、[[脚手架优于模型]] 提供了"编排优先于模型能力"的独立创作者版本证据。

## 口径差异记录（非矛盾）

"Skill 也是 Harness"（ConardLi）与爱奇艺的重工程口径属于同一方法论的层级差异，不应判为对立证据；两文均强调工具无关性与"模型已够强，问题在工程条件"的前提。
