# Agent 记忆存储方案对比

Wiki 已同时收录长期与短期记忆方案但缺系统对比（review-e44c0155/61067c4c 立项）。三轴比较如下。

## 方案 × 三轴

| 方案 | 存储介质 | 时效机制 | 结构化程度 |
|---|---|---|---|
| **Tair 短期记忆**（淘宝闪购） | 内存数据库（List/Hash 双轨） | **TTL 硬过期**（会话级生命周期） | Hash field 级精细读写 |
| **长记忆四件套**（小红书 PMO） | 结构化存储 | 长期保留+检索 | 结构化四件套 |
| **OpenClaw 双层记忆** | Markdown 自由文本 | 算法**时间衰减**（[[记忆时间衰减]]） | 自由文本（[[markdown多层记忆体系]]） |
| **memdir**（Hermes 系） | 目录文件+按需加载 | 无硬过期，按需淘汰 | 半结构化（YAML description） |
| **Deep-Sleep 晋升**（RDSClaw） | LanceDB 向量库 | 评分**晋升门控**（六维评分） | 向量+元数据 |

## 选型判据（从三轴归纳）

1. **时效确定性要求高**（会话状态、购物车）→ TTL 硬过期（Tair 型）：过期即删，不留垃圾；
2. **经验资产要求长期沉淀**（个人助理、团队知识）→ 衰减/晋升门控（OpenClaw/RDSClaw 型）：好坏由使用检验；
3. **人类可读可编辑优先** → Markdown 自由文本；**机器读写性能优先** → 数据库 field 级；
4. 阿里系实践（Tair+RDSClaw+RDSHermes）暗示：**生产级 Agent 记忆正在向云数据库收敛**，Markdown 系停留在个人/轻量场景。
