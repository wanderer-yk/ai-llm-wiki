# 苏雄 800 行框架与 Pi Agent / 极简 Agent 设计哲学对比

三个实现同属「Agent 极简谱系」：零框架依赖、直接基于基础 SDK/标准库、代码库本身作为上下文工程的一部分（[[极简agent设计哲学]] 的核心主张）。差异在**复刻面宽度**与**工程完备度**两个维度上系统性拉开。

## 一、苏雄 800 行框架 vs Pi Agent（同宗不同代）

| 维度 | [[轻量级单进程agent框架]]（苏雄 800 行） | [[pi-agent]]（OpenClaw Agent Core） |
|---|---|---|
| 定位 | 独立复刻 OpenClaw 核心机制的教学/工程实践 | OpenClaw 官方底层 Agent Core（工业级） |
| 工具面 | ≥9 个（文件四件套+Exec+Web 双件+Message+Cron+Spawn） | 4 个（Read/Write/Edit/Shell） |
| 子 Agent | 完整体系（SpawnTool + SubagentManager + 并发上限 + 工具排除） | 无（扩展交给 Skills 层） |
| 并发控制 | [[互斥锁与暂存队列]]（Mutex 保护 pendingSubagentResults） | 无（[[极简agent设计哲学]] 描述中未涉及） |
| 消息机制 | [[入站消息总线]]（subscribe 回调 + drain 轮询双消费） | 事件机制（[[pi-agent]] 页描述） |
| 定时调度 | CronService（add/list/remove 三 action） | 无 |
| 启动加载 | skills + memory（ContextBuilder） | Skills 扩展机制 |
| 智能观 | 实现面宽=工程能力强 | 「智能不来自工具数量，而来自 [[上下文工程]] 的质量」 |

**共识**：文件操作四件套 + Shell 是不可再削的核心同构；框架只提供系统能力，领域知识外置（skills/memory/Skills 层，与 [[agent三层商用架构]] 的分层理念一致）。

**分歧**：Pi Agent 把"极简"贯彻为能力边界（4 工具 + 事件 + Skills 即完成闭环），苏雄框架则把"极简"理解为**不借助框架**而非**功能最薄**——用 800 行把子 Agent、并发、调度、消息总线全部收进单进程。前者是产品哲学，后者是教学性全景复刻。

## 二、vs 极简 Agent 设计哲学（279 行 Python）

| 维度 | 苏雄 800 行 | yabohe 279 行 |
|---|---|---|
| 语言/依赖 | TypeScript + `@anthropic-ai/sdk` | Python 单文件零依赖 |
| 工具 | ≥9（含 Web/子 Agent/调度） | 4（shell_exec/file_read/file_write/python_exec） |
| 取舍声明 | [[有意取舍边界声明]]（不涉及 Context/Memory/持久化/Bot 层） | 自述局限：健壮性/安全性/流式/MCP/上下文压缩待改进 |
| 工程能力 | 并发控制+消息双通道+定时调度 | 单线程顺序执行 |

同谱系点：零框架依赖 + 显式取舍声明 + 代码即上下文。差异随行数扩大：279→800 行的三倍增量几乎全部投在**工程能力**（并发/消息/调度）而非工具数量本身，印证 [[薄抽象设计哲学]] 的定价方式——每一层能力都可用极薄代码换来，前提是坚持单进程单线程的硬约束。

## 三、调度范式对照：入站消息总线 vs 文件轮询架构

| 维度 | [[入站消息总线]]（苏雄框架） | [[文件轮询架构]]（[[zhiyuanfu]] / 24h 打工人） |
|---|---|---|
| 暂存介质 | 进程内存队列（`InboundMessage[]`） | 文件系统 + JSON 状态 |
| 消费模式 | subscribe 实时回调 / drain 轮询取空（单路径路由，绝不同时） | 周期轮询 CLI 队列 |
| 失败语义 | 无持久化，进程重启消息丢失 | 文件可 Git 追溯，出问题让 AI 直接看文件 |
| 管理对象 | 自己实现的单进程 Agent | 已是完整 Agent 的 CLI（codex/gemini-cli/claude-code） |
| 层级 | Agent 内部组件（进程内） | Agent 之上的元调度层（跨进程） |

范式同构点：**暂存-轮询消费**（无订阅者入队 → 稍后 drain）在两个量级上重复出现。本质差异在信任边界：内存队列赌的是"进程不挂"，文件队列赌的是"磁盘在就行"——前者换来零延迟与零序列化成本，后者换来可观测性与环境无关性。两者也分别对应 [[薄抽象设计哲学]]（进程内解决）与"不造 Agent 造调度层"（进程外管理）两种路线的自我定位。

## 结论

1. 极简谱系没有唯一形态：**4 工具（Pi Agent）→ 4 工具+顺序执行（279 行）→ 9 工具+完整工程能力（800 行）** 是同一哲学在能力维度上的三个采样点，分界变量是"框架依赖"而非"功能多寡"。
2. 单进程单线程约束是三者的公共支点，[[子agent单进程并发模型]] 与 [[互斥锁与暂存队列]] 展示了该约束下并发能力的上限做法。
3. 「Open Claw」（苏雄文标题用名）与 [[openclaw]] 的层级关系：苏雄框架是对 OpenClaw 机制的独立复刻，与官方 [[pi-agent]] Agent Core 无代码承继关系——标题的"实现"指重新实现，非二次开发。
