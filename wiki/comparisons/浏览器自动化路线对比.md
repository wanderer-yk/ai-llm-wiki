# 浏览器自动化路线对比

「业务世界对 Agent 不可信 UI」这一问题下的两条路线轴（review-9f1efad3/a13e4470 合并立项）。

## 轴一：API 优先 vs 沙盘推演

| | [[api优先浏览器自动化]]（OpenCLI，明径） | [[agent-canvas沙盘机制]]（Amazon） |
|---|---|---|
| 策略 | 绕过 GUI 直取底层 API，操作面固化为 CLI | 不可逆业务动作先映射到可视化沙盘，推演后再执行 |
| 侧位 | **供给侧**暴露可调用面（[[软件竞争可调用性]]：软件竞争从界面转向可调用性） | **消费侧**构造安全推演空间 |
| 解决的核心风险 | UI 不稳定/选择器脆弱 | 业务动作不可逆的误执行 |
| 交叉 | 与 [[agent生产落地环境重构论]] 呼应；与沙盘路线构成分野 | 与 [[业务diff等价]] 守护思路同源 |

## 轴二：实时泛化 vs 预建专用

OpenCLI 自身的两阶段模式即此权衡的样本：**探索阶段**用 browser_* 类 MCP 工具实时操控（browser_navigate/snapshot/click，泛化但慢且不稳），**产出阶段**固化为确定性 CLI 适配器（专用但快且稳）——「探索用通用工具、执行用专用命令」。

- 与 [[mcp工具封装模式]]、[[RAG能力MCP服务化]] 的工具化路径同谱系：MCP 适合实时泛化，CLI 适合高频确定性执行；
- 推广到工具选型：**低频探索用 MCP 实时操控，高频固化用 CLI/专用工具**——工具化不是终点状态而是成熟度阶梯。
