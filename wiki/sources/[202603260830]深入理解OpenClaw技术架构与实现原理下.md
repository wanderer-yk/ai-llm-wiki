## 3.8 沙箱系统要点

Sandbox 是 [[openclaw]] 的 Docker 隔离层，exec/read/write/edit 等工具操作在容器而非主机执行，目的是限定工具执行安全边界、减少模型误操作的"爆炸半径"。详见 [[openclaw沙箱系统]]。

沙箱子系统源码结构：

```bash
src/agents/sandbox/
├── types.ts          # 核心类型定义
├── config.ts         # 配置合并逻辑
├── context.ts        # 入口点 - 解析沙箱上下文
├── docker.ts         # Docker 容器管理
├── browser.ts        # 隔离浏览器容器
├── tool-policy.ts    # 工具允许/拒绝策略
├── validate-sandbox-security.ts  # 安全验证
├── fs-bridge.ts      # 文件系统操作桥接
└── prune.ts          # 容器自动清理
```

三配置维度：mode（off / non-main【默认】/ all）× scope（session【默认】/ agent / shared）× workspaceAccess（none【默认，完全隔离工作区 `~/.openclaw/sandboxes`】/ ro 只读挂载到 /agent / rw 读写挂载到 /workspace）。默认安全基线：只读根文件系统、无网络（network: "none"）、丢弃所有能力（capDrop: ["ALL"]）；禁止绑定挂载 /etc、/proc、/sys、/dev、/root、/boot、/run、/var/run/docker.sock、/；禁止 host 与 container:<id> 网络模式。

配置示例（原文保留）：

```json
{
  "agents": {
    "defaults": {
      "sandbox": {
        "mode": "non-main",
        "scope": "session",
        "workspaceAccess": "none",
        "docker": {
          "image": "openclaw-sandbox:bookworm-slim",
          "network": "none",
          "memory": "512m",
          "cpus": 1
        },
        "prune": {
          "idleHours": 24,
          "maxAgeDays": 7
        }
      }
    }
  }
}
```

CLI：`openclaw sandbox list` / `openclaw sandbox recreate` / `openclaw sandbox explain`。

## 3.9 记忆管理关键数据

设计哲学为"文件即真相"（详见 [[文件即真相]]）：MEMORY.md = 长期记忆（精选、持久化），memory/YYYY-MM-DD.md = 短期记忆（append-only 日志），与 [[openclaw双层记忆系统]] 互证。

记忆文件布局：

```bash
~/.openclaw/workspace/
├── MEMORY.md           # 长期记忆（精选、持久化）
└── memory/
    └── YYYY-MM-DD.md   # 每日记忆日志（append-only）
```

核心类型定义：

```typescript

```

算法公式（与 [[混合召回]]、[[记忆时间衰减]] 互证）：

```ini
finalScore = vectorWeight * vectorScore + textWeight * textScore   # 混合融合，默认 0.7/0.3
score = λ × relevance - (1-λ) × max_similarity_to_selected          # MMR，默认 λ=0.7
decayedScore = score × e^(-λ × ageInDays)                           # 时间衰减，半衰期默认 30 天
tokenEstimate > contextWindow - reserveTokensFloor - softThresholdTokens  # memory-flush 触发
```

memoryFlush 配置示例（与 [[memory-flush机制]] 互证）：

```json
{
  agents: {
    defaults: {
      compaction: {
        reserveTokensFloor: 20000,
        memoryFlush: {
          enabled: true,
          softThresholdTokens: 4000,
          systemPrompt: "Session nearing compaction.",
          prompt: "Write any lasting notes to memory/YYYY-MM-DD.md."
        }
      }
    }
  }
}
```

Embedding 提供商自动选择链：local.modelPath 存在 → local；否则按 OpenAI（text-embedding-3-small 默认）→ Gemini（gemini-embedding-001）→ Voyage（voyage-4-large）→ Mistral（mistral-embed）key 可用依序选择；全部不可用则 disabled。索引更新四触发：会话启动、搜索前、定时刷新、文件变化（watcher 防抖 1.5s）；会话索引按 delta 阈值（100KB 或 50 条消息）异步更新。常青文件不衰减：MEMORY.md 与非日期命名文件（如 memory/projects.md），与 [[Evergreen免衰减]] 互证。

CLI：`openclaw memory status` / `openclaw memory sync --force` / `openclaw config get agents.defaults.memorySearch`。

3.9.12 总结论："让文件成为真相，让索引成为加速器。"

## 3.11 Session 管理关键数据

四层架构：Session Key（身份标识）→ Session Entry（会话元数据）→ Session Store（持久化存储）→ Transcript File（对话历史）。详见 [[openclaw会话管理架构]] 与 [[openclaw会话键结构化设计]]。

会话键基础格式 `agent:<agentId>:<rest>`，示例：

```
agent:main:main                    # 默认 agent 的主会话
agent:ops:work                     # ops agent 的主会话
agent:main:telegram:direct:user123 # Telegram DM 会话
agent:main:discord:group:guild789  # Discord 群组会话
agent:main:cron:daily-backup:run:uuid  # Cron 任务运行会话
agent:main:subagent:child-session  # 子代理会话
```

```javascript
function parseAgentSessionKey(sessionKey) {
  // 1. 规范化：小写、去空格
  const raw = (sessionKey ? "").trim().toLowerCase();
  // 2. 验证最小结构 (agent:id:rest)
  const parts = raw.split(":").filter(Boolean);
  if (parts.length < 3 || parts[0] !== "agent") return null;
  // 3. 提取 agentId 和 rest
  return { agentId: parts[1], rest: parts.slice(2).join(":") };
}
```

| 类型 | 识别模式 | 示例 |
|------|----------|------|
| direct | 包含 `:direct:` 或 `:dm:` | agent:main:telegram:direct:user123 |
| group | 包含 `:group:` | agent:main:discord:group:guild789 |
| channel | 包含 `:channel:` | agent:main:slack:channel:C123 |
| cron | rest 以 `cron:` 开头 | agent:main:cron:backup |
| subagent | 包含 `:subagent:` | agent:main:subagent:child |
| thread | 包含 `:thread:` 或 `:topic:` | agent:main:discord:group:123:thread:456 |

## 3.12 自进化机制要点

四支柱：可修改核心文件（AGENTS.md / SOUL.md / MEMORY.md / memory/YYYY-MM-DD.md）+ 动态系统提示（每次运行时重建）+ Skills 扩展系统 + 自我修改能力（agent 用 read/write/edit 修改自身）。系统提示内置 "OpenClaw Self-Update" 部分提供 `config.apply` 与 `update.run` 两条自我更新指令。进化循环：`用户指令/反馈 → Agent 修改文件 → 下次会话加载新内容 → 行为改变 → 持续迭代`。详见 [[openclaw自进化机制]]。

## 3.13 工作区与 Agent 路由关键数据

| 文件 | 角色 |

| AGENTS.md | 代理行为指南 |
| SOUL.md | 代理核心人格 |
| TOOLS.md | 工具定义 |
| IDENTITY.md | 身份配置 |
| USER.md | 用户偏好 |
| HEARTBEAT.md | 心跳任务 |
| BOOTSTRAP.md | 初始引导 |

## 3.14 Nodes 关键数据

Node = 可被 Gateway 远程执行命令的客户端设备（iOS/Android/三大桌面及任何运行 `openclaw node` 的设备）。核心数据结构：

| 类型 | 位置 | 用途 |
|------|------|------|
| `NodeListNode` | shared/node-list-types.ts | 节点列表展示（含 caps/commands/permissions） |

## 3.15 安全策略要点

核心定位：单用户"个人助手"信任模型，非多租户总线；sessionKey 是路由控制不是授权边界；插件=可信代码（进程内加载、与 Gateway 同权限）；同一 Gateway 操作者互相可见数据是预期行为。范围外八类误报：Prompt 注入（除非绕过边界）、操作者预期的本地功能（TUI `!` shell）、已授权用户本地操作、恶意插件行为、多租户隔离期望、需可信输入的 ReDoS/DoS、公网暴露（不建议但非漏洞）、第三方凭证暴露。部署假设：一用户一主机/VPS 一 Gateway；`gateway.bind="loopback"` 默认；远程访问走 SSH 隧道或 Tailscale serve/funnel。运行时硬要求 Node.js ≥ 22.12.0；Docker 非 root+只读 FS+最小权限。文件系统加固：`tools.exec.applyPatch.workspaceOnly: true`（推荐）、`tools.fs.workspaceOnly: true`（可选）。3.15.3 称沙箱默认配置为 `agents.defaults.sandbox.mode: off`（默认关闭）、`tools.exec.host: sandbox` 仅为路由偏好——与 3.8.3 所述默认值 non-main 存在原文内部张力，待官方源码核实。详见 [[openclaw单用户信任模型]]。

```typescript
export function deepMerge(target: unknown, source: unknown): unknown {
  if (Array.isArray(target) && Array.isArray(source)) {
    return [.target, .source]; // 数组连接
  }
  if (isPlainObject(target) && isPlainObject(source)) {
    const result = { .target };
    for (const key of Object.keys(source)) {
      result[key] = key in result ? deepMerge(result[key], source[key]) : source[key];
    }
    return result;
  }
  return source; // 原始类型: 后值覆盖前值
}
```
