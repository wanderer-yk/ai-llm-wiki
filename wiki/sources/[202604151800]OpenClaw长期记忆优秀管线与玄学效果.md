# OpenClaw长期记忆：优秀管线与玄学效果

城决于 2026-04-15 18:00 发布于微信公众号「[[千问AI平台]]」（IP 属地浙江，原创标记）。本 wiki 第三篇 OpenClaw 主题来源（另两篇为 [[sources/[202604082000]从OpenClaw看Agent架构设计]] 与 [[sources/[202604152000]OpenClaw落地到生产实际应用的一种可能的路径]]），也是 [[openclaw]] 原生记忆子系统迄今最细粒度的公开披露。全文论证结构「管线（原生）→ 批判（玄学）→ 方案（插件）→ 评测 → 落地」完整闭环。

**中心论点**：OpenClaw 提供了一套以 Markdown 文件为载体的多层记忆体系，管线覆盖记录、演进、召回全流程——设计理念优秀，但全流程以 LLM 弱约束方式进行决策，实际记忆效果往往不够稳定（即标题中的"玄学效果"）。解决方案为 [[RDSClaw]] 记忆插件 `openclaw-memory-alibaba-local`，在 [[LoCoMo10]] 评测中总体 58.18% → 72.08%（+13.90%）。

**核心论断**："在不改变底层 LLM 的前提下，仅通过记忆管线的工程优化就实现了近 14 个百分点的提升"——与 [[脚手架优于模型]] 同构的跨来源证据。

## 一、OpenClaw 记忆系统全景

核心设计原则："一切持久状态都是磁盘上的 Markdown 文件"。身份/规则/用户档案类文件（AGENTS/SOUL/USER.md）与动态记忆类文件（MEMORY.md、memory/YYYY-MM-DD.md）是两套不同机制，后者有专门的写入、演进、召回管线。

| 文件 | 用途 | 加载时机 |
|------|------|----------|
| `AGENTS.md` | 工作区规则、安全边界、红线指令 | 每次会话（最高优先级） |
| `SOUL.md` | Agent 个性、价值观、沟通风格 | 每次会话 |
| `IDENTITY.md` | Agent 身份元数据（名字、角色、头像） | 每次会话 |
| `USER.md` | 用户档案（名字、昵称、时区、个人背景） | 每次会话 |
| `TOOLS.md` | 环境配置（设备信息、SSH 主机、TTS 偏好） | 每次会话 |
| `MEMORY.md` | 长期记忆（已验证事实、决策、持久学习） | 仅 DM 主会话 |
| `memory/YYYY-MM-DD.md` | 日记忆（当天观察、临时笔记） | 当天 + 昨天自动加载 |
| `DREAMS.md` | 梦境日记（Dreaming 系统输出，仅供人类审查） | 不自动注入 |

AGENTS.md 默认模板设计哲学引文：

```
"Memory is limited — if you want to remember something, WRITE IT TO A FILE.
'Mental notes' don't survive session restarts. Files do."
```

详见 [[markdown多层记忆体系]]。

## 二、记忆写入：两条路径

- **路径一：Agent 主动写入（LLM 决策）**——是否写入、写入什么、用什么格式写入，完全由 LLM 在对话中自主决定；无结构化提取规则、无强制写入模板，AGENTS.md 模板指导属"方向性建议"。
- **路径二：Memory Flush**——Compaction（上下文压缩）前的安全网，"最后一次救济机会"。两路均写入同一 `memory/YYYY-MM-DD.md`，该文件是 Dreaming 系统的输入源。

Flush 双触发阈值：

| 参数/常量 | 默认值 | 含义 |
|---|---|---|
| `softThresholdTokens` | 4000 | Memory Flush 的 token 触发阈值（距 Compaction 的 token 距离） |
| `forceFlushTranscriptBytes` | 2MB | 文件大小触发阈值，防止 token 计数器过时 |
| `DEFAULT_MEMORY_DREAMING_ENABLED` | false | Dreaming 默认禁用（opt-in） |
| Cron 表达式 | `0 3 * * *` | Dreaming 默认每日凌晨 3 点全量扫描 |
| Jaccard 相似度阈值（Light Sleep） | 0.9 | Light Sleep 机械去重阈值 |

Flush 提取指令原文：

```
Pre-compaction memory flush turn.
The session is near auto-compaction; capture durable memories to disk.
Store durable memories only in memory/YYYY-MM-DD.md.
Treat MEMORY.md, DREAMS.md, SOUL.md, TOOLS.md, AGENTS.md as read-only during this flush.
If nothing to store, reply with NO_REPLY.
```

Flush 期间 `write` 工具被包装为 `appendOnly` 仅追加模式。详见 [[记忆写入双路径]]、[[memory-flush机制]]。

## 三、默认晋升方式

未启用 Dreaming 时，日记忆 → 长期记忆完全依赖 Agent 主动整理：①主会话直接写 MEMORY.md（可跳过日记忆）；②心跳期间定期回顾（每隔几天：读近期日记忆→识别值得长期保留的内容→蒸馏更新→清除过时信息）。作者评价："灵活但不确定"。详见 [[默认晋升方式]]。

## 四、Dreaming 梦境系统（三阶段）

opt-in 功能，启用后自动创建 Cron 任务默认 `0 3 * * *`，按 Light → REM → Deep 顺序执行。

**Light Sleep（摄取与去重，纯确定性、不调用 LLM）**：

| 信号源 | 规格 |
|---|---|
| 日记忆文件 `memory/YYYY-MM-DD.md` | 逐行提取候选片段：最小 8 字符，最大 280 字符，最多 4 行合并为一个块 |
| 会话转录 | 按 Agent 和 Session 聚合的历史消息：每次最多扫描 240 条，每个文件 12~80 条 |
| 短期回忆存储 | `memory/.dreams/short-term-recall.json` 中已有记录 |

去重：Jaccard ≥ 0.9；重复项合并取最高 recallCount/maxScore，合并 queryHashes 和 recallDays。输出 `## Light Sleep` 块 + `lightHits` 计数。详见 [[light-sleep摄取与去重]]。

**REM Sleep（主题反射与候选真理，机械统计）**：

```
strength = min(1, (count / totalEntries) × 2)

confidence = avgScore × 0.45 + recallStrength × 0.25 + consolidation × 0.20 + conceptual × 0.10
其中：
  recallStrength = min(1, log1p(recallCount) / log1p(6))
  consolidation  = min(1, recallDays.length / 3)
  conceptual     = min(1, conceptTags.length / 6)
```

阈值：Jaccard 0.88（比 Light 更严格）、置信度 ≥ 0.45、最多 3 条候选真理。详见 [[REM睡眠主题反射与候选真理]]。

**Deep Sleep（六维评分与晋升门控，机械公式）**：

| 信号 | 权重 | 计算方式 | 含义 |
|------|------|----------|------|
| 频率 (Frequency) | 0.24 | `min(1, ln(signalCount + 1) / ln(11))` | 被回忆的总次数（recall + daily + grounded） |
| 相关性 (Relevance) | 0.30 | `totalScore / max(1, signalCount)` | 每次被检索时的平均质量分 |
| 多样性 (Diversity) | 0.15 | `min(1, max(uniqueQueries, recallDays) / 5)` | 不同查询/日期上下文的覆盖宽度 |
| 时效性 (Recency) | 0.15 | `exp(-λ × ageDays)`，λ = ln(2)/14 | 指数衰减，半衰期 14 天 |
| 巩固度 (Consolidation) | 0.10 | `max(0.55×spacing+0.45×span, groundedCount/3)` | 多日重现 或 grounded 信号强度 |
| 概念丰富度 (Conceptual) | 0.06 | `min(1, conceptTags.length / 6)` | Concept 标签密度 |

```javascript
phaseBoost = LIGHT_BOOST_MAX(0.06) × lightStrength × lightRecency
           + REM_BOOST_MAX(0.09) × remStrength × remRecency
// 衰减半衰期同为 14 天
```

晋升门控三条件：`score ≥ 0.80` + `totalSignalCount ≥ 3` + `max(uniqueQueries, recallDays.length) ≥ 3`；通过后先**重新水合**（从实时日文件重读片段，防止写入过时/已删除内容）再追加到 `MEMORY.md`。详见 [[Deep-Sleep六维评分与晋升门控]]、[[Dreaming三阶段演进]]。

Dreaming 管线唯一 LLM 调用点是三阶段各自的梦境日记（后台 subagent 生成、追加到 `DREAMS.md`），仅供人类阅读、不参与晋升评分。详见 [[梦境日记叙事生成]]。

## 五、记忆召回与反馈环

- `memory_search` 检索 `MEMORY.md` + `memory/*.md`；双后端：builtin（SQLite + FTS，可选配 sqlite-vec 向量扩展）与 QMD；embedding 不可用时 builtin 自动降级为 FTS 全文索引 + 词法排名。
- 每次检索后异步 `recordShortTermRecalls` 记账写入 `memory/.dreams/short-term-recall.json`（查询/结果路径/评分）。
- Dreaming 正反馈环："越被检索 → 越容易晋升"（仅启用 Dreaming 时生效）。
- Active Memory 插件启用时，主回复前子 Agent 自动预取。
- 检索侧另有可选时间衰减：默认关闭，半衰期 30 天。

详见 [[记忆召回与反馈环]]。

## 六、随机性的代价：原生记忆不确定性链路

四环节（展开为六项不确定性）叠加的原文链路图：

```
对话内容
  ↓ ❶ LLM 自主判断是否写入（可能遗漏）
  ↓ ❷ 短对话无 Flush 安全网（可能不触发）
日记忆文件
  ↓ ❸ 晋升不确定或不准确
  │   ├─ 默认路径：Agent 自主判断，可能不执行或整理不全
  │   └─ Dreaming 路径（默认禁用）：
  │        Jaccard 机械去重（无语义理解）
  │        六维统计评分（无 LLM 语义判断）
MEMORY.md
  ↓ ❹ 召回受限（无 embedding 时降级为词法匹配）
对话上下文
```

文章定性：非设计缺陷，是通用框架在提取精度与系统复杂度间的权衡。论证案例：名字/城市/饮食偏好只记住名字；"花生过敏"类低频重要信息可能被统计评分埋没。详见 [[原生记忆不确定性链路]]、[[LLM弱约束记忆决策]]。

## 七、RDSClaw 插件：个人记忆管线

插件全名 `openclaw-memory-alibaba-local`，与原生系统互补（非替换）。从 User 消息提取两类个人记忆：**个人画像（UserImageExtraction）**（偏好/个人详情/计划意图，个人事实 Evergreen 免衰减）与**世界记忆（WorldImageExtraction）**（事件/实体/第三方信息，按策略淘汰），共享提取器，按是否含 `User/用户` 分流（详见 [[双提取器分流]]）。

两阶段实时管线流程（原文）：

```
对话内容
  ↓ ① 提取器（Extractor）
LLM 结构化提取，配合强制规则
  ↓ 分流：个人记忆管线 / 世界记忆管线
  ↓ ② 整合器
  对每条新事实，向量检索已有记忆 → LLM 判定 CRUD 动作：
  INSERT（新事实）/ UPDATE（信息更丰富）/ SKIP（已存在）/ DELETE（矛盾过时）
  ↓
LanceDB（向量 ANN + BM25 FTS + 标量索引）
```

由 `agent_end` 钩子每轮对话结束稳定触发，不依赖 token 阈值或 Agent 自主判断，当轮完成、无需 Cron。详见 [[两阶段实时记忆管线]]、[[LLM-CRUD记忆整合]]、[[Evergreen免衰减]]、[[混合召回]]。

九维核心差异对照表（原文）：

| 维度 | OpenClaw 原生 | 插件 |
|---|---|---|
| 提取时机 | Agent 主动写入 + Compaction 前 Flush（被动） | 每轮对话结束即触发（主动） |
| 提取方式 | LLM 自由写入（无结构约束） | LLM 结构化提取 |
| 演进方式 | Cron 三阶段 → 六维统计评分 | 实时 LLM CRUD 整合（INSERT/UPDATE/SKIP/DELETE） |
| 演进周期 | 数天 | 分钟级（当轮对话结束即完成） |
| 去重 | Jaccard 字面相似度 | 向量近似 + 精确匹配 + LLM 语义判断 |
| 矛盾处理 | 依赖统计评分自然淘汰 | LLM 显式识别矛盾 |
| 时间衰减 | Dreaming 评分默认 14 天半衰期；检索侧另有可选时间衰减（默认关闭，半衰期 30 天） | 个人事实 Evergreen（免衰减），世界事件按策略淘汰 |
| 存储后端 | Markdown + SQLite/QMD | LanceDB（向量 ANN + FTS 全文索引 + 标量索引） |
| 召回方式 | memory_search 单通道 | 混合召回 |

六项不确定性补强映射表（原文）：

| 原生系统不确定性 | 插件的互补方式 |
|---|---|
| LLM 主观写入 | 结构化 Prompt 约束 + 强制规则 |
| 短对话无 Flush 安全网 | 每轮 `agent_end` 钩子自动触发，不依赖 token 计数或 Agent 自主判断 |
| Cron 演进延迟 | 提取→整合→存储在同一轮完成，无需等待调度 |
| Jaccard 机械去重 | 向量相似度 + LLM CRUD 语义整合 |
| 统计评分无语义 | LLM 参与每次整合决策（INSERT/UPDATE/SKIP/DELETE） |
| 召回受搜索配置制约 | 混合召回，不依赖单一搜索后端 |

## 八、自进化记忆管线

从 Assistant 消息提取「AI 自己做了什么、犯了什么错、学到了什么」，定位"让 Agent 越用越好"。

三类提取目标（原文）：

| 类别 | 含义 | 示例 |
|------|------|------|
| 最佳实践（learnings） | AI 总结出的可复用行为规则 | "上线前必须重启服务使新代码生效" |
| 错误经验（errors） | AI 犯过的错误和应避免的模式 | "Do not assume X; always check Y first" |
| 行为诉求（feature_requests） | 用户对 AI 行为的期望和约束 | "删除前必须确认，不要直接执行" |

双提取方式：LLM 提取（默认，User+Assistant 消息组合输入，结构化输出 `{category, text, importance}` 数组，每轮最多 5 条）与正则提取（轻量级，关键词模式 `学习：`/`错误：`/`lesson:`）。向量去重（相似度 ≥ 0.92 视为近似重复）后存 LanceDB；后续会话在 `before_prompt_build` 阶段与个人记忆一起召回注入系统上下文。详见 [[自进化记忆管线]]、[[双提取方式]]、[[个人记忆vs自进化记忆对比]]。

分析性张力：自进化记忆演进方式仅为"向量去重 + 存储"，无 LLM CRUD/矛盾识别/淘汰机制——错误经验如何过期/纠错未说明。

## 九、LoCoMo10 评测结果

基准定义：snap-research/locomo（https://github.com/snap-research/locomo），长上下文会话记忆与推理基准，10 个对话集，四大类别（事实查询/时间推理/逻辑推理/描述性问答），"目前评估 AI Agent 长期记忆能力的主流 benchmark 之一"。

完整成绩表（原文精确值）：

| 类别 | 基线 | 使用插件后 | 提升 |
|------|------|-----------|------|
| 事实查询（Category1） | 34.04% | 62.54% | +28.50% |
| 时间相关（Category2） | 57.01% | 67.07% | +10.06% |
| 推理性（Category3） | 43.75% | 65.35% | +21.60% |
| 描述性（Category4） | 68.37% | 78.18% | +9.81% |
| **总体（全部类别汇总）** | **58.18%** | **72.08%** | **+13.90%** |

归因解读（原文三条）：事实查询提升最大（+28.50%）← 双管线+实时 CRUD 整合与 Evergreen 存储（个人事实不因统计信号不足而丢失）；推理性提升显著（+21.60%）← 混合召回（向量+BM25）与 LLM 语义去重提供更完整上下文；总体提升 ← 不改变底层 LLM，仅靠记忆管线工程优化实现近 14 个百分点提升。

**评测口径核查**：四类别差值简单平均为 +17.49%，与总体 +13.90% 不一致——终章确认总体行为**加权汇总**（各类别题量不同），非简单平均，数据内部自洽，[[ai工程量化效果声明追踪]] 挂接条目口径已核实。保留项：评测执行方、各类别题量与加权方案、样本量均为作者自报未披露。
