## 一句话核心论断

> 传统编程和 Workflow 都是人在做决策、提前设计好所有逻辑，而 Agent 是 AI 在做决策，能够解决原有写程序不能解决的问题，因此更容易做出差异化的体验，也因此更适合作为下一代的用户交互新范式。就像目前大家都在用的 coding agent 一样，未来会有更多面向不同领域的 agent 涌现。

（"下一代交互新范式"为作者前瞻判断，非被证实事实。）

## 三维度对比表（原文照录）

| 维度 | 传统编程 | Workflow 工作流 | Agent |
|------|---------|----------------|-------|
| 开发所需技能 | 需掌握编程语言、算法、系统设计等专业知识 | 理解编程原理，理解图形化拖拽产品的能力，以及扩展函数的写法 | 自然语言即可完成所有业务逻辑 |
| 完成任务的方式 | 完全依赖硬编码规则，难以处理不确定或复杂场景 | 固定路径流转，条件判断有限，无法动态调整策略 | 在自然语言的引导下，动态调整策略完成任务 |
| 修改与维护成本 | 多角色瀑布协作：运营发现问题 -> 产品拆解排期 -> 研发 -> 部署 -> 测试 -> 上线 | 基本只能节省部署环节：运营发现问题 -> 产品拆解排期 -> 研发 -> 测试 -> 上线 | 业务自闭环：(发现->测试->解决） |

## 三种方式详解（"天气推荐穿衣"玩具示例）

### 传统编程：一切都要提前想好

类比建房子——先把所有图纸画好、材料备好，严格按图施工，图纸上没有的情况就得重新设计。原文以 `get_weather_recommendation` 的 Python 硬编码示例说明：

```python
def get_weather_recommendation(city):
    # 1. 查询天气
    weather = query_weather_api(city)
    temperature = weather['temperature']
    condition = weather['condition']

    # 2. 根据温度判断
    if temperature < 10:
        return "建议穿厚外套"
    elif temperature < 20:
        return "建议穿薄外套"
    elif temperature < 25:
        return "建议穿长袖"
    else:
        return "建议穿短袖"
```

原文指出的问题：
- 硬编码规则：所有逻辑提前写死，遇到新情况就得改代码
- 异常处理复杂：各种边界情况都要提前考虑，代码变复杂
- 修改成本高：改一个小逻辑需要开发、测试、部署整个流程走一遍

```python
# 3. 如果API返回错误怎么办？需要写异常处理
# 4. 如果数据格式不对怎么办？需要写数据验证
# 5. 如果用户想要更详细的建议怎么办？需要修改代码
```

### Workflow 工作流：流程固定，但更灵活一些

类比搭积木——用图形化方式把不同"积木"（节点）连接成固定流程。示例流程：开始 -> 查询天气API -> 判断温度 -> 返回建议 -> 结束。
- 优点：可视化（不需要写代码，拖拽即可）、模块化（每个节点独立、可复用）
- 问题：流程固定（用户想要"先查天气、再查穿衣建议、最后保存到文件"就需要重新设计整个流程）、条件判断有限（复杂逻辑仍需写代码）、复杂流程维护难度变大、修改流程仍需开发人员参与

### Agent：边走边看，动态调整

类比有经验的向导——告知目标，向导根据实际情况动态调整路线，遇到问题就解决，走不通就换条路。示例指令："帮我查一下北京今天天气怎么样，适合穿什么衣服，然后保存到文件。"Agent 自主决定：
1. 先调用天气查询工具
2. 根据天气结果，决定调用穿衣建议工具
3. 获取建议后，决定调用文件写入工具
4. 如果某个工具失败了，会自动尝试其他方法

## 本质区别：谁在做决策

展开见 [[决策权三分法]]。决策者不同（程序员 / 产品开发 / AI）→ 技能门槛不同（专业编程知识 / 图形化工具与扩展函数 / 自然语言）→ 修改维护成本不同（多角色瀑布协作几天到几周 / 仅节省部署环节 / [[业务自闭环]]——原文称"从发现问题到解决问题只需要几分钟"，为自报无口径声明）。

## 总结：同源替代与 Agent 新范式

展开见 [[编程与工作流同源替代论]]。原文论断：Workflow 与传统编程核心的变化都仅在于"在固化的流程中适当地增加 AI 的能力"，除此外其他部分类似，二者本质都是"程序控制的流程流转"，是相互替代关系，在没有 AI 的时代就已充分竞争过；竞争结果是写代码的方案因优秀的**复用性和扩展性**成为更主流选择。Agent 的决策权完全下放给 Agent 和 Prompt，能解决原有写程序不能解决的问题——处理不确定性、动态调整策略、理解自然语言意图——因此"不是对传统编程的简单替代，而是一种更有机会的新范式"。

## 应用场景二分

展开见 [[ai增强与agent体验二分选型]]。
- 既有系统增强 AI 能力：代码 + toolcall，效果最好、准确性有保障，适合需要精确控制、高性能的场景
- 让用户明显感知 AI 驱动的创新类产品：AI Agent，适合处理不确定性、快速迭代、让非技术人员也能完成复杂任务的场景

原文结语："关键是要理解每种方式的本质，根据实际场景选择最合适的方式。Agent 的核心价值在于它开辟了新的可能性，让 AI 真正成为决策者，而不仅仅是执行者。"
