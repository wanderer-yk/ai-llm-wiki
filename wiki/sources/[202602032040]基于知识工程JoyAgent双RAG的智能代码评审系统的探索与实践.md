# 基于知识工程 JoyAgent 双 RAG 的智能代码评审系统的探索与实践

**作者**：齐海智（[[京东物流]]供应链商家导入研发团队）
**发布平台**：[[京东技术]]微信公众号（IP 属地北京）
**发布时间**：2026 年

## 摘要

本文记录了京东物流供应链商家导入研发团队构建智能代码评审系统的完整探索与实践。系统采用 [[双rag架构|双 RAG 架构]]——将知识工程的代码知识检索能力与 [[joyagent|JoyAgent]] 知识库检索能力相结合，解决现有 AI 评审方案在全局上下文缺失、知识归纳失真、项目身份感知缺失等方面的固有缺陷。核心技术贡献包括 [[两级分块策略]]（文件级分割 + [[代码结构感知分割]]）、[[项目身份感知能力]]（文件扩展名特征识别）、[[bge本地重排序方案|BGE 本地重排序]]等。

## 问题背景

### 大促评审困境

[[大促封板管控]]（双十一等大促期间的系统封板机制）导致封板前评审任务集中激增，传统人工评审面临"量与质"双重压力——效率低、风险遗漏可能性高。现有 AI 评审工具核心痛点为误报率高，多数评审意见无实质帮助。

### 现有方案两大局限

**技术 1（流水线+通用大模型）** 三大缺陷：
- [[固定行数截断策略]]导致 [[全局上下文缺失]]（"管中窥豹"）
- [[提示词天花板]]：评审规则硬编码于 Prompt 导致膨胀触及上下文上限
- 知识无法沉淀（效果提升仅靠换模型/调 Prompt）

**技术 2（JoyAgent 知识库 RAG）** 两大缺陷 + 一大前置缺陷：
- [[知识归纳失真]]：LLM 对 Code Diff 总结不稳定
- [[检索与生成联动失效]]：归纳失真传导至 RAG 检索与生成链路
- 缺乏 [[项目身份感知能力]]：无法识别 EDI 项目，使用通用 Java 规则

## 双 RAG 架构设计

完整流程五步骤：
1. **[[项目身份感知能力|项目类型识别]]**：[[文件扩展名特征识别]]（`.flow`、`.dt` 等），EDI 优先于普通 Java 项目
2. **[[两级分块策略|两级智能分块]]**：文件级分割（git diff 识别文件边界）+ [[代码结构感知分割]]（方法签名正则在自然边界处分割）
3. **知识工程检索**：[[业务领域识别]]→关键词提取与净化→语义搜索
4. **[[bge本地重排序方案|BGE 重排序]]**：本地部署 `bge-reranker-base.onnx`，解决 [[向量召回质量不均问题]]
5. **双源知识融合生成**：[[双rag知识融合论|双 RAG 知识融合]]，实现"1+1>2"智能涌现

### Token 管理工程实践

- [[token估算经验公式]]：固定开销 63 tokens + 英文单词分级 + 中文每 2 字符 1 token + 空格不计
- [[分块安全阈值设计]]：触发阈值 100K Token（128K 的 80%）+ 单块上限 60000 Token

## 实际案例验证

### 案例 1：空值处理预防

三方系统返回 null 值未做空值校验导致线上问题：`String.valueOf(null)` 返回 "null" 字符串→`Integer.parseInt("null")` 抛 `NumberFormatException`。双 RAG 系统在评审阶段成功预防此类事故。

### 案例 2：EDI 配置规范检查

XML 字面常量错误：`<case value="${orderType}">`（错误）vs `<case value="NORMAL">`（正确）。系统通过 [[项目身份感知能力]]识别 EDI 项目类型后，使用 EDI 专用规范成功检出。
