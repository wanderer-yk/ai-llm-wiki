## 核心论点

1. **胶水层论点（标题主论点）**：Agent 开发很大程度上是构建胶水层（Context 层），其设计质量直接决定 Agent 生产力与鲁棒性；深层原因是业务逻辑前置到模型训练阶段，应用层坍塌为胶水代码。见 [[agent胶水层]]。
2. **LLM 不确定性物理不可消除**：Temperature=0/top-k=1 仍不确定，源于 MoE 工程、浮点精度误差累积、硬件异构；且含厂商为低成本高吞吐的主动让渡。见 [[llm不确定性物理不可消除]]。
3. **Agent 开发经验主义**：Agent 系统"看似流程确定，但细节充斥大量不确定性和经验主义"，以约 30 处反问注释的伪代码与七大类不确定性清单论证。见 [[agent开发经验主义]]。
4. **控制论视角**：ReAct 与闭环控制是同一件事；质检 Agent 的根源是必要多样性定律；第三条路是引入真实世界负反馈。见 [[闭环负反馈控制]]、[[必要多样性定律]]、[[真实世界负反馈]]。
5. **性能视角**：分布式性能本质两类 I/O；显存墙与算力墙；AI 系统圣杯是数据局部性。见 [[显存墙与算力墙]]、[[ai系统圣杯数据局部性]]。

## 关键主张（摘要）

- 基座模型无状态，Agent 应用成为有状态存储节点（[[状态管理反转]]）。
- Agent 架构选型/阈值配置本质是与模型厂商推理成本的间接博弈（[[推理成本博弈论]]）。
- Agent 开发六个关键点：Prompt 工程、Context 管理、输出解析、工具编排、异常处理、质量评测（[[agent系统模块六要素]]）。
- 编排四等式：ReAct=while+if；Workflow=if+elif+else；LangGraph=Workflow+StateNode；Plan-Exec=for+function call（[[agent编排四等式]]）。
- LangChain 真正价值是语义层面标准化（Message 四角色），类比 Java 早期 SSH；随基座达阈值将向完全 ReAct 迁移（[[langchain语义标准化]]、[[langchain]]）。
- 产品交互从即时响应转向异步交付；工程目标从低延迟转向持续交付高质量确定性（[[即时响应到异步交付]]）。
- LLM 六条天然工程约束（[[llm天然工程约束]]）；三类适合 LLM 的问题（[[llm适用三类问题]]）；AI 能力边界四原则（[[ai能力边界定义]]）。
- 概率级联故障链取代传统物理拥塞故障链；测评须覆盖变更时+运行时（[[概率级联故障]]）。
- 业务逻辑前置训练阶段致代码量大降，Java 声量缺失由此解释（[[java声量缺失论]]）。

### QWen AI Quick Start（Java，dashscope 端点；标识符/字符串/参数保持原样）

```java
public class Main {
    public static GenerationResult callWithMessage() {
        Generation gen = new Generation(Protocol.HTTP.getValue(), "https://dashscope-intl.aliyuncs.com/api/v1");
        Message systemMsg = Message.builder()
                .role(Role.SYSTEM.getValue())
                .content("You are a helpful assistant.")
                .build();
        Message userMsg = Message.builder()
                .role(Role.USER.getValue())
                .content("Who are you?")
                .build();
        GenerationParam param = GenerationParam.builder()
                .apiKey(System.getenv("DASHSCOPE_API_KEY"))
                .model("qwen-plus")
                .messages(Arrays.asList(systemMsg, userMsg))
                .resultFormat(GenerationParam.ResultFormat.MESSAGE)
                .build();
        return gen.call(param);
    }

    public static void main(String[] args) {
        GenerationResult result = callWithMessage();
        System.out.println(result.getOutput().getChoices().get(0).getMessage().getContent());
    }
}
```

### 不确定性清单七大类（正文原表）

| 类别 | 不确定点 |
|------|---------|
| RAG | chunk_size/chunk_overlap 设置；Embedding 模型；向量数据库、相似度阈值配置 |
| Memory | 怎么清理 short_term_memory 中低效信息；怎么索引 long_term_memory |
| Prompt Engineering | System Prompt 放什么；Message 次序 |
| LLM 调用 | 模型选择及参数配置；API 调用失败处理；返回格式错误/字段缺失/结果评测 |
| Tool | Tool 过多精度下降；执行失败或返回结果数太多；高危 Tool 误用限制 |
| 编排和 Multi-Agent | 子 Agent 选择与失败恢复；结果整合；循环检测与 MAX_STEPS 设置 |
| 安全和评测 | Prompt Injection 防护；身份认证与工具权限；好输出无统一标准；是否引入其他 LLM 评测 |

### 编排范式四等式（正文原表）

| 框架概念 | 代码等价 | 语义 |
|---------|---------|------|
| ReAct | while + if | 循环执行：思考→行动→观察，直到完成 |
| Workflow | if + elif + else | 条件分支：根据任务类型选择不同处理链 |
| LangGraph | Workflow + StateNode | 本质还是条件分支，图结构表达更灵活 |
| Plan-Exec | for + function call | 顺序执行：先规划步骤列表，再逐个执行 |

### NVIDIA B300 关键组件参数（作者据"推动 AI 工厂时代的芯片动力"图逐条解读）

| 组件 | 参数 | 作者解读要点 |
|------|------|------|
| GPC (Graphics Processor Cluster) | 160 SMs per GPU, 640 Tensor Cores, 15 PetaFLOPS Dense NVFP4 | 每秒 1.5×10^16 浮点运算；NVFP4 4 位浮点降精度换速度；640 并行 MMA = F(X)=W×X+B |
| HBM CTRL (High Bandwidth Memory Controller) | 288GB HBM3E Memory（8 Stacks, up to 8 TB/s） | 不到 10 毫秒可把 70B 模型（FP8）全部参数搬入计算核心一次 |
| NV-HBI (High Bandwidth Interface) | 10TB/s Die-to-Die（B300） | 双芯片直接封装，速度高于 HBM 带宽；NUMA 透明 |
| NVLink v5 / NVLink-C2C | 1800GB/s to NVLink Switch；900GB/s Coherent CPU-GPU Interface | 多卡并行的现实最优解；MoE 专家跨卡分布引发高频跨卡通信 |
| PCIe Gen 6 | 256GB/s CPU Host Interface | 为 NVLink 的 1/7、HBM 的 1/30，走 PCIe 性能数量级崩塌 |

### H200 vs H20 对比（作者引述参数）

| 型号 | Dense/Sparse FP8 | HBM | NVLink |
|------|------------------|-----|--------|
| H200 | 2 / 4 PFLOPS | 144GB, 4.8TB/s | 900GB/s |
