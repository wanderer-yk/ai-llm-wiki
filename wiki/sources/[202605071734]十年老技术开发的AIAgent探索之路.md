# 十年老技术开发的 AI Agent 探索之路

**作者：** [[zhiyuanfu]]（署名"腾讯程序员"）
**发布平台：** [[腾讯技术工程]] 微信公众号
**发布时间：** 2026-05-07 17:34
**IP 属地：** 广东

## 摘要

本文是腾讯开发者 zhiyuanfu 基于 10 年技术经验和一年 AI Agent 实践撰写的深度长文。以个人实践为主线，系统阐述从多终端混乱到 24 小时无人值守 Agent 系统的完整探索路径。全文核心线索为"人是瓶颈→Vibe Coding 翻车→SDD 正道→24h 打工人架构→Goal-Driven 跃迁→增强自我而非取代自我"。

## 核心章节

### 第一章：人是瓶颈
同时管理 5 个 AI 终端（codex、gemini-cli、claude、Cursor 双窗口）的真实混乱体验，提炼[[人工并发天花板]]（4-6 个窗口），核心洞察：解决瓶颈不是让 AI 替代人，而是让系统不依赖人的实时在场。

### 第二章：80% 的 AI 需求不需要 AI
提出"[[自动化决策层级]]"五层金字塔（目标→代码→CLI→Prompt→Agent），核心原则"能在下层解决的，绝不上推"。10 行 Bash 即可替代大量 LangChain+Agent+ToolCalling 过度工程。

### 第三章：Vibe Coding 翻车记
以真实 15 天时间线记录从"哇效应"到代码混乱的全过程，提出[[先易后难陷阱]]——Vibe Coding 先易后难，SDD 先难后易（"大道如夷，而民好径"）。第三天就要补 spec。

### 第四章：24h 打工人
设计 24 小时无人值守 AI 开发系统（[[24h打工人]]），核心架构为[[文件轮询架构]]（文件系统存储+轮询调度+JSON 状态管理），含 [[agent调度四职能]]（接收/分发/状态管理/失败切换）和[[按项目分组并发策略]]。不是重新造 Agent，而是造管理 Agent 的调度层。

### 第五章：Agent 自己修了自己的 bug
自举案例：系统通过自身反馈系统提交 bug→触发 SDD 流程→自动定位修复。前提是三项基础设施（[[agent自举三前提]]）：设计文档+SDD 流程+constitution.md。

### 第六章：从 demo 到系统
核心命题"门槛不是模型，是治理"。建立[[agent可观测性六维度]]和[[agent-control-plane]]。提出[[脚手架优于模型]]——脚手架升级成本+50%效果+200% vs 模型升级成本+300%效果+20%。

### 第七章：协议层正在成形
分析 [[responses-api]]（runtime 收敛）、[[mcp]]（工具接入标准化）、[[a2a]]（多 Agent 协作）三大趋势。Agent 开发从框架之争转向协议+runtime+control plane 之争。

### 第八章：从 Task-Driven 到 Goal-Driven
提出[[task-driven对goal-driven]]认知跃迁框架。Goal-Driven 五前提：目标清晰/边界清晰/状态可见/过程留痕/权限可控。[[state-yaml共享面板]]解决多 Agent 协调。[[六步落地路径]]渐进式建设。

### 结语：增强自我，而非取代自我
SDD 五层文件体系（spec.md→plan.md→tasks.md→constitution.md→eval/trace/policy）构成无人值守系统完整地基。终极论断："真正的跃迁不是让 AI 多做几个步骤，而是让人退出微观调度"。
