## 问题定义：Naive RAG 三瓶颈（双层论述）

团队初期采用 Naive RAG 路线（问题→向量召回→大模型生成），上线后暴露的问题在文中有两层论述：

**表现层三痛点**：
1. 对提问方式高度敏感——同义改写/口语化导致召回不稳定
2. 知识碎片化——文档切分破坏上下文、多跳推理困难
3. 缺乏评测闭环——优化凭直觉（“从玄学变成工程”是本文目标）

**检索架构层三结构性局限**：
1. 上下文在切块时被物理性切断（配置→构建→部署流程示例）
2. 无法进行跨文档关联推理（A/B 组件事件通信机制对比示例）
3. 知识以“碎片”而非“结构”形态存在（同一概念散布十几篇文档，扁平向量空间无法利用结构化关系）

## 三大方案

1. **CoT 驱动的意图识别（查询侧）**：意图识别选用 qwen-turbo-latest（选型理由：极低延迟、无需强推理），先推理出解决问题的逻辑步骤，再生成多组查询并行召回；传统串行改写产出 2-3 条查询 vs 本方案十几条覆盖不同维度。详见 [[cot驱动意图识别与并行检索]]。
2. **GraphRAG → LightRAG 检索演进（知识侧）**：先以 44 篇文档实测 [[graphrag]] 验证图结构有效性但确认四大致命工程困境（[[graphrag工程化四困境]]），再落地 [[lightrag]] 实现秒级响应与增量更新。
3. **多维度评测体系（度量侧）**：“好/坏”二元标签升级为三维标注，并发现评测 Agent 的“乐观偏差”，人工校验不可或缺。详见 [[多维度标注体系]] 与 [[评测agent乐观偏差]]。

**基础能力建设**（作者自述为标准实践，未展开）：XML 结构化行为规范（工具调用分层优先级、禁止虚构、回复后自查清单）、联网搜索兜底、思考过程与工具调用流式透出（可解释性）、轻量级知识录入、转人工兜底路径。

## GraphRAG：论文方法与 44 篇文档实验

### 方法蓝本：GraphRAG 原始论文（arXiv:2404.16130）

GraphRAG 由微软团队于 2024 年提出（Edge D, Trinh H, Cheng N, et al.），论文标题为《From local to global: A graph RAG approach to query-focused summarization》，arXiv:2404.16130（[[edge-2024-graphrag|GraphRAG 论文]]），完整引文见下文参考文献 [1]。

> [!note] 口径说明
> 本节对论文方法论的整理均基于来源文章参考文献 [1] 的完整引文及其对论文方法论的转述，非论文原文直读。

核心方法（据来源文章转述）：

- **核心思路**：将“基于文本片段的平面检索”升级为“基于实体-关系网络的结构化检索”。
- **索引构建四步流水线**：TextUnit 分块 + LLM 实体关系抽取 → 全局图合并（消除信息孤岛）→ Leiden 层次化社区发现 → LLM 社区摘要。
- **双查询模式**：
  - **Local Search**：embedding 定位实体→沿图谱边扩展，适合具体问题；
  - **Global Search**：社区摘要 Map-Reduce，适合宏观综合问题。

详细机制与工程困境实证见 [[graphrag]] 与 [[graphrag工程化四困境]]。

### 实验设置与结论

跨端技术团队以该论文方法为蓝本，选取知识库中某模块的 44 篇文档做双栈实验（Streamlit 可视化），确认图结构有效解决上下文断裂与跨文档推理——GraphRAG 跨文档综合问答效果兑现（回答更全面、有条理，定性表述无量化数字）；但下述四个致命工程问题使其“在我们的答疑场景中几乎不可用”，随后转向 [[guo-2024-lightrag|LightRAG 论文]] 所述的轻量化方案。

### 四大工程困境

| 致命问题 | 机制根源 | 量化/定性口径 |
|---|---|---|
| 索引构建成本极高 | 每篇文档实体抽取+关系挖掘均调用 LLM（通常需 GPT-4 级别保证质量），社区摘要又是一轮调用 | 44 篇文档消耗大量 API 调用，“费用不菲”（无金额数字） |
| 不支持增量更新 | 社区结构由 Leiden 在全局图计算；新文档→图谱结构变化→社区边界重划→所有社区摘要重生成 | 文中标注“最致命”；对知识库每天更新的答疑系统代价无法接受 |
| 查询延迟过高 | Global Search 遍历多层级社区摘要+Map-Reduce 聚合 | 一次查询可能耗时 5 分钟以上；Local Search 亦显著高于传统 RAG |
| 对抽取质量高度敏感 | 弱模型/文档表述不规范→图谱噪音→社区划分不合理 | 检索质量反而不如传统 RAG |

## LightRAG：论文方法与落地

### 方法蓝本：LightRAG 原始论文（arXiv:2410.05779）

LightRAG 原始论文由 Guo Z, Xia L, Yu Y, et al. 于 2024 年发表，标题为《LightRAG: Simple and fast retrieval-augmented generation》，arXiv:2410.05779（[[guo-2024-lightrag|LightRAG 论文]]），完整引文见下文参考文献 [2]。

> [!note] 口径说明
> 本节对论文方法论的整理基于来源文章（[[sources/[202604101635]AI答疑助手优化实践从RAG到LightRAG的全链路升级|[202604101635]AI答疑助手优化实践从RAG到LightRAG的全链路升级]]）参考文献 [2] 的完整引文及其对论文方法论的转述整理。

核心方法（据来源文章转述）：

- **索引构建形式化为三函数**：R(·) 实体关系抽取、P(·) 键值对生成（替代社区摘要）、D(·) 去重与合并（使增量更新天然可行），详见 [[lightrag三函数索引构建]]。
- **查询引擎采用双层检索范式**：低级检索定位具体实体、高级检索走关系边全局主题关键词，同时触发+合并去重，详见 [[lightrag双层检索范式]]。
- **设计哲学为“做减法”**：去掉 GraphRAG 最昂贵的社区发现与社区摘要机制。

### 设计哲学与三函数索引构建

设计哲学为“做减法”：GraphRAG 最昂贵的社区发现+社区摘要机制对以具体问题为主（80%+）的私域答疑非必需，故去掉社区机制，改用图索引+向量嵌入混合方案——其中 P(·) 的键值对生成即承担替代社区摘要的职能。索引构建形式化为三函数（原文口径）：

```
R(·) —— 实体与关系抽取：LLM 识别实体（节点）与关系（边）；
        简化：不追求精细实体类型分类，注重抽取效率和覆盖面
P(·) —— 键值对生成：对每个实体节点/关系边生成 (Key, Value) 文本对；
        Key = 便于检索的短语/关键词（实体用名称；关系由 LLM 增强生成多个全局性主题关键词）
        Value = 总结性文本，聚合该实体/关系在原始文档中的所有相关描述
D(·) —— 去重与合并：识别不同文档段落的相同实体/关系并合并为同一节点/边；
        压缩图规模 + 使增量更新天然可行（匹配即合并，无需重建全图）
```

详见 [[lightrag三函数索引构建]]。

### 双层检索范式

查询引擎采用双层检索范式（低级检索定位具体实体、高级检索走关系边全局主题关键词，同时触发+合并去重），详见 [[lightrag双层检索范式]]。

### 同批 44 篇文档实验对比（LightRAG vs GraphRAG）

LightRAG 相对 GraphRAG：索引构建快“数倍”（省社区发现+摘要开销）、查询“分钟级→秒级”、API 调用与 token 大幅减少；质量上具体问题接近 GraphRAG Local Search，全局问题逊于 Global Search（无社区摘要加持）但 80%+ 场景够用。五维度实测对照详见 [[graphrag与lightrag对比]]。

## 评测体系

- 初版“好/坏”二元标签粒度过粗无法区分根因，升级为三维标注（问题质量/回答质量/问题成因），实现 Bad Case 四对症：幻觉→强化提示词约束、召回不足→调检索策略、知识缺失→推动补录、超出能力→引导转人工。
- 评测 Agent 发现显著“乐观偏差”（判“需改进”精准率高、判“优秀”召回率低），结论为任何 LLM 应用不能完全依赖模型自评估。

## 前沿综述（未实践）

- **MiniRAG**：图增强 RAG 在小模型（SLMs）上的尝试——异构图索引（文本片段节点+语义概念节点双类型）+拓扑增强检索，面向端侧等资源受限场景。
- **Agentic RAG**：让 Agent 自主决定“是否检索、检索什么、结果够不够、要不要重查”，含自适应/自反思/纠正性三模式，详见 [[agentic-rag]]。

## 总结：上下文工程统一命题

全文核心命题："AI 答疑系统的质量，取决于你为模型构建上下文的能力——这正是‘上下文工程’的核心命题"。三个优化方向统一为同一件事：CoT 意图识别=查询侧（用什么去检索）、GraphRAG→LightRAG 演进=知识侧（检索到的知识如何组织）、评测体系=度量侧（衡量上下文质量，让优化可量化可迭代），三者互为补充构成闭环，详见 [[上下文工程统一命题]]。RAG 演进被概括为知识表示升级路线：扁平向量空间→结构化实体-关系图谱→未来自主决策检索智能体，详见 [[rag知识表示演进论]]。作者自评其 CoT 意图识别“某种程度上已经具备了 Agentic RAG 中‘自主规划检索策略’的雏形”（自评定位，无实证）。
