# 如何用 AI 做业务级 Code Review

## 来源信息

- **作者**：货拉拉大前端
- **发布渠道**：微信公众号「货拉拉大前端」
- **发布时间**：2026 年 2 月
- **IP 属地**：上海

## 摘要

本文是 [[货拉拉大前端]] 团队关于 AI 辅助业务级代码评审的完整实践分享。针对核心业务项目中 Code Review 面临的三大痛点——Diff 数量过多导致人工审查疲劳、历史事故教训遗忘导致同类问题反复出现、通用 AI 工具缺乏业务上下文理解——团队设计并落地了一套从 `git push` 自动触发的 AI Code Review 系统。

系统核心链路为：**GitLab Webhook 事件触发 → Diff 深度预处理与语义重塑 → RAG 经验召回 → LLM 深度 Review → 可视化报告与消息通知 → 反馈闭环**。

文章核心理念概括为一句话：**"把团队踩过的坑变成模型的直觉"**。

## 核心架构

### 事件驱动触发

系统基于 [[gitlab-webhook]] 实现自动化触发，支持监听 Push events 和 Merge request events。开发者推送代码后，Webhook 回调携带 Diff 数据进入预处理流水线。

### Diff 预处理流水线

详见 [[diff预处理流水线]]。核心步骤包括：

1. **特征过滤**：剔除非逻辑文件（`.json`、`.png`、`.lock`、`.css`、`.scss`、`.less` 等），减少 Token 消耗和注意力分散
2. **切片化**：将长 Diff 按文件维度切分为可管理单元
3. **语义重塑**：先让模型分析"这段代码在做什么"及改动意图，为后续 RAG 匹配和深度审查奠定基础

### RAG 经验召回引擎

详见 [[rag经验召回引擎]]。将历史事故复盘文档、最佳实践等知识通过 Embedding 向量化存入向量库，在代码审查时基于余弦相似度检索匹配 **Top 2** 相关上下文注入 Prompt。

查询流程：代码变更简要 → Embedding Model → 余弦相似度匹配 → 过滤低于 0.85 阈值的结果 → Top 2 知识注入 Prompt。

### 深度 Review 与 Prompt 组装

Prompt 由三部分融合构建：
- 原始 Diff（经预处理后）
- 语义简要（语义重塑阶段生成）
- 检索到的历史问题（RAG 召回结果）

### 长 Diff 工程优化

详见 [[长diff分片并发与报告整合]]。当 Diff 规模较大时，系统采用四项工程优化：
- **Token 安全余量分片**：累计超过 30000 tokens 时创建新 Chunk
- **优先级权重计算**：`DiffProcessor.calculateWeight` 根据 `coreDirs` 路径配置优先处理核心逻辑
- **并发 API 调用**：`Promise.all(chunks.map(...))` 并行处理所有 Chunk
- **多 Chunk 报告整合**：`reportStore` 缓存 + `isAllChunksDone` 校验触发最终报告聚合推送

## 实践效果

系统已在核心业务大组深度落地，覆盖底层服务及复杂业务中台等多场景。关键效果包括：

- 老事故复发率明显下降
- 历史复盘文档命中时，系统可提示"当前代码与历史事故逻辑模式相似度达 85%"，极大缩小人工审计盲区

## 模型选型与反馈评估

### 多维选型评分

借助公司模型审核平台，用预设案例检验各候选模型的审查能力并打分，以此指导最终模型选型决策。

### 闭环反馈评估

通过抽检 Review 结果，结合用户反馈（如标记"误报"）和开发者修正行为，持续评估模型输出质量。

### 反馈学习链路（规划中）

开发者标记"误报"后，系统计划自动微调检索策略，逐步提升召回精度。

## 未来规划

1. **[[发布卡点校验]]**：将审计结果作为发布流水线的标准条件，实现"未通过 AI Review 不可发布"的硬性门控
2. **Cursor CLI 集成**：计划通过 [[cursor]] CLI 实现本地与审核工具的原生集成，将审计反馈嵌入编辑器侧边栏

## 与其他 AI 审查方案的对比

- **与美团 [[pre-pr机制]] 的差异**：货拉拉侧重 RAG 召回历史事故经验注入，美团侧重 AI 多轮自查前置审查
- **与腾讯 [[mr双重视角审查]] 的差异**：货拉拉聚焦业务上下文与事故复盘匹配，腾讯同时审查代码和规划文档
- **与转转 [[六步智能提示词生成法]] 的差异**：转转从 Sonar 静态扫描结果出发生成修复提示词，货拉拉从 Git Diff 出发进行业务逻辑审查
- **与有赞 [[code-insight]] 的相似性**：都使用 RAG/AST 技术进行代码理解，但货拉拉聚焦审查场景，有赞聚焦搜索与问答

## 开放问题
