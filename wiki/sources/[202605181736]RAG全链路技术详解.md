## 全文结构：七环节契约

| 全链路环节 | 技术要点 |
|------|----------|
| 文档加载 | 多格式解析 + 元数据提取 |
| 智能切分 | 规则/语义/结构化方法，含 Meta-Chunking 原理 |
| 索引构建 | embedding 模型选型与向量生成详解 |
| 检索优化 | Query改写、HyDE/Doc2Query、标签过滤、重排序 |
| 生成调优 | Prompt设计、参数控制、SFT微调 |
| 进阶 Graph RAG | 多跳推理与全局摘要 |
| Ragas 自动化评估体系 | Context Precision/Recall、Faithfulness、Answer Relevancy 等指标及测试集生成 |

RAG 工作原理被类比为「开卷考试」：先检索相关实时/私有信息作为参考背景与问题一起提供给大模型，基于可靠证据生成更准确、实时且可溯源的回答。

## 各环节要点与结构化数据

### 文档加载：RAG 的入口

文档加载是 RAG 的「入口」，其质量直接决定后续检索准确性（呼应 [[gigo原则]]）：多格式适配（PDF/Word/Markdown/HTML/JSON/TXT/Excel）、格式特定解析（PDF 解析文字层、扫描件 OCR、HTML 剔除脚本样式）、元数据提取（文件名/页码/标题/作者/创建时间/章节层级）、初步清洗（乱码/空格/非打印字符）。

### 智能切分：Meta-Chunking 与语义补全

本环节的核心学术引用为论文 *Meta-Chunking: Learning Text Segmentation and Semantic Completion via Logical Perception*（arXiv:2410.12788，venue arXiv，编号 2410 提示 2024 年 10 月发布，见 [[arxiv-2024-meta-chunking]]）。论文提出一种基于逻辑与语义的文本切分（chunking）方法，包含完整的原理与效果评测；文章对其评价为「基于逻辑和语义的 chunking 方法，有完整的效果评测，可参考」，并以该论文为蓝本展开 PPL 语义切分与语义补全两块教学内容。论文作者与机构信息在源文中未给出，待从 arXiv 页面补全（论文维基页 `authors` 因此留空）。论文链接在源文 HTML 中以原生锚点形式多次出现：chunk 6-7 为正文引用，chunk 12、16、19 的出现多为导出噪音复现（其中 chunk 19 紧邻 Graph RAG 文本切分步骤，性质存疑）。

#### PPL 语义切分

[[ppl语义切分]]：计算文章中各句子的 PPL（困惑度），以句子级 PPL 曲线的局部极大值作为潜在切分边界；低 PPL＝通顺连贯，高 PPL＝突兀、逻辑断层。PPL 源于信息论，是衡量语言模型预测序列好坏的核心指标；论文将其转用作感知语义边界与逻辑完整性的度量工具。

实现步骤：

1. 按标点将长文档切成句子序列 (x₁, x₂, ..., xₙ)；
2. 用轻量化大模型（论文中常用 **Qwen2**）计算每个句子与前文的 PPL（K 表示 xᵢ 中 token 数，tᵢₖ 为 xᵢ 中第 k 个 token，t<ᵢ 为此前所有 token），得到随文本流动的 PPL 曲线；
3. 取局部极大值为切分边界。

#### 语义补全（Semantic Completion）

解决分块导致的上下文丢失语义鸿沟，含两个子机制：

- **全局增强的文本块重写**（for 生成质量），四步：
  1. 向量化预处理（可选）：极长文档用 embedding 模型向量化各文本块，识别相近 trunk（即 chunk，源文笔误）；
  2. 推理是否丢失信息：LLM 结合相关信息判断每个文本块缺失的前提、背景信息、相关事实或结论性陈述；
  3. 丢失信息提炼：对潜在丢失信息打分和筛选，防止引入无关或错误补充（防幻觉设计）；
  4. 丢失信息补全：LLM 生成信息片段并与当前文本块整合，生成语义自然、跨块信息融合的新文本块。
- **Context-Aware Summary Generation**（摘要生成，for 检索），三步：
  1. 全局补充：利用全局信息生成补充摘要，补偿切分导致的话语背景（Discourse Background）与外部关联信息缺失；
  2. 推理是否丢失信息：LLM 显式识别并列出缺失领域；
  3. 局部融合：Local Summary 与补充摘要融合精炼为一句 Enhanced Summary Sentence，增强文本块的语境感知能力。

> 转录备注：源文转述存在笔误（「LLL」应为 LLM、「trunk」应为 chunk），不影响方法记录，但引用时需注意。另：「文档切分的主要方式」总览与多数配图为图床图片，文本不可提取。

### 索引构建：embedding 原理

以「苹果手机很好用」为例拆解 Transformer 前向全流程：Tokenization（`[CLS, 苹果, 手机, 很, 好用, SEP] -> [101, 512, 678, 321, 102]`，1536 维初始向量示例）→ W^Q/W^K/W^V 三角色变换 → Positional Encoding → Self-Attention 打分归一化 → 加权求和混合 V → 逐层深化（12/24 层「超级词向量」）→ Pooling（CLS / Mean / Max，Mean 为 BGE 等 RAG 模型最常用）→ L2 Normalization（点积=余弦相似度）。

Self-Attention 打分与加权求和示例（HTML 转录疑误已按加权公式校正）：

| Query | Key | 权重 |
|-------|-----|------|
| “苹果”的 Q | “苹果”的 K | 100% |
| “苹果”的 Q | “手机”的 K（HTML 转录误作“苹果”） | 50% |
| “苹果”的 Q | “很好用”的 K | 10% |

加权求和：`“苹果”的新向量 = 100% * “苹果”的V + 50% * “手机”的V + 10% * “很好用”的V`

### 检索优化

- **[[Query改写]]**（本文口径）：指代消解／纠错与去噪／术语对齐／结构转换四类问题。
- **[[多查询生成]]**：LLM 生成 3-5 个变体（例句展示 3 个），核心提升召回率。
- **[[hyde|HyDE]]**：先编「假答案」再搜「真内容」，本质是「问题-文档匹配」→「文档-文档匹配」，解决非对称检索问题；四步流程＋面团发酵完整例句。
- **[[doc2query|反向HyDE（Doc2Query）]]**：针对 chunk 生成虚构 question 并建索引关联，可离线处理不影响实时 rt；差旅报销例句量化对比见下表。

| 对比对象 | 向量匹配度 | 原因 |
|---|---|---|
| 真实提问 vs 原始政策文本 | ~0.6 | 词汇错位+疑问句 vs 陈述句，易被含“报销”二字的干扰文档带跑 |
| 真实提问 vs 虚构问题 1/2 | ~0.9 | 提问方式、口吻、关注点完全一致 |

- **[[提取标签]]**：非结构化→半结构化，语义向量检索＋标签过滤（硬标签如 `iphone15`）提升检索确定性。
- **[[重排序rerank|重排序（ReRank）]]**：召回粗筛＋重排精选；原理与优缺点见 [[cross-encoder]] 与概念页。三优点（精度飞跃／多源融合——向量搜索与 BM25 排序标准不一，重排序做统一裁判／降低大模型负担——省 Token、提高答案质量、解决[[中间丢失]]）；四缺点（增加延时、算力开销、重排序模型上下文长度限制、对查询扩写不友好——Multi-Query 5 个变体使重排序计算量×5）。

### 生成调优

RAG 生成阶段「更多是利用大模型的总结能力，而不是大模型本身具有的知识」。问题清单①-⑤与调优四方向详见 [[生成阶段问题清单]] 与 [[生成调优技术]]。

### 进阶 Graph RAG

定义：结合知识图谱（KG）与 LLM，不止存储文本向量，还通过 NLP 从文本块提取实体（Entity）、关系（Relationship）、属性（Property）构建知识网，检索时相连节点一起召回。解决的两类问题与工作原理详见 [[多跳问题]]、[[全局理解]]、[[社区检测]]。

**索引构建（建图）四步**：

| 步骤 | 内容 |
|------|------|
| 文本切分 | 将长文档切成小块 |
| 提取实体与关系 | 利用 LLM 识别每个文本块中的实体（人、地、事、概念）及其关系（属于、位于、工作于），生成三元组 |
| 图构建 | 将三元组汇聚，去重、消歧，构建全局知识图谱 |
| 社区检测（关键步骤） | 如微软 GraphRAG；利用图算法（如 Leiden 算法）将紧密相关的实体聚合形成“社区”，并用 LLM 为每个社区生成总结 |

**查询检索两模式**：

| 模式 | 流程 |
|------|------|
| 局部检索 | 识别问题关键词 → 图中定位具体实体 → 提取实体及邻居节点（n 跳关联）信息 → 结构化数据喂给 LLM 生成答案 |
| 全局检索 | 问题涉及宏观主题时不找具体实体 → 检索预先生成的“社区摘要” → 汇总多个社区结论，给出全局性回答 |

**代表性框架清单**（仅列名）：Microsoft GraphRAG / LlamaIndex / LightRAG。

### Ragas 自动化评估（全文第七环节）

定义与核心理念：「Ragas（Retrieval Augmented Generation Assessment）是一款广受欢迎的用于 RAG 框架效果评估的自动化工具」「实验显示其指标结果的准确性已经非常接近人工评测结果」「核心理念是使用 LLM 来评估 LLM（LLM-as-a-Judge）」。测试集全自动生成链：建边（embedding/实体/层级/关键词）→ 出题 → 出答案全闭环。五指标体系与测试集自动生成详见 [[ragas]]、[[ragas评估指标]]、[[评测集生成]]、[[ragas查询类型分类]]、[[ragas知识图谱构建]]、[[场景生成]]、[[场景采样两阶段解耦]]。

**Ragas 指标-输入矩阵**：

| 指标 | 输入 | 分值方向 |
|------|------|----------|
| Context Precision | user_input、reference、retrieved_contexts | 越高越好 |
| Context Recall | user_input、reference、retrieved_contexts | 越高越好 |
| Faithfulness | user_input、response、retrieved_contexts | 0-1 越高越好 |
| Answer Relevancy | user_input、response | 0-1 越高越好 |
| Noise Sensitivity | user_input、reference、response、retrieved_contexts | 0-1 越低越好（含 Relevant/Irrelevant 两子类） |

**自定义 Query Synthesizer 示例代码**（逐字保留，含疑似 `reference_contexs` 拼写）：

```python
from dataclasses import dataclass
from ragas.testset.synthesizers.base_query import QuerySynthesizer

@dataclass
class EntityQuerySynthesizer(QuerySynthesizer):
    async def _generate_scenarios(self, n, knowledge_graph, callbacks):
        """
        这个方法不调用大模型去写问题，它只是在查地图（KG）。
          1. 输入：你想要几道题（n），以及知识图谱（KG）。
          2. 它做的事：
            在 KG 中寻找有关系的节点。
            决定这n道题分别用哪些节点作为素材。
            给每道题贴上标签（如：这道题用"正式"风格，由"经理"身份提问）。
          3. 输出：一组 Scenario（方案列表）。
        """
        return scenarios

    async def _generate_sample(self, scenario, callbacks):
        """
        1. 输入：一个 Scenario（包含节点文本、人设、风格等）。
        2. 它做的事：
          把文本和要求塞进 Prompt。
          调用 LLM。
          让 LLM 返回：问题是什么？标准答案是什么？
        3. 输出：一个 TestsetSample（一道完整的题目）。
        """
        return SingleTurnSample(user_input=query, reference_contexs=contexts, reference=reference)
```
