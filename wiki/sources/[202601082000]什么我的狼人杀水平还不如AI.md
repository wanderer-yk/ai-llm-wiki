# 什么？我的狼人杀水平还不如AI？

## 概述

本文由亦盏、望宸撰写，于2026年1月8日发布于微信公众号「阿里巴巴中间件」，系统介绍了使用 AgentScope Java 框架开发 AI 狼人杀游戏的完整技术方案。文章从五大技术挑战出发，逐一展开 AgentScope 的七项核心能力，并提供了完整的代码示例和架构设计。

## 核心内容

### 技术挑战

文章指出开发 AI 狼人杀远非"写几个 Prompt"那么简单，面临五大核心挑战：

1. **多 Agent 持续思考** — 每个 AI 玩家需要基于历史对话持续推理
2. **信息隔离** — 狼人夜间密谋、预言家查验等需严格隔离
3. **记忆多玩家发言** — AI 需区分不同说话者并理解对话脉络
4. **决策明确可解析** — 投票、技能使用等决策需可靠解析
5. **支持人类玩家参与** — 人机混合对局

### 七项核心能力

| 能力 | 解决的问题 | 关键组件 |
|------|-----------|---------|
| ReActAgent | 持续思考 | name/sysPrompt/model/memory |
| Memory | 对话记忆 | [[inmemory-memory]] |
| MsgHub | 信息隔离与广播 | 自动广播/手动广播/多实例 |
| MultiAgentFormatter | 区分说话者 | 消息标记 + 消息合并 |
| Structured Output | 可靠解析决策 | Function Calling |
| 多Agent编排 | 游戏流程控制 | 编排器 + GameState |
| Human in the Loop | 人类参与 | UserAgent + WebUserInput |

### 关键发现

- LLM API 仅支持 system/user/assistant 三种角色，无法直接区分"3号玩家"和"5号玩家"，[[多智能体格式化器]] 通过消息标记与合并解决此问题
- [[结构化输出]] 基于 Function Calling 机制，将 Java POJO 转为 JSON Schema 注册为临时工具，确保 LLM 严格按格式输出
- [[human-in-the-loop]] 通过 UserAgent 与 ReActAgent 实现同一接口，编排器无需区分人类/AI 玩家
- SSE 实时推送支持玩家视角（角色过滤）和上帝视角（全量保存+赛后复盘）

### 技术栈

- **后端**: Java 17+、Maven 3.6+、Spring Boot / Spring WebFlux
- **LLM**: 通义千问 (qwen3-plus)，通过阿里云[[百炼]]平台提供 API
- **前端**: 浏览器原生 EventSource API
- **异步机制**: Project Reactor (Sinks.One / Sinks.Many)

### 未来方向

- **多人对战模式** — 多个人类玩家 + AI 填补剩余席位
- **全模态交互** — TTS 语音合成、角色专属声线（Python 版已实现）
- **新角色** — 白痴、守卫、丘比特
