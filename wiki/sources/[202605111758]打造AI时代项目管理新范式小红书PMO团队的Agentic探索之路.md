# 打造AI时代项目管理新范式——小红书PMO团队的Agentic探索之路

**作者**：白也、聂风、广见、唐泽、若臻、浩宇（小红书 PMO 团队）
**发布平台**：[[小红书技术REDtech]] 微信公众号
**发布时间**：2026-05-11
**IP 属地**：上海

## 核心摘要

小红书 PMO 团队自 2025Q1 起从零构建项目管理 AI Agent，经历四轮迭代：

1. **1.0 项目管理知识问答薯**：以 RAG 知识问答切入，简单工作流（意图识别→RAG→LLM 生成）落地生产可用 AI 项目顾问。核心发现：[[评测集优先于知识库]]，10+ 代表性 Case 的评测集比知识库本身更有价值。
2. **2.0 Agent + 多渠道接入**：提出[[原子agent设计三原则]]（原子自闭环、复合原子组合、复合禁止嵌套），将 Agent 推入公司内部 IM（[[agent推到用户所在之处]]），上线 6 个场景能力。采用 Master-Sub Agent JSON 协议，统一通知能力剥离。
3. **3.0 基于 OpenClaw 个人助理**：春节前自测后切换至 [[openclaw]] 框架，实现跨会话跨渠道长记忆。建设[[长记忆四件套]]（UserProfile / SessionMessage / KnowledgeItem / ContextBuilder），全栈 Vibe Coding 构建[[项目注册平台]]作为唯一数据锚点。三平台打通后用户月增十几→几千。
4. **4.0 PMO BP Agent**：基于 OpenClaw 构建 [[pmo-bp-agent]]，Session 模型升级为[[1项目×n人×m-session模型]]，新增项目上下文路由 + 角色感知两层专属能力，12 项落地能力矩阵。

## 核心论点

- 项目管理四阶段演进：人治→机制化→工具化→AI化
- AI 接管项目四阶段预判：人管→人驾驭 AI→AI 主导人打辅助→AI 完全接管（当前处于第二阶段）
- [[领域Agent即Source-of-Truth]]：领域 Agent 核心价值是成为领域可信唯一信息源
- [[信息中枢先于任务执行]]：PMO BP Agent 首先是信息中枢，其次才是任务执行者
- 主数据先于场景扩展：先做主数据扩展，再做场景扩展
- 知识问答只覆盖 30% 提效，执行动作（催更、通知、周报、拉群等）占 70%

## 七条实践经验

1. 快速启动优先于完美规划——每阶段用当时最快平台，架构跟着场景走
2. 评测集是 Agent 的"单元测试"
3. Agent 推到用户所在之处——推入 IM 而非要求用户到平台
4. 原子 Agent 三条设计原则从 2.0 坚持至今
5. Workflow 模式长记忆缺陷——每次对话"失忆"
6. 信息中枢先于任务执行
7. 主数据先于场景扩展

## 跨领域关联

- **OpenClaw 实践验证**：与 [[openclaw]] 框架（腾讯 yabohe 文章分析）形成实践案例补充
