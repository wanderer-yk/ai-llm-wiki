## 总体架构：Local-First 多端联动（详见 [[local-first多端联动架构]]）

- **Gateway**：统一控制平面，基于 WebSocket，Node ≥22 下以 Daemon 常驻，管理 Sessions/Presence/配置/Cron/Webhooks/Control UI/Canvas 宿主。
- **Pi Agent**：智能体运行时核心引擎（[[pi-agent]]），RPC 模式，支持 Tool Streaming 与 Block Streaming；按频道/账户/同伴路由到相互隔离的智能体（独立 Workspace 与会话）。
- **Channels**：原生支持 10 个通讯平台——WhatsApp、Telegram、Slack、Discord、Google Chat、Signal、iMessage、Microsoft Teams、Matrix、Zalo。
- **Nodes & Apps**：设备节点化，`node.invoke` 远程调用硬件（摄像头拍照/录码、屏幕录制、地理位置），macOS `system.run` 命令执行；Voice Wake & Talk Mode 基于 ElevenLabs 等。
- **Tools & Skills**：托管 Chrome/Chromium 浏览器控制、Live Canvas（A2UI 画布）、技能平台 [[clawhub]]（捆绑/托管/工作区三类技能自动搜索安装）。

安全与部署：DM 配对门控（未知发送者须配对码验证）、Docker 非主会话沙箱（群组/外部频道独立容器 + 敏感工具黑白名单）、Tailscale Serve/Funnel 与 SSH 隧道远程部署。

## 3.1 Gateway 网关（详见 [[gateway单一控制平面]]）

关键特性表（原文）：

| 特性 | 说明 |
|------|------|
| 单端口复用 | WebSocket RPC + HTTP API + Control UI 共用一个端口（默认 18789） |
| 协议版本化 | 客户端声明 `minProtocol/maxProtocol`，服务端拒绝不匹配的连接 |
| 角色分离 | `operator`（控制面）和 `node`（能力节点）两种角色 |
| 作用域控制 | 细粒度的 scopes 控制（`operator.read`、`operator.write`、`operator.admin` 等） |
| 设备认证 | 支持设备身份验证和配对机制 |
| 热重载 | 支持 `hot`/`restart`/`hybrid` 三种配置重载模式 |

帧类型（原文）：

```text
Request:  {type:"req", id, method, params}
Response: {type:"res", id, ok, payload|error}
Event:    {type:"event", event, payload, seq?, stateVersion?}
```

核心配置（3.1.9 原文）：

```json
{
  "gateway": {
    "port": 18789,
    "bind": "loopback",
    "mode": "local",
    "auth": { "mode": "token", "token": "your-token" },
    "tls": { "enabled": true, "certPath": "/path/to/cert.pem", "keyPath": "/path/to/key.pem" },
    "reload": { "mode": "hybrid", "debounceMs": 300 }
  }
}
```

认证四模式：`token`（默认）/`password`/`trusted-proxy`/`device-token`；绑定五模式：`loopback`（默认）/`lan`/`tailnet`/`auto`/`custom`；热重载实为四档：`off`/`hot`/`restart`/`hybrid`（`hybrid` 默认）。安全强制：非环回绑定必须启用认证；明文 `ws://` 禁止连接非本机地址（CWE-319）。

## 3.2 推理循环 / Pi Loop（详见 [[openclaw推理循环四层分工]]）

事件驱动架构，四层分工：主循环 `runEmbeddedPiAgent`（run.ts:192，while 重试 + 异常三路分派：context overflow→自动压缩、auth failure→profile 轮换、timeout→重试或报错）→ 尝试层 `runEmbeddedAttempt`（attempt.ts:306，四阶段）→ 事件订阅 `subscribeEmbeddedPiSession`（pi-embedded-subscribe.ts:34，五类事件分发）→ 工具循环（SDK `@mariozechner/pi-coding-agent` 的 `createAgentSession` 自动管理）。

关键调用链（原文）：

```text
用户消息 → runAgentTurnWithFallback() (agent-runner-execution.ts:72)
→ runEmbeddedPiAgent() (pi-embedded-runner/run.ts:192)
→ [while循环 - 重试] runEmbeddedAttempt() (pi-embedded-runner/run/attempt.ts:306)
→ createAgentSession() + activeSession.prompt()
→ [LLM调用 + 工具循环] subscribeEmbeddedPiSession() → 事件处理器
→ onPartialReply / onBlockReply / onToolResult → 回复消息发送
```

LLM 调用经 `streamFn`：默认 `streamSimple`（`@mariozechner/pi-ai`），Ollama 走 `createOllamaStreamFn()`，可经 `applyExtraParamsToAgent()` 包装加参。

## 3.3 定时任务系统（详见 [[openclaw定时任务系统]]）

CronService（src/cron/service.ts）由 Timer/Store/State 三组件构成，操作 `~/.openclaw/cron/jobs.json`（原子写入 + 自动备份 + mtime 热重载）。调度三类型、定时器钳制（最大延迟 60s、最小重触发间隔 2s）、错误指数退避（30s→1min→5min→15min→60min）、卡住任务 2h 超时清理、双会话目标（main: systemEvent / isolated: agentTurn）、超时控制（Promise.race + abortController）、Heartbeat 集成（server-cron.ts 注入三回调，Wake 模式 `next-heartbeat`/`now`）、Webhook 通知、CLI 六命令、七大设计特点。

调度类型定义（原文）：

```typescript
type CronSchedule =
  | { kind: "at"; at: string }
```

## 3.4 工具系统（详见 [[openclaw工具系统六层架构]]、[[七步工具策略管道]]）

六层架构：Tool Creation → Tool Definition → Schema Normalization → Policy Pipeline → Execution+Hook → Plugin System，外加 HTTP Invocation API（`POST /tools/invoke`）。8 个内置工具：browser/memory/message/exec/canvas/gateway/tts/process。

`AnyAgentTool` 核心类型（tools/common.ts:8）与 `ToolPolicyConfig`（原文）：

```typescript
type AnyAgentTool = AgentTool<any, unknown> & {
  ownerOnly?: boolean;  // 仅所有者可用标志
};

type ToolPolicyConfig = {
  allow?: string[];      // 白名单
  alsoAllow?: string[];  // 追加白名单
  deny?: string[];       // 黑名单
  profile?: "minimal" | "coding" | "messaging" | "full";
};
```

Schema 规范化三厂商适配：Anthropic 保持完整 JSON Schema draft 2020-12 兼容；OpenAI 确保顶层有 `type: "object"`；Google/Gemini 清理不支持的约束关键字；所有提供商合并 `anyOf`/`oneOf` union schemas。

工具调用 12 步完整流程（原文压缩链路）：

```text
用户消息 → Gateway 接收 → 构建工具列表 (createOpenClawCodingTools())
→ 应用策略过滤 (applyToolPolicyPipeline()) → 规范化 Schema (normalizeToolParameters())
→ 发送给 AI 模型 → AI 生成 tool_use → 工具执行前检查 (before_tool_call hook)
→ tool.execute() → 工具执行后处理 (after_tool_call hook) → 返回 tool_result → AI 继续推理
```

## 3.6 上下文管理（详见 [[openclaw上下文构成]]、[[openclaw压缩四步流水线]]、[[上下文剪枝cache-ttl模式]]、[[工具结果上下文守卫]]、[[压缩后关键章节重注入]]）

- Context 四类构成（系统提示词、工具列表+描述、Skills 仅元数据、工作区位置+时间+运行时数据），**Context ≠ Memory**；窗口五级解析优先级；`CONTEXT_WINDOW_HARD_MIN_TOKENS = 16_000` / `CONTEXT_WINDOW_WARN_BELOW_TOKENS = 32_000` 双阈值守卫。
- 压缩：四步流水线（估算→分块→摘要→裁剪）+ JSONL 持久化 + 自适应分块三常量 + 过大消息三级降级 + `targetTokens: 0.7`。
- 剪枝：cache-ttl 模式、5 分钟 TTL、软修剪（保留头尾各 1500 字符）/硬清除（占位符）、四重保护。
- 工具结果守卫：单条 50% 上限 + 总预算 75% headroom。
- 运行时注入：七个 md 文件族、bootstrap 双上限（20000/150000）、压缩后重注入 AGENTS.md 关键章节、五条调试命令。

Compaction vs Pruning 对比表（原文）：

| 特性 | Compaction | Pruning |
|------|-----------|---------|
| 作用范围 | 整个历史 | 仅 toolResult 消息 |
| 持久化 | ✓ 写入 JSONL | ✗ 仅内存 |
| 触发时机 | 接近窗口上限 | 每次请求前 (TTL 过期时) |
| 内容变更 | 生成摘要 | 软修剪/硬清除 |

剪枝默认配置（`src/agents/pi-extensions/context-pruning/settings.ts` 原文）：

```javascript
DEFAULT_CONTEXT_PRUNING_SETTINGS = {
  mode: "cache-ttl",
  ttlMs: 5 * 60 * 1000,        // 5 分钟 TTL
  keepLastAssistants: 3,       // 保护最后 3 条助手消息
  softTrimRatio: 0.3,          // 上下文占用 > 30% 触发软修剪
  hardClearRatio: 0.5,         // 上下文占用 > 50% 触发硬清除
  minPrunableToolChars: 50_000,
  softTrim: { maxChars: 4_000, headChars: 1_500, tailChars: 1_500 },
  hardClear: { enabled: true, placeholder: "[Old tool result content cleared]" },
}
```

默认注入文件清单：AGENTS.md（项目规则）、SOUL.md（角色定义）、TOOLS.md（工具指南）、IDENTITY.md（身份信息）、USER.md（用户偏好）、HEARTBEAT.md（心跳状态）、BOOTSTRAP.md（首次运行引导）——与 [[openclaw工作区md文件族]] 一致，构成双源互证。
