## 全文结构（五部分）

1. **场景抽象——四大高频场景类型**：按第一性原理归纳复杂指令、知识问答、问题排查、常规碎片化四大场景（coding 单列课题除外），覆盖近 80% 日常工作任务。
2. **技术破局——四套解决方案**：分层解耦整体架构 + 四场景各自的方案设计（详见 [[四大高频场景抽象]]、[[智空间分层解耦架构]]）。
3. **prompt 插拔式架构——框架 prompt + 业务定制**：以意图识别 Agent 为例的双层 prompt 契约（"prompt 即代码、设计即架构"）。
4. **平台落地——从技术方案到"助手工厂"**：四套解决方案固化为四套模版 → [[助手市场]] → "选择模板→配置→生效"三步法（[[三步法配置助手]]）。
5. **总结展望**：方法论三步法（[[场景抽象三步法]]）、配置化到自动化（[[配置化到自动化]]）、智能化与基建并行（[[智能化与基建并行]]）、金句"平台是骨架，专家经验才是灵魂"（[[专家经验沉淀论]]）。

核心叙事贯穿全文：业务方"配"助手而非"开发"助手；专家专注沉淀专家经验，平台屏蔽 agent 设计 / prompt 配置 / 工具召回复杂度。

## 核心量化声明（自报，无口径）

- 近 80% 的日常工作任务可归为四大类场景（声明方法为"第一性原理+贴身观察和行为分析"）。

### 复杂指令场景核心流程

```
1. 预处理
2. 意图识别
3. 意图处理
4. 工具召回（过滤引擎）
5. 推理执行
6. 总结&返回
```

预处理模块负责多模态识别处理与内嵌式命令快速响应（"能不用LLM就不用LLM"）。

### IntentResult 七字段解析实例（输入："给用户1234发放一张满50减20的优惠券，预发环境"）

| 字段 | 解析值 |
|------|--------|
| 谁 | 一般是我，不用解析 |
| 什么地点 | 预发环境 |
| 什么条件 | 未提供 |
| 关联方是谁 | 用户1234 |
| 做什么 | 发放 |
| 对象是什么 | 满50减20的优惠券 |
| 什么时间 | 现在 |

### 逆向推理正向执行四步（推理执行）

1. 目标工具筛选：从发券目标出发，找到能完成发券的工具A
2. 依赖分析：工具A需要用户ID作为输入，但当前指令没提供
3. 上游追溯：找到能查询用户ID的工具B
4. 形成工具链：工具B（查询用户ID）→ 工具A（发放优惠券）

### 四重安全校验

1. 环境校验：确保工具在当前环境（预发/线上）可用
2. 读写类型校验：严格控制影响面，查询类意图绝不用写类工具
3. 功能匹配校验：确保工具能力与目标一致
4. 权限与影响面校验：验证用户权限，防止越权操作

### 知识问答场景

- 推理流程六步：预处理 → query改写 → 知识汰换 → 上下文生成 → 答案生成 → 图片填充
- 图文嵌入模式四步：文本拆分为逻辑连贯文本块 → 图片经图像解析Agent生成结构化语义摘要 → 图片摘要回填对应文本上下文形成图文关联知识块 → 文本和图片分别向量化但语义层面保持关联
- 动态知识筛选三信号：`topicSwitch`（是否发生话题切换）、`dialogAct`（当前轮对话行为类型）、`infoNovelty`（当前轮信息新鲜度）

### 问题排查场景：ReAct 推理模块输入五要素

- IntentResult：来自意图识别 Agent
- 原始query：用户的原始输入请求（需作为最终结果校验的基准）
- tool_results：本轮已执行的工具调用结果
- 历史对话：用户与平台的过往交互记录
- mcp工具池：平台注册的工具信息

执行约束四条：①输出结构化模型 ToolExecutionChain；②只思考不执行；③多轮迭代基于历史推理；④保持严谨、安全性。

### 执行引擎场景适配表

| 场景类型 | 推荐引擎 | 原因 |
|---------|---------|------|
| 简单排查（答疑） | ReActExecutor | 快速响应（少一步LLM调用），无需复杂评估。 |
| 多步骤业务流程 | ReActObversationExecutor | 需动态评估每一步结果，确保流程正确性。 |
| 需要错误恢复 | ReActObversationExecutor | 观察者可触发重试或回退策略。 |

### 意图识别 Agent：三目标与框架/业务定制双层结构表

三目标：理解用户语义，确保语义完整；解析指令，规范输出；意图分类（可选）。

| | 框架 prompt | 业务定制 |
|---|---|---|
| 功能抽象 | 语义结构；输出格式；步骤拆解逻辑；追问逻辑；归一化逻辑 | 意图分类；归一化词表；案例声明 |
| prompt结构 | 角色定义（职责；原则）；输出模型定义（IntentResult）；深层语义结构识别；意图分类（通用意图；业务定制）；信息抽取与字段规则（如何从query中抽取元素，组装IntentResult）；语义完整与追问逻辑；语义归一化；特殊场景处理 | 业务说明（业务信息补充）；意图定义（分类）（意图定义、说明；意图分类方法；数据完整性校验（可选））；归一化词表（动作、实体）；案例说明 |

业务定制模版结合前端产品设计开放模块，由助手创建者填写（原文"又助手创建者填写"疑为"由"之笔误）——"配"而非"写"的直接证据。
