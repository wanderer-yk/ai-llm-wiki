# 治愈 Cursor AI 编程的「幻觉」？用它就够了！

## 基本信息

- **作者**：天玑前端团队（爱奇艺）
- **发布平台**：微信公众号「爱奇艺技术产品团队」
- **发布日期**：2026-03-26 12:00
- **地点**：北京
- **标记**：原创

## 内容概要

本文是爱奇艺天玑前端团队基于一年 AI Coding 实践经验的技术分享，核心介绍其自研的**规格驱动 AI 开发流程 Specflow**，旨在解决 [[cursor]] AI 编程工具的幻觉问题，实现开发流程标准化与效率提升。

## 文章结构

### 01# 背景
团队从 [[vibe-coding|Vibe Coding（氛围编码）]] 的早期快感走向瓶颈期，识别出 AI 辅助编程效率波动的两大根因：**上下文断层**（多轮对话中 AI 丢失上下文）和**需求共识缺失**（人与 AI 对需求理解不一致）。核心论点：AI 不缺代码实现能力，缺的是精准的"指令规格"。

### 02# 方案设计
深入调研三种业界 SDD 方案并提炼启发：
- [[openspec|OpenSpec]]：原子化变更理念
- [[github-spec-kit|GitHub Spec Kit]]：严格门控理念
- [[bmad-method|BMAD-METHOD]]：角色思维隔离理念

融合三者之长自研 Specflow，提出四大设计哲学：
1. **全链路流程闭环**（Specify→Plan→Implement→Archive 四阶段）
2. **严格物理门控**（[[blocker-gate|Blocker Gate]] 硬性阻断）
3. **[[单指令状态机]]**（`/specflow` 零心智负担自动寻迹）
4. **[[ssot单文档策略|SSOT 单文档策略]]** + [[多agent角色思维隔离|多 Agent 角色思维隔离]]

### 03# 具体实现
四阶段核心工作流，每阶段有独立命令、角色定义、核心动作和标准产物：
- **Specify**（`/specflow-specify`，PM 角色）→ 产物 `ai-docs/{ID}/specify.md`
- **Plan**（`/specflow-plan`，架构师角色）→ 产物 `ai-docs/{ID}/plan.md`
- **Implement**（`/specflow-implement`，工程师角色）→ 按 Group 原子化编码 + 断点 Review
- **Archive**（`/specflow-archive`，知识管理员角色）→ 知识脱水 + 归档

### 04# Quick Start
前置要求：仅支持 Cursor IDE、Node.js ≥ 18.0.0。通过爱奇艺私有 npm 镜像源安装 Specflow CLI，初始化时将 Commands 和 Templates 注入项目 `.cursor` 目录。

### 05# 最佳实践指南
以 Step-by-Step 形式详述各阶段实操：Specify 阶段支持 UI 设计图上传、`[User]` 区域填写；Plan 阶段通过 `[Block]`/`[?]` 双级问题标记实现灵活门控；Implement 阶段按 Group 顺序原子化编码并强制断点 Review；Archive 阶段含 Dry-run 安全机制。

### 06# 未来规划
提出 Specflow 2.0 从"模拟流程"进化为"自治架构"：**Subagents**（深度角色隔离、上下文裁剪、自主验证闭环）和 **Agent Skills**（意图驱动流转、原子能力封装）。

### 07# 写在最后
阐述"研发范式前移"理念——将问题解决的关键环节从编码调试期前移至需求设计期。核心主张：未来核心竞争力 = 定义需求 + 拆解任务 + 驾驭规范。

## 关键发现

- 文章全程**未提供量化效果数据**（效率提升百分比、幻觉率下降等指标均缺失）
- Specflow 目前通过**爱奇艺私有 npm 镜像源**分发，尚未公开/开源
- 概述段落称第四阶段为"Achieve"，但详细工作流中命名为"Archive"，存在命名不一致

## 局限性

1. 无对照实验或 A/B 测试数据支撑"治愈幻觉"和"提效"主张
2. Specflow 与三种社区方案（OpenSpec/Spec Kit/BMAD）的对比仅为定性分析
3. Blocker Gate 判定逻辑、业务感知进化的长期效果等关键细节未详述
4. 工具尚未公开，外部可复用性未知
