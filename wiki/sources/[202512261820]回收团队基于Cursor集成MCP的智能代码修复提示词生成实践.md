# 回收团队基于Cursor集成MCP的智能代码修复提示词生成实践

## 基本信息

- **作者**：[[刘雅斌]]（侠客汇 Java 开发工程师）
- **发布平台**：[[转转技术]] 微信公众号（IP 属地北京）
- **发布日期**：2025-12-26
- **实践主体**：[[回收团队]]（转转公司旗下）

## 核心问题

文章从 AI 修复 Sonar 扫描问题的痛点出发，指出三大典型失败模式：拒绝处理大文件、修复目标但连带改坏周边逻辑、上下文超限。核心洞察为**问题不在 AI 能力，而在提示词质量**——模糊提示词通过三条路径浪费 Token：输入冗余（含不相关内容）、输出膨胀（模型覆盖多种解释）、无效多轮修正循环。

AI 代码修复的四大失败模式为：上下文冗余（几千行文件仅 20 行相关）、缺乏规范引导、信息不准确（未精确定位方法/结构）、没有示例（AI 缺修复参考）。

## 核心方案：六步智能提示词生成法

设计哲学为"让 AI 精确理解问题，而非猜测问题"。完整方案参见 [[六步智能提示词生成法]]。

### 第一步：Sonar 规则类型映射

`IssueTypeClassifier` 将 Sonar 具体 rule key 静态映射为七大高层问题类型：空指针（java:S2259/S2637）、资源泄露（java:S2095/S2093）、SQL注入（java:S3649）、命令注入（java:S2076）、命名规范（java:S117）、重复字符串（java:S1192）、通用兜底。未知规则自动归入 General。

### 第二步：AST 精准方法定位

`JavaCodeParser` 使用 [[javalang]] 纯 Python 库（无需 JDK）解析 Java 源码 AST，按行号区间匹配定位问题行所属方法，提取方法名、参数、返回值、修饰符等结构化上下文。AST 解析的四大价值：精确定位（区分同名方法）、完整信息（方法签名元数据）、语法理解（不受注释/字符串/Lambda 干扰）、99%+ 准确率。

### 第三步：问题类型差异化上下文提取

`ContextExtractor` 根据问题类型配置差异化提取策略——高风险问题提取完整方法+imports+类声明，低风险问题仅提取周围代码。参见 [[问题类型差异化上下文提取]]。

量化参数：NullPointer max_lines=150, ResourceLeak=100, SQLInjection=120, NamingConvention=30, General=50。AST 解析失败时优雅降级到问题行前后各 25 行。

### 第四步：分层模板体系

`PromptTemplateEngine` 三层结构组装提示词：角色设定 + 通用编码规范（阿里巴巴 Java 开发手册 6 条核心规则）+ 问题类型专属修复要求。参见 [[分层模板体系]]。

专属模板覆盖 NullPointer（防御性检查 + IllegalArgumentException）、ResourceLeak（try-with-resources）、SQLInjection（PreparedStatement 参数化查询）三种类型，其余降级到通用默认模板。

### 第五步：Few-shot 示例库

`ExampleRepository` 预置修复前后对比案例，让 AI 通过案例学习修复模式。参见 [[few-shot示例库]]。NullPointer 提供两个示例（单参数检查、多参数检查），ResourceLeak 和 SQLInjection 各一个。

### 第六步：MCP 服务整合

`IntelligentPromptGenerator.generate_for_issue()` 串联前五步，新增 Token 估算（`len(prompt) // 4`）和元数据追踪。`auto_fix_sonar_issues` 通过 `@mcp.tool()` 装饰器暴露为 MCP 工具，使用 httpx 异步调用 [[sonar]] API，逐一生成提示词。每个 issue 独立 try/except 容错。

依赖极简化：mcp≥0.9.0、httpx≥0.27.0、javalang≥0.13.0 共 3 个包。

## 部署与使用

通过 `~/.cursor/mcp.json` 注册名为 `intelligent-code-fix` 的 MCP 服务，在 Cursor 聊天窗口通过 `@intelligent-code-fix` 调用。实际项目 `hunter_partner_recycle_core` 验证了 10 个 Sonar issue 的批量修复。

## 量化效果

- 成本降低 70%（精准上下文提取减少 Token 使用量）
- 准确率提升 30%（结构化提示词 + Few-shot 示例引导）
- 效率提升 3 倍（自动化流程）

> ⚠️ 以上量化数据未提供测量方法论和基线定义，数据可信度无法独立验证。

## 核心抽象

文章最终将方案抽象为通用原则——[[非结构化转结构化提示词]]：将代码扫描工具的非结构化输出自动转换为结构化 AI 提示词，适用于 Sonar/ESLint/Checkstyle 等任意扫描工具。AI 辅助开发有效性的四要素：问题精准识别、上下文智能提取、规范有效注入、经验系统沉淀。

## 矛盾与局限

- `IssueTypeClassifier` 映射 7 种类型，但 EXTRACTION_RULES 仅 5 种、ISSUE_TEMPLATES/EXAMPLES 仅覆盖 3 种——CommandInjection/DuplicateString 无专用规则和模板
- Token 估算 `len(prompt) // 4` 对中文内容严重偏低（中文字符 Token 比例远高于 1/4）
- Sonar API 使用 Cookie 鉴权（非 OAuth/API Token），存在过期和安全隐患
- 脚本路径硬编码绝对路径，跨机器复用需各自修改
