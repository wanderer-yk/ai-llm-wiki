# AI编程能力边界探索：基于 Claude Code 的 Spec Coding 项目实战

得物技术公众号（作者 [[阳凯]]，2026-03-11）发布的 Claude Code Spec Coding 项目实战长文：以 10 天、217 条指令、2,754 次工具调用、25,546 行净增代码，完成企业级中后台系统（code-knowledge-qa，代码知识问答）从 0 到 1 搭建。方法论核心是「约束 + 示范 + 视觉」[[三层规范体系]]，能力边界结论凝练为 [[需求颗粒度三档协作模式]]、[[AI顶级执行者比喻]]、[[AI失效三模式]]、[[开发者角色重构]] 与 [[确定性空间边界论]]。本文是得物技术公众号的第二篇 Claude Code 主题文章（第一篇为稚归署名的 [[sources/[202601261830]AI编程实践从ClaudeCode实践到团队协作的优化思考得物技术|AI编程实践：从ClaudeCode实践到团队协作的优化思考]]）。

## Spec Coding 定义与价值

核心思想是**「在写代码之前，先写规格文档」**，通过 [[openspec]] 工具实现，每个功能变更经历 proposal → design → specs → tasks 阶段流程。文中案例标题直接使用"SDD"（案例二、三），**Spec Coding 与 SDD 在本文中同义使用**，即 [[规格驱动ai开发]] 的别名。价值三要点：

1. **减少返工**：proposal 阶段明确方向；
2. **适合复杂功能**：tasks 分组聚焦；
3. **可审计**：proposal→design→specs→tasks 完整决策链留痕。

## 四个典型案例

### 案例一：AI 驱动产品设计（Persona）

单工程师借 Persona 角色扮演覆盖产品经理/UI 设计师/工程师三职责。Rules 植入「首席产品专家」Persona，将 AI 从「急于执行」切换为「先想清楚」模式；对话式生成高保真 HTML（非源码）；HTML 稿再作为上下文生成组件行为级 PRD。与 [[多agent角色思维隔离]]、[[图片转结构化提示词]] 存在方法同构，构成「设计阶段前置为上下文源」链条。

### 案例二：SDD 驱动前端功能研发（定时任务管理）

「定时任务管理」模块 + 6 个后端接口，`opsx:new` → `archive` 完整命令链（[[opsx指令集]]），验证 SDD+MCP 联调路径：接口 URL → MCP 直连文档 → 一次获取字段/枚举/必填项 → 接口文件一次生成 → 零联调返工。量化（自报）：人工指令 < 10 条、AI 代码占比 100%、6 个接口零联调返工、单日 3 个完整模块、人效提升 3 倍（基线为「按纯人工开发」对照估算）。源文 typo：「SSD需求开发」应为 SDD。

### 案例三：SDD 驱动系统重构（知识问答首页）

9 组 34 个子任务（含 4 个验证任务）全部完成；人工干预 < 5 条指令；7 个业务组件解耦；`useChat` 20+ 方法（4 种职责）拆为 3 个单职责 hook；`ChatInterface` 17 props → 6-8 props。提出 **SDD 重构三问**（改什么 / 不能改什么 / 按什么顺序改），论断「新功能从无到有可大胆生成；重构是在活体系统上动手术」，与 [[零排期渐进式重构]]、[[执行语义冻结]] 呼应。

### 案例四：复杂问题排障（AI 能力边界）

约 4 小时 / 7 个会话 / 15+ 次方案尝试 / 59 条指令——全项目单日指令峰值与 AI 独立解决能力最受限日。测试环境构建失败的三条根因：

1. `.npmrc` 历史副作用：`omit=optional` 无意跳过 `@tailwindcss/oxide-linux-x64-gnu`，postinstall 循环等待；
2. Prisma v6 境外下载沉默卡死：`node_modules/@prisma/fetch-engine/dist/index.js` 第 2319 行，不报错不超时；
3. pnpm 跨平台 lockfile 不一致：macOS arm64 lockfile 缺 Linux x64 native package；切 npm 则 lockfile 被忽略。

最终解法配置（原样保留）：

```text
锁定 tailwindcss@4.1.11
PRISMA_ENGINES_MIRROR=https://registry.npmmirror.com/-/binary/prisma
统一使用 pnpm，CI 命令同步更新，删除 .npmrc 中的 omit=optional
```

由此提炼 [[AI能力边界三结构性特征]]：AI 每次分析都正确，失效源于问题结构而非推理能力。

## 三层规范体系（CLAUDE.md + Rules）

结构（原样保留）：

```text
第一层：约束层（.claude/rules/）      ← 告诉 AI「禁止什么、必须怎样」
第二层：示范层（.claude/code-design/）← 告诉 AI「标准产出长什么样」
第三层：视觉层（.claude/ui-design/）  ← 告诉 AI「页面应该长什么样」
```

**约束层 7 个规范文件：**

```
.claude/rules/
├── ts.md          # TypeScript 规范（禁止 any、使用可选链等）
├── code-names.md  # 命名规范（kebab-case/camelCase/PascalCase）
├── comment.md     # 注释规范（JSDoc、@ai-context/@ai-rules 文件头）
├── lint.md        # 代码风格（单引号、文件末尾换行）
├── style.md       # 样式规范（Tailwind CSS、less 文件）
├── pages.md       # 页面目录结构规范（constants/services/hooks/components 分层）
└── service.md     # API 接口生成规范（fetch{Name}Api 命名、UniversalResp 泛型）
```

**示范层 6 个标准模板：**

```
.claude/code-design/
├── pro-table/           # 通用列表页模板（含搜索、分页、批量操作、行操作）
├── pro-form/            # 通用表单页模板（含创建/编辑双模式、字段验证）
├── editable-pro-table/  # 可编辑表格模板（含行内编辑、添加/保存/删除）
├── drawer/              # 抽屉组件模板（含标准打开/关闭逻辑）
├── compontent/          # 通用组件模板（含 README、Props 定义、使用示例）
└── utils/               # 工具函数模板
```

**视觉层 HTML 设计稿：**

```
.claude/ui-design/
├── knowledge-spaces.html  # 知识空间列表页设计稿
├── search-strategy.html   # 检索配置页设计稿
├── space-detail.html      # 空间详情页设计稿
└── xxx设计稿
```

实际效果（自报）：正面 4 例——205 个文件保持 `fetch{Name}Api` / `I{Name}Req/Res` 命名一致、目录分层被遵守、模板被继承、可选链普及；人工干预 3 例——2/24 单文件不分层（一条追问修复）、2/27 `.less` 误用（项目实际配置 SCSS，即时修正）、antd v5 废弃 API（`destroyOnClose`/`dropdownStyle`，AI 沿用训练数据中高频的 v4 习惯，靠构建报警触发修正）。核心结论即 [[约束非能力论]]；示范层模板「后续可以切换为 skills」。

## MCP 工具：消除信息断层

- **接口文档直连 MCP**：累计调用 21 次，完成 39 个接口联调，支持同步生成 mock 数据，`interface.ts` 类型定义「无需人工校对」；
- **飞书云文档直读 MCP**：AI 直接读取 [[飞书]] 中的 PRD/设计说明/技术文档，免复制粘贴。

文末确认现状：「本项目 MCP 仅覆盖了接口文档、飞书文档」，后续拟接入设计稿、测试用例、发布平台、日志平台（MCP 工具链纵向延伸）。详见 [[MCP消除信息断层]]。

## 经验总结

### AI 顶级执行者比喻

否定「Copilot」比喻的完整性，代之以三特征模型：极度服从 / 无限耐心 / 无内部业务常识（208 次 TodoWrite 为「无限耐心」佐证）。详见 [[AI顶级执行者比喻]]。

### 能力边界：需求颗粒度三档协作模式

按需求颗粒度选择协作模式（原表保留）：

| 颗粒度 | 场景 | 策略 | 理由 |
|--------|------|------|------|
| 小颗粒 | 改文案、修显隐逻辑、调 CSS 间距 | Cursor Chat 对话即扫即改 | 沟通成本低于编写规范成本 |
| 中颗粒标准化 | 标准 CRUD 页面、简单业务组件 | Cursor Rules 或 Skills 预设规范（如 pro-table.mdc） | 有强烈"模式感"：识别场景→读取示例→生成类型→完成 UI |
| 中大颗粒复杂 | 重构核心逻辑、复杂业务模块、无参考代码新功能 | OpenSpec 标准流（SDD） | 业务复杂时 AI 易幻觉/需求偏移；Spec 强制先设计后编码，留痕具维护价值 |

详见 [[需求颗粒度三档协作模式]]。

### AI 失效的三种模式

核心论断：「AI Coding 的失效不是随机的，而是可归类的」（原表保留）：

| 模式 | 表现 | 发生频率 | 应对 |
|------|------|----------|------|
| 规范真空 | 功能正确但风格/结构偏离团队约定 | 高（新功能开发初期尤甚） | 在 CLAUDE.md 或 code-design 补充规范，一次修复全局生效 |
| 信息孤岛 | 本地正常 CI 失败；只解当前暴露的问题 | 低但代价高 | 架构设计阶段锁定跨平台/跨环境依赖；环境差异写成规范前置 |
| 任务目标模糊 | 把「该问人的问题」当「执行问题」（如「优化一下首页」→ 悄改组件结构） | 中 | Spec 工作流 proposal 阶段强制先描述「Why」 |

详见 [[AI失效三模式]]。

### 开发者角色的重构

三项新核心竞争力：规范设计能力（作者主张其价值大于同等功能代码能力）、系统性思维（AI 只解局部不看全局）、质量意识前移（Review 从代码完成后前移至方案设计/任务执行阶段）。详见 [[开发者角色重构]]。

### 值得期待的方向（规划性质，尚未落地）

1. **规范体系结构化积累**：踩坑→提炼规范→自动追加闭环（现 7 条规范文件为手动维护）；
2. **MCP 工具链纵向延伸**：设计稿、测试用例、发布平台、日志平台；
3. **多 Agent 并行开发**：动机是大型任务执行等待时间较长（源文 typo「多Agen并发」）。

### 一句话总结（文末定稿）

10 天、217 条指令、2,754 次工具调用、25,546 行净增代码。杠杆比喻：**规范是杠杆，AI 是力，Spec 工作流是支点**——即 [[确定性空间边界论]]。

## 矛盾与疑点

- 「10 天」总周期 vs 阶段二至四已合计 10 个工作日、设计阶段亦在「10 天演进过程」章节内——口径未解释（文末重申仍未解）；
- 提效 36% / 人效提升 3 倍 / AI 代码占比 100% 均无基线与测量方法，且全文为 AI 生成报告 + 人工校准 → 挂接 [[ai工程量化效果声明追踪]]；
- `style.md` 注释「less」vs 2/27 干预案例称项目实际使用 SCSS——规范文件描述滞后或行文笔误；
- `pro-table.mdc`（[[cursor]] Rules 专有格式）与 `.claude/` 目录并存，规则体系可能历经 Cursor→Claude Code 迁移；
- 源文 typo：「SSD」（应为 SDD）、「多Agen并发」。
