# Agent Skills 与 MCP：一场被误解的替代战争

**作者**：牛潇（京东 EI），IP 属地北京
**发布平台**：微信公众号「京东技术」
**发布时间**：2026-02-27

## 核心论点

本文系统阐述了 [[agent-skills|Agent Skills]] 与 [[mcp]]（Model Context Protocol）并非替代关系，而是互补搭档。文章纠正业界"Agent Skills 会取代 MCP"或"MCP 已过时"的二元对立叙事，提出**能力 vs 行为二分法**：MCP 解决"能不能做"的能力边界问题（能力导向、服务化架构），Agent Skills 回答"怎么做才对"的行为规范问题（流程导向、声明式架构）。

核心金句：*"真正的智能，不在于选择某一种工具，而在于知道何时用哪一种，以及如何让它们共舞。"*

## 概念定义

### MCP 五大核心特性
1. **能力扩展协议**（标准化接口）
2. **安全沙箱规范**（权限/隔离/审计）
3. **上下文同步机制**（内外状态一致性）
4. **标准化接口**（JSON-RPC 等协议）
5. **服务化架构**（独立部署、水平扩展）

### Agent Skills 五大核心特性
1. **流程编排标准**（原子操作组合为业务流程）
2. **上下文感知能力**（根据历史和环境动态调整）
3. **透明可解释性**（决策路径人类可见）
4. **轻量级集成**（无服务部署、配置即生效）
5. **组合式架构**（支持嵌套/组合/复用）

## 设计哲学差异

| 维度 | MCP | Agent Skills |
|------|-----|--------------|
| 关注焦点 | "什么"和"能否"（能力中心） | "为什么"和"如何"（业务中心） |
| 架构本质 | 服务化（独立部署、水平扩展） | 声明式（配置即生效、无服务部署） |
| 维护主体 | 工程师和 SRE | 产品经理和业务专家 |
| 架构隐喻 | 企业 IT 基础设施 | 企业 SOP 手册 |
| 变更频率 | 低（严格测试审批） | 高（随业务灵活调整） |

## 三个实战场景

1. **客户服务工单处理**：Agent Skills 编排业务流程（意图分类→数据需求→回复生成），MCP 提供安全数据访问（订单历史/系统状态/客服备注）
2. **金融风险评估**：Agent Skills 封装合规规则与决策逻辑，MCP 提供敏感数据访问、专业模型调用和审计追踪
3. **Claude Code 自动化部署**：MCP 层封装 CI 系统和 S3 上传（`DeploymentMCP`），Skills 层用 [[claude-md|CLAUDE.md]] 声明式定义部署流程和安全规则

## 选择建议与高阶策略

### 基础决策框架（6.1）

**Skills 优先的五项判据**：业务规则复杂多变、需人类可读规范、涉及主观判断、强调一致性合规性、快速原型迭代。

**MCP 优先的五项判据**：需访问外部数据源、性能要求严格、安全性至关重要、需精确控制、跨系统集成。

### 经典协同模式三式（6.3）

1. **模式1：分层架构** — Skills 定义 why/what，MCP 提供 how，严格分离关注点，实现变更独立性
2. **模式2：技能驱动型 MCP** — Skill 中用条件逻辑动态选择最合适的 MCP 工具（基于数据新鲜度/数据量/安全等级）
3. **模式3：MCP 增强型技能** — MCP 工具基于历史数据分析+ML 推荐最优工作流，形成闭环学习系统

## 真实工程三大误区

1. **用 MCP 实现所有功能** → 过度工程化，业务逻辑与技术实现耦合。解法：优先评估是否需外部系统访问
2. **在 Skills 中硬编码复杂逻辑** → 超过 2000 行复杂条件导致不可靠。解法：将复杂逻辑拆分为 MCP 工具，Skills 只做编排
3. **忽视安全边界** → 在 Skills 暴露敏感操作引发数据泄露风险。解法：强制敏感操作走 MCP
