### 摘要

《如何设计一个AI Agent系统》一文由淘天集团 SRE 团队北桓撰写，发布于微信公众号"大淘宝技术"。文章从工程实践角度系统阐述如何设计、实现和落地可控且可用的 AI Agent 系统。内容涵盖理论基础（Software 1.0/2.0/3.0 范式演进）、四要素（Planning/Memory/Tools/Action）、六大具体技术板块，以及"Agent 工程实践"部分（含三种 Agent 设计范式与三种开发方式分析）。实践案例"AI需求资损分析"涵盖五步人工流程拆解、工作流设计范式的架构选型及四大设计支柱、知识体系构建（基于 MSRA RAG 分级）、产品化设计（AI资损资控门禁），最终以九条个人实践体会作为全文总结。

### 概念

- **可控且可用的 AI Agent 系统** — 文章核心设计目标
- **AI Agent 标准公式** — AI Agent = LLM (Reasoning) + Planning + Memory + Tool Use
- **提示词工程 / 推理能力 / 工具扩展 / 记忆管理 / 执行架构 / 协同与进化** — Agent 核心技术组件（Part 1-6）
- **Agent研发流程三转变** — 核心关注点、流程驱动力、协作方式三个维度的转变
- **Agent 设计范式三分类**：最小可用范式、工作流式（确定性优先）、动态规划式（ReAct/Plan-and-Execute）
- **Agent 开发方式三分类**：纯 Prompt 型、拖拽/低代码型、纯代码型
- **AI需求资损分析** — 嵌入研发pipeline的自动化资金损失风险分析实践
- **资损风险三挑战** — 资源与风险错位分配 + 专家经验规模化难题 + 评估流程效率瓶颈
- **三态架构** — 运行态（MoE调度领域Agent）/ 归档与保鲜（结构化沉淀+知识自动更新）/ 研发态（数据集+验证Agent+动态回流）
- **五步人工资损分析流程** — Step1 判断资损需求→Step2 需求改动点提炼→Step3 丰富业务需求→Step4 召回相似场景→Step5 资损布控场景分析
- **失血模型** — 各领域持续沉淀的资金损失场景模型
- **确定性推理管道** — 工作流范式的核心实现
- **工作流范式四大设计支柱**：多源输入标准化、需求点/实现点抽象、变更影响面分析、资金风险描述语言
- **rag查询四级分类** — MSRA 论文分级：Level1 明确事实→Level2 隐含事实→Level3 可解释推理→Level4 隐藏式推理
- **资金安全知识三类上下文能力** — 语义对齐+链路落点+经验复用
- **agent能力vs agent产品** — 好的 Agent 能力不等于好的 Agent 产品
- **ai资损资控门禁** — 将 Agent 输出转化为研发可执行的门禁
- **最小可用范式起步** — 从 Prompt + LLM 验证核心价值，渐进引入复杂范式，遵循奥卡姆剃刀
- **混合架构常态** — "工作流外壳 + 智能内核 + 知识管理"三层结构为生产环境主流
- **智能vs稳定权衡** — 智能是奢侈品，稳定是必需品，错误可预测比高准确率更重要
- **分层任务策略** — 简单高频用规则小模型、复杂低频用大模型、关键环节人工审核
- **ai的次要困难与根本困难** — AI 消除次要困难但无法解决根本困难，对人要求更高
- **知识工程流程** — 业务专家+知识工程师协作的知识管理体系，决定 Agent 能力上限
- **评估驱动迭代飞轮** — "无评估不迭代，无数据不优化"，线上发现→标注→优化→验证闭环
- **过渡型vs重构型产品策略** — 人机协同兜底 vs AI 视角重新设计交互
- **agent作为团队成员** — Agent 组织管理新思维：明确职责、岗位说明书、持续培训、协作模式

### 主张

- AI Agent 系统设计应以工程实践为导向，追求"可控且可用"。
- Agent 研发流程本质上是"评估-迭代"循环，评估集是跨职能协作对齐的关键。
- AI 资损分析最终选用工作流范式，核心追求系统可控性。
- 从最简单可用版本开始是明智之选，过度工程化带来维护成本和不确定性。
- 混合架构（工作流外壳+智能内核+知识管理）已成为生产环境主流选择。
- "智能是奢侈品，稳定是必需品"——错误可预测可兜底比高准确率但偶犯低级错误更受欢迎。
- AI 消除了次要困难，但根本困难仍需人类承担；AI 的引入反而对人要求更高。
- 没有被量化验证的优化都是自我安慰。
- 好的 Agent 能力 ≠ 好的 Agent 产品，产品设计是建立用户信任的"最后一公里"。
- Agent 参与者都需要深度理解业务，不能简单分"产品定需求、工程写代码"。
- 在定义明确的特定领域内，Agent 会逐渐超越人类的稳定性，应作为"团队成员"培养管理。

### 证据

- 工作流范式支持每步可观测、可回溯、可评估，便于定位问题与迭代优化。
- MSRA RAG 分级论文提供 Level 1-4 查询任务分级理论框架。
- 资金风险描述语言输出可直接用于相似场景召回和核对脚本开发，形成闭环。
- MoE 架构+多租户设计支持各业务产品线独立接入、调试、灰度与上线。
- 归档机制结构化沉淀分析结论、命中风险点、校验脚本与效果指标。
- 单轮对话系统往往比多 Agent 协作更稳定高效（实践观察）。
- 85%但错误可预测的系统比 95%但偶犯低级错误的系统更受欢迎（用户体验反馈）。
- Agent 不存在情绪波动、知识遗忘和疲劳，能 7×24 小时保持一致服务。

### 矛盾

- 前文 Digest 记录为"四步人工流程"，文中明确为五步（Step5 资损布控场景分析）。

- **目标锚定与环路检测** — 每轮交互中强化原始目标；检测重复操作序列并强制中断循环。
- **可调试性与可观测性不足** — 复杂执行过程涉及多次模型调用、工具交互和状态转换，失败时难以追溯完整执行路径。
- **全链路追踪** — 端到端追踪系统，记录每次模型 I/O、工具调用（参数/结果/耗时）和关键状态变更。
