# 颠覆传统！意图规划+上下文工程+数据自迭代，让企业智能办公助手效能跃升200%

## 核心论点

文章针对企业智能办公助手"1天POC，1年难推广"的普遍困境，提出三层系统性框架：[[意图规划]]、[[上下文工程]]、[[数据自迭代]]，声称可实现查询准确率稳定 93% 以上、新知识上线成本降低一个数量级。

## 痛点分析

文章识别三大核心痛点：

1. **意图理解靠猜**：缺乏体系化意图识别框架，LLM 回答质量像开盲盒→信任度下降→沦为鸡肋
2. **知识接入路径单一**：传统 RAG 仅处理文本知识，企业知识库 60%+ 为非文本知识（培训视频、会议纪要），助手看不懂用不上
3. **答案评估全靠人工**：人工抽检仅覆盖 5% 对话，漏掉 95% 问题，存在幸存者偏差

## 产品架构

四层架构设计（从场景分析推导）：

| 层级 | 设计依据 | 技术选择 |
|------|----------|----------|
| 入口层 | Web 双端适配 + IM 内嵌 | 响应式一套代码，IM 机器人推送耦合 |
| 意图层 | 意图数量有限 → 小模型分类 | [[意图规划]]三子模块 |
| 交付层 | 三类用户需求差异 → [[Agent协同模式]] | [[上下文工程]]三大标准化接入 |
| 评估层 | 回答质量监控 → LLM 质检 | [[AI质检模型]] + 混淆矩阵对齐 |

三类核心用户：普通员工、专业工作者、高管，因需求差异显著，核心层必须多 Agent 协同交付。

## 量化指标

| 指标 | 数值 | 备注 |
|------|------|------|
| 意图识别准确率 | >99% | 迭代成熟后的稳态指标 |
| 任务交付准确率 | >93% | 整体混合指标，含 Agent 协同复杂场景 |
| 95% 意图识别基线 | — | 低于此值项目本质不可交付 |
| 宽表模式准确率 | 接近 100% | 40+ 字段员工数据聚合 |
| FAQ 转化准确率 | 98%+ | 动态数据静态化为知识对 |
| AI 质检一致性 | 89% | 混淆矩阵对齐，基准线 80% |
| 低质量回答中数值错误 | <1% | 95% 为四类语义问题 |

## 方法论关联

本文来自[[马上消费技术团队]]（金融科技行业），与 Wiki 中已有的 [[harness-engineering]]（爱奇艺数据库团队）、[[规格驱动ai开发]]（爱奇艺天玑前端团队）属于**不同公司、不同行业**的方法论，构成有价值的横向对比素材：

- [[上下文工程]]三类标准化接入 ↔ Harness Engineering 的[[多源分治策略]]（均强调信息按职责分类管理）
- [[数据自迭代]]动态迭代 ↔ Harness Engineering 的[[执行语义冻结]]事前冻结（方法论互补）
- [[主体合并宽表模式]]聚合策略 ↔ [[多源分治策略]]分离策略（信息组织策略差异）

- Agent 协同安全铁律（数据写入前强制用户授权） ↔ [[human-in-the-loop]] 概念高度一致
