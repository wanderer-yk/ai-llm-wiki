## Final Global Digest
### 摘要
本文来自微信公众号“腾讯程序员”，作者 stevenpxiao，发布于 2026 年 05 月 11 日。核心论点：“Harness 不是目的，知识才是护城河”。文章基于 Harness Engineering 三支柱，提出工作流可替换而知识可累积，创新设计了三维正交的知识分层架构（五层存储×五种类型×三级成熟度），构建了完整的知识流动闭环（独立Git仓库→协作治理→三通道沉淀→冷启动导入→Lint治理→引用追踪）。系统采用“文件系统即状态机”设计保障可见性与可迁移性，并结合 Hapi 内网版远程操控方案突破人在场依赖。文章最终将 AI Team 的设计哲学升华为“工作流是手段，知识是目的”，并指出了语义检索增强、跨团队知识联邦、自动质量评估、全异步工作流四大未来探索方向。

### 实体
- **stevenpxiao** — 腾讯技术工程团队成员，本文作者
- **腾讯技术工程 / 腾讯程序员** — 发布平台
- **AI Team 系统** — 包含 16 阶段状态机的 AI 工程交付工作流系统；设计哲学从“文件即状态”升华为“知识即资产”
- **Karpathy / Karpathy LLM Wiki** — 提出 LLM Wiki Pattern 的 AI 专家，三级索引设计及 Lint 机制（Ingest + Query + Lint）灵感来源
- **@doc-collector / @codebase-profiler / @knowledge-builder** — 冷启动管道三阶段 Agent
- **@archiver** — 知识自动提取 Agent，负责 ARCHIVE 阶段批量更新引用追踪
- **Hapi 内网版** — 远程操控工具，支持跨设备会话接管/24小时待机/PWA原生体验/多助手切换/自主模式（YOLO）
- **`/flow-import` 工具** — 多源收集冷启动工具，配合 `import-state.json` 实现断点恢复
- **Lint 机制** — 定期自动运行的治理系统，包含索引修复、孤儿降级、矛盾标记、过时归档、合并候选标记、成熟度

### 概念
- **知识分层架构** — 三维正交：五层存储、五种类型、三级成熟度
- **知识流动闭环** — 从独立 Git 仓库到协作治理，再到冷启动、Lint 治理、引用追踪
- **文件系统即状态机** — 利用文件系统的天然特性记录和驱动状态流转
- **知识即资产** — 核心哲学理念，将工作流从手段转变为目的沉淀

### 主张
- 工作流可替换，但累积的知识是真正的护城河。
- LLM 的上下文与知识提取是 AI 系统可持续发展的关键。
- 未来的发展方向在于语义检索增强、跨团队联邦、质量自动评估和全异步流。

### 证据
- Hapi 内网版的使用经验证明其有效突破了人类需实时在场的瓶颈。
- 基于 Karpathy LLM Wiki 的方法验证了 Lint 机制在知识治理中的有效性。
