# 上下文终局三方押注追踪

**开放问题**：上下文窗口四要素（[[上下文窗口四要素]]：系统提示词/工具定义/历史对话/参考文档）中，哪个是"浪淘沙"后最终留存、最值得长期投入的资产？Wiki 内三个路线已形成对立押注，本页长期追踪各团队后续文章的资源投入与验证证据（review-2b26eb97/9d0836be 立项——wiki 少有的可长期验证的预测性分歧）。

## 三方押注现状

| 押注方 | 核心资产 | 代表证据 | 当前态势 |
|---|---|---|---|
| **工具定义派** | 工具定义（名称/描述/JSON Schema）——[[工具定义最终论]] | [[function-calling大地基论]]：Skill 本质是 Tool、RAG/SubAgent/MCP 均 Tool 化，工具定义精度决定 Agent 上限 | 预测性（"可能会走到最后"），暂无验证数据 |
| **记忆/历史对话派** | 结构化记忆资产——小红书长记忆四件套、Hermes [[内外双驱记忆架构]]、ChatGPT 四层记忆 | [[用得越久越好用]]（Hermes）、[[记忆资产跨系统迁移]] | 产品化最快（Hermes 已有迁移工具） |
| **参考文档/知识库派** | 预结构化知识——[[知识库降熵论]]（有赞）、[[知识基座-天猫]] | 召回 85%/检索提速 1.5-3min 等自报数据 | 落地最久，量化声明已入追踪页 |

## 追踪判据

1. 各团队**新文章的资源投入比例**（篇幅/工程深度落在哪一要素）；
2. 是否出现**跨要素融合**的第三形态（如工具化记忆——Hermes 记忆已 MCP 服务化，实际上已开始越线）；
3. 有无团队给出**可核验的对照实验**（同任务下三类资产增益对比）。

## 已观察到的越线信号

- Hermes 记忆经外部记忆服务插件化（Mem0/Honcho 等）——记忆正在被**工具化**；
- 有赞 RAG 能力 MCP 服务化（[[RAG能力MCP服务化]]，觖弦篇）——知识库也在被**工具化**；
- 若"一切皆 Tool"成立，则工具定义派胜出的方式是**吞并**另两派，而非并行留存。
