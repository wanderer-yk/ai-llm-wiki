# skill 错误倒逼生成

**skill 错误倒逼生成**是本文对 Skill 来源的经验判断：Skill 不是提前规划出来的，而是被真实错误倒逼出来的。前期规范必然粗糙，AI 在执行中反复出错；团队在反复纠错中补充边界条件和反例，规范由此逐步长成。

## 固化信号

判断某条规则是否应写入 Skill 的信号是：**"这类问题每次都要纠正"**——同一种错误被人工纠正的频率越高，越说明它应该被固化为 Skill 规则。

## 迭代的价值

第六章经验总结确认：迭代过程本身就是价值——把团队踩过的坑沉淀成下次不会再踩的规则。Skill 因此成为一种组织级错误记忆载体，而非一次性配置。

## 关联

该机制支撑 [[skill稳定性决定论]]（方案稳定性最终由 Skill 规范质量决定），与 [[skill迭代闭环]]（ConardLi 来源的 Skill 改进循环）同域：两者都把 Skill 视为"错误 → 规则"的持续迭代产物，而非一次设计到位的静态资产。
