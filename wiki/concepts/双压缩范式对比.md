# 双压缩范式对比

双压缩范式对比是来源文章对 [[hermes-agent]] 内置的两套压缩系统的四维以上对照：**上下文实时压缩（Context Compressor）** 服务对话进行时，**离线 Agent 轨迹压缩（Trajectory Compressor）** 服务训练数据准备。二者压缩对象、时机、目标完全不同，不可混用。

## 对比表（原样保留）

| 维度 | 上下文实时压缩 (Context Compressor) | 离线Agent轨迹压缩 (Trajectory Compressor) |
|---|---|---|
| 运行时机 | 对话进行中 | 对话结束后 |
| 目的 | 保持对话可继续 | 准备高质量训练数据 |
| Token 目标 | 降到上下文窗口的50%以下 | 精确到 15250（固定值） |
| Token 计数 | 粗略估算（4字符≈1Token） | 通过 HuggingFace Tokenizer 精确计数 |
| 总结器 | 同模型或配置模型 | Gemini Flash（更轻量高效） |
| 保护策略 | 保留前10条 + 尾部动态 | 保留首轮系统/人类/助手/工具 + 最后4轮 |

## 关联

- 实时压缩的触发机制见 [[比例阈值压缩]]；离线压缩的三区算法见 [[轨迹头尾保护压缩]]。
- 在 [[上下文压缩策略]] 的压缩谱系中，二者共同构成“训练数据压缩”这一与“运行时压缩”正交的新范式分支，压缩器模型选择（同模型 vs 轻量专用模型）也是新出现的对比维度。
