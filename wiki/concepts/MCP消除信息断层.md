# MCP消除信息断层

MCP消除信息断层是 [[阳凯]] 得物技术实践中对 [[mcp]] 价值的定位：AI 编程失效的重要来源是 [[AI失效三模式|信息孤岛]]——接口文档在 API 平台、需求文档在飞书，模型默认无法触达；该项目以两个 MCP 分别消除两类断层，使 AI 无需人工复制粘贴即可获取权威信息，从信息供给层面收窄 AI 的能力边界缺口。

## 双接入实证

1. **接口文档直连 MCP**：累计调用 21 次，完成 39 个接口联调，支持同步生成 mock 数据；`interface.ts` 类型定义「无需人工校对」；与 SDD 组成联调路径——接口 URL → MCP 直连文档 → 一次获取字段/枚举/必填项 → 接口文件一次生成 → 零联调返工（案例二：6 个接口零返工）；
2. **飞书云文档直读 MCP**：AI 直接读取 [[飞书]] 中的 PRD/设计说明/技术文档，免复制粘贴。

## 现状与延伸计划

文末确认：「本项目 MCP 仅覆盖了接口文档、飞书文档」。纵向延伸计划：接入设计稿、测试用例、发布平台、日志平台——将 MCP 从「文档通道」扩展为覆盖研发全链路的信息供给层。

## 谱系与关联

- 是 [[上下文工程]] 统一命题在编码场景的实例：与有赞 [[结构化上下文组装]]（XML 分层组装）互补——前者解决「信息从哪来」，后者解决「信息怎么组装」；
- 与 [[AI能力边界三结构性特征]] 的「隐性行为无文档」共同说明：可文档化信息的 MCP 前置供给，是收窄 AI 边界的低成本手段。
