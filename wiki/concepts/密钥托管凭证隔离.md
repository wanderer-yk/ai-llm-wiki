# 密钥托管凭证隔离

密钥托管凭证隔离是 [[RDSHermes]] 的安全机制（厂商自述）：云凭证 AK/SK 不下发到客户端，而是由**网关代理鉴权**、加密托管——密钥不落盘、不暴露给 Agent 也不暴露给用户；Agent 的数据库操作经网关代为完成认证。对照：开源 [[hermes-agent]] 的做法是 AK/SK 写进环境变量或配置文件，密钥对 Agent 可见。文章给出该设计的逻辑："Agent 自我进化自由度越大，凭证隔离越不可少。"

## 设计逻辑

自进化 Agent 的自由度随经验积累而增长（能自主创建 Skill、自主执行更复杂操作），若凭证直接暴露给 Agent，自由度增长即攻击面增长；网关托管将"认证能力"与"凭证持有"解耦，使 Agent 能执行操作却无法窃取凭证。

## 边界说明

- 本文未展开网关架构与权限模型的技术细节。
- 开源版管不到的密钥安全正是 RDSHermes 产品化的切入点之一。
- 与 [[agent-control-plane]]（权限/边界/审计控制平面）、[[多层安全护栏]] 互补；与 [[团队治理写操作二次确认]] 共同构成 RDSHermes 的治理组合。
