# 五种常见控制模式

来源在 Agent Loop 与 Workflow/Agent 分界的讨论之后，归纳了构建 AI 系统的五种常见控制模式，并给出核心主张。

## 五种模式

1. **提示链 Prompt Chaining**：顺序步骤 + 代码检查点；适合生成后翻译、先大纲后正文等固定管线。
2. **路由 Routing**：输入分类定向；简单问题走轻量模型，成本与延迟可控。
3. **并行 Parallelization**：分段法拆子任务并发 + 投票法多次取共识；适合高风险决策或多视角任务。
4. **编排器-工作者 Orchestrator-Workers**：中央 LLM 动态分解并委派任务；[[nanobot]] 的 `spawn` 工具与 learn-claude-code 的子 Agent 模式均为此原型。
5. **评估器-优化器 Evaluator-Optimizer**：生成-反馈循环；适合翻译、创意写作等难以代码化质量标准的任务。

## 核心主张与使用方式

**多数 AI 系统是五种模式的组合，很多场景并不需要完整的 Agent 自主权。**

与 [[workflow与agent控制权分界]] 配合使用：先判断需要多少控制权，再从五种模式中组合。

## 与本 Wiki 既有概念的关联

- 模式 5 与 [[reflection模式]]（Reflexion/Self-Refine/CRITIC 学术脉络）同源，均以"生成→评估→改进"循环提升输出质量。
- 模式 4 与 [[plan-and-execute模式]]（先制定多步计划再逐步执行）在"分解-委派"环节相通，区别在于编排器模式由中央 LLM 动态决定拆分。
- 编排器-工作者模式是多 Agent 组织的基础形态；一旦扩展到多 Agent 协作，须同步引入 [[多agent幻觉放大链]] 的交叉验证打断机制，否则并行会放大错误。
- 五种模式为 [[workflow与agent控制权分界]] 提供了连续谱：多数模式偏 Workflow 侧的结构化控制，完整 Agent 自主权只是谱系一端。
