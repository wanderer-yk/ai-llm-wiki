# 软件竞争可调用性

「软件竞争可调用性」是 [[明径]] 在《浏览器自动化：从GUI到OpenCLI》结尾提出的行业判断：未来软件同时服务人与 Agent——GUI 给人用，API 是能力底座，而 Agent 偏好更清晰的执行面（命令、参数、返回值、失败原因）；软件竞争维度将从「界面」转向「可调用性」。

## 原文论述（原样引用）

> 未来的软件，不会只服务人，也会服务 Agent。
>
> 以前我们评价一个 SaaS，看的是界面顺不顺、按钮好不好点。但 Agent 不会欣赏你的按钮做得多圆。它只在乎一件事：能不能稳定调用你。
>
> GUI 是给人用的。API 是能力底座。而 Agent 最喜欢的，其实是更清晰的执行面：命令、参数、返回值、失败原因。
>
> 未来软件可能会多一个新竞争维度：不是谁页面更好看。而是谁更容易被 Agent 理解、调用、验证，再接进工作流。唯有如此，才更有机会成为下一代工作流里的基础节点。
>
> 过去的软件竞争界面，未来的软件竞争可调用性。

## 定位与证据强度

- 属**观点/趋势判断**而非实证结论；导语已声明「仅代表个人观点」，全文无量化数据支撑。
- 其工程化依据是 [[opencli]] 的实践：当 Agent 可以绕过 GUI 直取 API（[[api优先浏览器自动化]]）时，界面优劣不再是 Agent 侧的核心评价维度，「能不能稳定调用」才是。
- 可作为 SaaS/内部平台「Agent 就绪度」的评估视角：谁更容易被 Agent 理解、调用、验证并接入工作流，谁就更可能成为下一代工作流的基础节点。

## 与既有 Wiki 概念的关联

- 与 [[领域Agent即Source-of-Truth]] 呼应：被 Agent 信任调用的前提是成为可信的唯一信息/执行源。
- 与 [[workflow与agent控制权分界]] 呼应：清晰的执行面（命令/参数/返回值/失败原因）正是 Agent 可控性的前提。
- 与 [[agent生产落地环境重构论]] 互证：软件主动提供可调用面，本质是「环境改造先于能力提升」的供给侧版本——与其让 Agent 逆向破解 GUI，不如直接暴露稳定接口。
- 反面参照：[[cli录制回放生成]] 的读写断裂说明当前多数软件的「可调用性」仍需 Agent 侧工具补齐，供给侧原生可调用性尚未普及。
