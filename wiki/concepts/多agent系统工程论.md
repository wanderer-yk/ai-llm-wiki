# 多agent系统工程论

多agent系统工程论的核心论断：多 Agent 不是 prompt 工程，而是系统工程；其失败原因通常不是「智能不够」，而是无状态、无恢复、无结果回流。多个 Agent 能否落地取决于六个难点问题（原文「难点六问」，其中第三项在原文 overlap 截断处，按上下文推断为上下文隔离）：

1. 生命周期怎么管
2. 状态怎么观察
3. 上下文怎么隔离（截断处推断，参见 [[异步上下文隔离]]）
4. 结果怎么回流
5. 失败怎么恢复
6. 多条执行链怎么不串

统一任务抽象使多 Agent 不撕裂系统：执行体共享同一套生命周期、通知模型和回流协议，前后台差别降为调度与可见性差异（见 [[统一任务抽象先行]]、[[任务结果回流]]）。Claude Code 的成熟点在于先做最易忽略的工程问题——上下文隔离、结果回流、失败恢复、可观察性；做不好则 manager/worker 只是 demo。多 Agent 需要任务状态、通知、会话记录、上下文隔离底座，否则反噬系统复杂度。
