# 强依赖选型判据

**强依赖选型判据**是本文提出的 SubAgent / Agent Team / Skill 选型唯一依据：判断任务之间有没有强依赖。这一判据把三层架构从"技术清单"变成"决策规则"——不是按技术偏好选，而是按任务间依赖关系选。

## 判据表

| 任务关系 | 选型 | 本文对应位置 |
|---------|------|-------------|
| 有强依赖，需串行 | SubAgent | 转化阶段的串行步骤调度 |
| 无强依赖，可并行 | Agent Team | 提取阶段的并行分工 |
| 具体执行动作 | Skill | 所有具体任务的执行单元 |

## 质量维度的补充

正文在"提效心得"中为该判据补充了质量维度：**并行不只是效率问题**——专注分工本身提升单类任务处理质量，质量改善往往比缩短的时间更重要（见 [[并行质量收益论]]）。

## 与其他立场的对照

- 本文将 Agent Team 视为一线选项（用于结构化提取任务并行，且质量收益大于速度收益）。
- ConardLi 的 [[agent-teams最后选项论]] 主张 agent-teams 应作为最后选项；[[SubAgent与AgentTeams双模式]] 则主张双模式并存。
- 三方立场的逐维对比与"场景差异"解释假设见 [[agent-team选型判据三源对比]]。
