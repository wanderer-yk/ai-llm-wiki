# 场景严苛度分级

**场景严苛度分级**是天猫新品营销技术团队提出的 AI 生码场景适用性判定框架：按"严苛程度"将典型业务场景从"最为严苛"到"不严苛"分为五级，维度涵盖错误容忍程度、交互问题容忍程度、代码要求与视觉还原要求，[[sources/[202605081607]天猫新品团队AI编码实战指南下|来源]]。它回答的核心问题是"哪些需求可以放心交给 AI、哪些必须人深度介入"。

## 分级表（原文逐字保留）

| 严苛程度 | 典型场景 | 错误容忍程度 | 交互问题容忍程度 | 代码要求 | 视觉还原要求 |
|---|---|---|---|---|---|
| 最为严苛 | C 端频道 | 0 容忍 | 明显则 0 容忍 | 高 | 高 |
| 较为严苛 | B 端商家平台 | 0 容忍 | 特别明显则 0 容忍 | 中 | 中 |
| **交付分割线**（原文为跨 6 列的分隔行） | | | | | |
| 普通严苛 | 小二端工作台 | 0 容忍 | 影响主链路则 0 容忍 | 低 | 低 |
| 低严苛 | 研发自用工具与平台 | 一定程度容忍 | 没有 hack 绕过的方案则 0 容忍 | 无 | 无 |
| 不严苛 | 研发 DEMO | 能意会则能容忍 | 怎么都能容忍 | 无 | 无 |

> 原文以颜色编码标记要求强度：红（最高）、橙（中）、绿（低）、灰（无/最宽松）；完整语义规则原文未明示。

## 关键洞察

- 所有场景的错误容忍程度均为 0 或接近 0——分级差异主要体现在交互问题容忍、代码要求与视觉还原要求上，而非"允许出错"。
- [[交付分割线]] 将高要求外部交付区（C 端频道、B 端商家平台）与内部研发区（小二端工作台、研发自用工具与平台、研发 DEMO）切开；分割线以下即"需求驱动型"，人可以基本不介入代码（[[小二端AI主导对话生码]]）。
- 与 [[需求驱动型与工程主导型对比]] 的需求二分互为表里：严苛度是场景属性，需求类型是该属性在流程上的映射。
