# Rules四类分层调度

[[柚漫剧团队]] 的 Rules 体系（4.3.1）：覆盖 **25 个规则文件**，按职责分四类，通过入口调度文件 `start.mdr` 统一管理，按**"先读基础规则 → 按场景匹配专项规则 → 再执行生成"**三步流程强制加载。规则的对象是团队的**自研跨端框架**（公开训练数据与互联网资料中几乎零信息，不额外处理则 AI 生成代码基本不可用）。

## 四类规则（verbatim 表）

| 类别 | 加载策略 | 覆盖内容 |
|------|----------|----------|
| 基础规则（必读） | 任何代码生成前都会加载 | 项目结构、San 组件语法、样式属性白名单、常见布局最佳实践 |
| 组件 & 能力专项规则（按需加载） | 按场景匹配 | 6 个内置组件（img / list / swiper / video / pagview / refresh）+ 3 类能力（BOM-DOM-路由 / 端能力调用 / CSS 动画）；每条规则包含属性表、事件表、注意事项和正反示例 |
| 工程专项规则 | 非编码环节对齐 | 项目配置、CLI 创建、单元测试（vitest）、AI Code Review 评审标准 |
| 迁移规则 | 存量项目渐进式迁移 | 完整迁移链路（项目结构 / API 替换 / 组件标签 / 样式转换 / 目录优化） |

## 要点

- 自研跨端框架官方名称未披露，基础规则含"San 组件语法"，暗示基于百度开源 San 体系；25 个文件在四类中的数量分布未给出。
- 迭代三阶段：纠错经验 → 核心概念/生命周期/状态管理 → 完整体系（见 [[痛点倒逼基建]]）。
- Rules 教 AI"认识我们的工程"，与 Skills 的分工见 [[知识到流程跃迁]]；与 Claude Code 中 rules 注入机制的对比可参照 [[rules被动注入机制]]、[[rules与skills等价论]]。
