# LightRAG 三函数索引构建

[[lightrag|LightRAG]] 论文（arXiv:2410.05779）将图增强检索的索引构建形式化为三个函数：R(·) 实体关系抽取、P(·) 键值对生成、D(·) 去重与合并。跨端技术团队按原文口径转述如下：

```
R(·) —— 实体与关系抽取：LLM 识别实体（节点）与关系（边）；
        简化：不追求精细实体类型分类，注重抽取效率和覆盖面
P(·) —— 键值对生成：对每个实体节点/关系边生成 (Key, Value) 文本对；
        Key = 便于检索的短语/关键词（实体用名称；关系由 LLM 增强生成多个全局性主题关键词）
        Value = 总结性文本，聚合该实体/关系在原始文档中的所有相关描述
D(·) —— 去重与合并：识别不同文档段落的相同实体/关系并合并为同一节点/边；
        压缩图规模 + 使增量更新天然可行（匹配即合并，无需重建全图）
```

## 键值对替代社区摘要（P(·) 关键创新）

不做社区聚类即实现信息聚合与压缩：
- **Key**：实体用名称；关系由 LLM 增强生成多个全局性主题关键词（这一双轨设计直接支撑了 [[lightrag双层检索范式]] 的低级/高级两层查询）；
- **Value**：总结性文本，聚合该实体/关系在原始文档中的全部相关描述。

## 设计取舍与效果

- **R(·) 简化**：不追求精细实体类型分类，重效率与覆盖面——实体抽取质量直接决定后续图谱质量（[[gigo原则]] 式主张）。
- **D(·) 增量可行性**：匹配即合并、无需重建全图，与 GraphRAG"新文档→社区边界重划→全部摘要重生成"的全局重算形成对照；三步局部增量（R→D→P）实测耗时与 API 调用远小于全量重建。
- **实测**：同批 44 篇文档，索引构建快"数倍"（省社区发现+摘要开销），API/token 大幅减少。
