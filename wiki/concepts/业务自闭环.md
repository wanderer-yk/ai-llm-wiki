# 业务自闭环

业务自闭环是 [[沈询]] 在 AI Agent 系列第二篇（2026-02-25）中对 Agent 修改维护模式的概括：Agent 使"发现 → 测试 → 解决"在业务侧形成闭环，将原本需要多角色协作、耗时数天到数周的修改维护流程，压缩为由业务侧自主完成。

## 三种模式的维护成本对比（原文照录）

- **传统编程**：多角色瀑布协作——运营发现问题 -> 产品拆解排期 -> 研发 -> 部署 -> 测试 -> 上线
- **Workflow 工作流**：基本只能节省部署环节——运营发现问题 -> 产品拆解排期 -> 研发 -> 测试 -> 上线
- **Agent**：业务自闭环——(发现->测试->解决）

## 量化声明（存疑）

原文称"Agent 可以实现业务自闭环，从发现问题到解决问题只需要几分钟"。该声明与 Lynxe"解决 80% 以上个人问题"同属自报、无度量口径的量化声明，已按 [[ai工程量化效果声明追踪]] 的口径登记存疑；生产环境实证尚缺，相关开放问题记录于 [[queries/workflow与agent范式之争如何按场景裁决]]。

## 与既有概念的区别

与 [[反馈回灌闭环]]（问诊 Agent 场景）含义不同，不可混用：
- **反馈回灌闭环**：描述"评分 Agent → 坏样本聚焦 → 反馈回灌知识体系"的知识迭代机制，属于评测优化链路
- **业务自闭环**：描述业务需求修改维护链路从多角色瀑布协作到业务侧自主完成的形态变化，属于研发/维护协作链路
