# 一切都是函数（函数第一公民）

"一切都是函数，函数才是第一公民"是[[沈询]]为其 Func-Agent 框架 [[lynxe|Lynxe]] 提出的设计哲学：每个 Agent 能力都以函数形式暴露、接受结构化参数输入，使 Agent 得以超越对话框形态集成进既有系统。该哲学是文章在论证 [[mcp与skills竞争关系论]] 之后的收尾性回答——在 MCP（协议接驳）与 Skills（文字化流程）之外给出的第三条路线。

## 四项函数化能力

1. 接受结构化的参数输入，而不是依赖纯文本描述
2. 返回结构化结果，方便与现有系统集成
3. 支持多种调用方式（不限聊天界面）
4. 与现有业务逻辑、表单、API 无缝对接

## 双优势论证

函数化方式"既保留了 Agent 处理不确定性的核心优势，又解决了结构化输入输出和系统集成的问题"（定性主张，无量化口径）——即函数化在保留模型动态调整灵活性的同时，补齐了与既有系统对接所需的确定性结构。

## 文内"问题→解法"闭环

能力清单的第②③④项（返回结构化结果 / 多种调用方式不限聊天 / 与业务逻辑·表单·API 无缝对接）逐条正面回应 [[skills两大未解问题]] 之第②项——Agent 只能聊天式接驳、无法融入多步骤表单/实时数据展示/UI 组件交互场景。Func-Agent 在文内被明确定位为 Skills 缺陷的解法。

## 跨源关联

- 与 [[结构化输出]]（基于 Function Calling 的结构化输出机制）、[[function-calling大地基论]] 相互印证：三者都把结构化 I/O 视为 Agent 工程化的地基
- 与腾讯 [[三大武器库]] 的 Skills 层定位形成对照：Skills 在腾讯框架中是掌握层能力封装，在沈询框架中被函数化能力部分取代——见 [[skills与mcp是互补还是竞争]]
