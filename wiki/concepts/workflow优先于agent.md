# Workflow 优先于 Agent

有赞共享技术团队在 AI 客服场景中提出的架构决策原则：优先选择确定性 Workflow 而非自主 Agent，追求结果可控。

## 核心论点

客服场景的特殊性决定了架构选择：
- **确定性优先**：客服回答直接影响用户体验，错误回答的代价极高
- **可控结果**：Workflow 的每一步输出可预测、可审计
- **"宁可不答，不能答错"**：与 [[意图识别保守策略]] 一脉相承

## 与 Agent 的关系

这一原则并非否定 Agent 的价值，而是明确的**分阶段策略**：
- **当前阶段**：Workflow 为主，确保核心客服链路的稳定可靠
- **未来规划**：从 Workflow 向更具自主性的 Agent 能力演进

这种渐进式思路与 [[三阶段平台演进路线]] 在哲学上一致——先建立确定性基础，再逐步引入灵活性。

## 与沈询"Agent 新范式"主张的跨源张力

千问AI平台沈询在 AI Agent 系列第二篇（2026-02-25）中提出 [[编程与工作流同源替代论]]：Workflow 与传统编程同源（本质都是程序控制的流程流转），代码方案已凭复用性和扩展性在无 AI 时代胜出，Workflow 只是编程的低代码形态；并主张 Agent 决策权下放，是"更有机会的新范式"。这与本页"客服场景优先确定性 Workflow"形成场景差异下的路线张力——但并非严格矛盾：

- 场景不同：准确性敏感的客服系统（有赞）vs 追求体验差异化的通用创新产品（沈询）
- **部分收敛**：沈询同文末尾的 [[ai增强与agent体验二分选型]] 边界明确"既有系统增强 AI 能力用代码 + toolcall，准确性有保障"——与有赞确定性优先立场实质收敛：双方都在准确性敏感场景放弃全自主 Agent
