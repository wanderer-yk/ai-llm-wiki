# 迭代型需求git版本管理策略

迭代型需求 git 版本管理策略是天猫新品营销技术团队对复杂迭代场景的核心工程对策：及时用 git 存档，使任何一版"符合需求的代码"都可回退。原文口径为「多方案对比用分支 / 版本管理用 commit」，直接解决迭代型需求四大常见问题中的"版本回退缺失"与"方案覆盖丢失"两类。

## 原文策略

「对于复杂迭代，最好及时通过 git 进行版本管理，因为符合需求的代码可能在前几个小时，甚至前一天的某个版本（多方案对比用分支 / 版本管理用 commit）」。

## 对应的问题目录（原文表格，逐字保留）

| 场景 | 发生了什么 | 后果 |
|------|-----------|------|
| 改一个功能，坏了另一个 | 添加删除功能时，不小心影响了添加功能 | 花时间排查，可能越改越乱 |
| 想回到"昨天那个版本" | 昨天的代码能用，今天改了一堆，全坏了 | 找不到昨天的版本 |
| 试了三种方案，想回到第一种 | 第一种方案其实最好，但已经被覆盖了 | 要么重写，要么将就 |
| AI 改了不该改的地方 | 让 AI 改一个文件，它顺手改了其他文件 | 不知道哪些被改了 |

其中策略③直接消解第 2、3 行痛点；第 1 行由[[仓库解耦决定迭代成功率论]]对应，第 4 行由 AI 目标漂移约束对应。

## 跨来源对照

该策略为 AI 生码补齐了代码世界天然具备的可回滚能力，与 vivo 提炼的[[coding-agent四特征]]（可回滚）、Amazon 的[[agent-canvas沙盘机制]]（类 git 版本管理特征）形成同构互证；与[[原子化变更原则]]（小步提交）在颗粒度上互补。微调场景下的轻量版对策见[[分支控制]]。
