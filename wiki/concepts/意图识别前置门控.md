# 意图识别前置门控

意图识别前置门控是[[aiagentdemo]]项目 AgentCore 的编排设计：在每次对话进入 RAG 流水线**之前**，先用 LLM 判别意图枚举 `Intent.RAG / Intent.GENERAL`，**仅当判定为知识问答（RAG）时才触发检索**。其收益由正文明确声明：「避免每次对话都触发 RAG 检索，节省不必要的向量检索和 Rerank 开销」。

## 在五段编排中的位置

AgentCore 五段编排：**意图识别 → RAG 注入 → 记忆管理 → 模型调用 → 工具执行**——意图识别是第一道门，决定第二段（RAG 注入）是否执行。注入时使用自然语言模板拼接：「以下是从知识库中检索到的相关参考资料，请结合这些资料回答用户的问题：…」（与有赞 XML 分层的 [[结构化上下文组装]] 构成自然语言模板 vs 结构化标签的对照）。

## 与既有概念的关系

- **与 [[意图规划]] 的对照**：马上消费的意图规划是「Query改写→意图识别→意图挖掘」的企业级三段框架，意图识别服务于路由到正确知识源与 Agent；本文的意图识别目标更单一——二值门控（检索/不检索），是最简形态的意图前置；
- **与 [[意图识别保守策略]] 的对照**：有赞「宁可让 AI 不回答，也不能让它答错」的保守策略约束的是回答阈值；本文门控约束的是检索成本，两者都体现「不确定时降级到低成本路径」的思想，但误判代价不同（漏检索 vs 错回答）；
- **与 [[RAG工具化双路径]] 的互补**：意图门控是「系统主动注入」路径的开关；封装为 `knowledge_search` 工具的「LLM 主动检索」路径不经过此门控，两条路径并存。

## 待核

IntentRecognizer 的 LLM prompt 设计、误判兜底（识别错意图时 RAG 检索被跳过的代价）与准确率未披露。
