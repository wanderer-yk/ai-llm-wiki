# 长期记忆 Record/Retrieve 双向机制

长期记忆 Record/Retrieve 双向机制是长期记忆系统的核心运作模型：Record（写入）侧用 LLM 从会话消息中语义抽取"事实/偏好/经验"，Retrieve（检索）侧按当前查询取出相关信息注入短期记忆。两条流水线构成双向闭环，出自《AI Agent 记忆系统》（柳遵飞（翼严））。

## Record 流水线（写入）

```text
LLM 事实提取 → 信息向量化 → 向量存储 →（复杂关系存储）→ SQLite 操作日志
```

- 起点：会话消息中的语义信息（事实/偏好/经验）；
- 复杂关系存储走图数据库（GraphStore）；
- 终点：SQLite 记录所有记忆操作的审计日志，支持版本回溯。

## Retrieve 流水线（检索）

```text
User query 向量化 → 向量数据库语义检索 → 图数据库关系补充 →（Reranker-LLM）→ 结果返回
```

- 向量检索提供语义召回，图数据库补充实体-关系；
- Reranker-LLM 对初步结果按语义相关性重排后返回，注入当前短期记忆。

## 第三方组件化背景

由于长期记忆内部流程复杂（信息提取、向量化、存储、检索），长期记忆通常实现为**独立组件经 API 集成**。源文列出的生态：[[mem0]]、Zep、Memos、[[reme]]。

## 与 RAG 的关系

Mem0 类长期记忆系统与 RAG 技术架构相似（向量化存储、相似性检索、注入上下文生成三点），但功能与场景有明显区别（差异细节在源文图片中，未提取）。可对照 [[向量检索rag]]、[[rag技术瓶颈]]。
