# 评测集生成（Testset Generation for RAG）

评测集生成（Testset Generation for RAG）是 Ragas（[[ragas]]）提供的测试集自动生成能力，也是《RAG 全链路技术详解》七环节契约的最后一环。动机：「在实际开发中，开发者往往缺乏高质量的‘问题’数据集。Ragas 提供了一个强大的工具，可以自动生成测试集。」

## 完整机制链

1. **动机**：缺乏高质量「问题」数据集；
2. **查询类型分类**：单跳/多跳 × 具体/抽象的 2×2 矩阵（[[ragas查询类型分类]]），全部生成基于知识库文档块；
3. **知识图谱构建**：多跳问题生成需知道 chunk 间关系，Ragas 内部执行 Document Splitter → Extractors → Relationship builder 管线（[[ragas知识图谱构建]]）；
4. **场景生成**：以节点×查询长度×查询风格×人设四参数构造覆盖真实用户分布的问题（[[场景生成]]）；
5. **Query Synthesizer 实操**：内置或自定义（继承 `ragas.testset.synthesizers.base_query.QuerySynthesizer`，实现 `_generate_scenarios` 与 `_generate_sample`）；
6. **reference 生成**：`_generate_sample` 内 LLM 同时产出问题＋标准答案＋reference contexts，输出 `SingleTurnSample(user_input, reference_contexs, reference)`（[[场景采样两阶段解耦]]）。

## 自举链张力（关键方法论问题）

该机制构成「自动建边→自动出题→自动出答案→自动评测」的**全自动闭环**：

- 与 [[评测agent乐观偏差]] 的张力加深：评估者（LLM）同时是被测系统的同类模型，且参考答案本身由 LLM 生成，双重自举削弱评测的独立基准地位；
- 与 [[评测集优先于知识库]]（小红书 PMO「评测集是 Agent 的单元测试」）定位共振：都强调评测集是系统性质量保障的先决资产，但小红书的评测集隐含人工锚定，Ragas 走全自动路线；
- Ragas「接近人工评测」声明无实验口径，与上述张力一并纳入 [[ai工程量化效果声明追踪]]。

## 文中缺失项

单跳/多跳类型分布配比、生成后是否需人工审核环节，源文确认未出现——这是全自动路线留给使用者的显式决策点。与 [[agent评测四要素]] 的数据集要素对接方式待整合。
