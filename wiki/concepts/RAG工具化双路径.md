# RAG 工具化双路径

RAG 工具化双路径是[[aiagentdemo]]项目中知识检索能力同时存在的两条触发路径：

1. **主动注入路径**：AgentCore 五段编排中，经 [[意图识别前置门控]] 判定为 RAG 意图后，系统在模型调用前主动完成「多路召回 + [[RRF排名融合算法]] + Rerank」并将结果以模板注入上下文（「以下是从知识库中检索到的相关参考资料…」，对照有赞 [[结构化上下文组装]] 的 XML 分层）；
2. **主动检索路径**：RAG 能力同时封装为 `knowledge_search` 工具，LLM 可在对话中依需求自主决定调用检索。

## 双路径的设计逻辑

- 注入路径**省 LLM 决策成本**、延迟确定，但依赖意图识别的准确性；
- 工具路径**给 LLM 主动权**——LLM 可在任意轮次按需检索、多次检索，但每次都消耗一次工具调用循环；
- 两条路径并存意味着系统在「确定性流程」与「LLM 自主性」之间不做单选，而以意图门控控制注入路径的成本、以工具化保留自主检索的兜底。

## 与 workflow/agent 控制权讨论的关系

双路径是 [[workflow优先于agent]]（有赞）与 [[workflow与agent控制权分界]] 讨论在单项目内的微观实现：注入路径偏 Workflow（确定性流程），工具路径偏 Agent（LLM 决策）。与 [[意图规划]]（马上消费）的对照：意图规划将意图识别扩展为「Query改写→意图识别→意图挖掘」的路由框架，本文则将其简化为二值门控并辅以工具化兜底——复杂度预算不同的两种解法。检索能力经 [[RAG能力MCP服务化]] 对外暴露后，第三条「外部应用触发」路径亦成为可能。
