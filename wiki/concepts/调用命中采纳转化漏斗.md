# “调用→命中→采纳”转化漏斗

“调用→命中→采纳”转化漏斗是天猫链路指标的量化骨架：用三级漏斗衡量“费心准备的上下文（知识库、组件文档、SPEC 规范）在 AI 生成代码的过程中有没有按预期起到正向作用”，并支持逐级诊断定位问题环节。价值定位：让知识库管理“从「有没有用」进化到「哪条好用、哪条该淘汰」”。

## 逐级诊断映射（完整）

| 漏斗层级 | 异常信号 | 诊断结论 |
|---------|---------|---------|
| 调用率低 | 调用少 | Prompt 引导问题（Agent 不知道要查资料） |
| 命中率低 | 查不到 | 知识库内容覆盖不足，或者索引质量差 |
| 采纳率低 | 查到了但不用 | 查到了但不是 Agent 需要的，召回精度有问题 |

## 链路诊断双规则

- 知识库被频繁调用但代码采纳率低 → 知识库内容可能有问题的；
- Agent 不查知识库就写代码 → Prompt 引导有问题。

## 单条知识采纳追踪不可行论

放弃追踪单条知识“采纳”的三大工程难题：

1. 知识库返回“软内容”，Agent 不显式标注引用；
2. 强制标注影响自然输出；
3. 无对照组做 A/B 测试。

替代方案：**会话级关联分析**——分析使用了某条知识的会话整体采纳率表现，规避软内容标注难题；散点图数据即关联分析产物。

## 周度运营实践

每周拉取各能力三级漏斗数据，重点关注两类异常：①调用率低（检查 System Prompt 工具使用引导是否清晰，或触发条件是否过于苛刻）；②命中率高但采纳率低（用 [[命中采纳四象限分析]] 定位具体知识条目，优先优化“高频低效”象限）。零结果查询 Top 20 列表作为知识库扩展的直接输入。
