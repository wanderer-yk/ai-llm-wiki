# 反馈循环护栏

反馈循环护栏是技巧 5 提出的质量机制："反馈循环是 Ralph 的护栏"——类型检查、测试、Linter 等自动验证构成循环内的质量门禁；没有护栏时，Ralph 会产出"看起来正确但实际上有问题"的代码。

## 提示词模板（原文）

```markdown
在每次迭代中：
1. 实现功能
2. 运行类型检查：`tsc --noEmit`
3. 运行测试：`npm test`
4. 运行 Linter：`npm run lint`
5. 只有在所有检查通过后才提交
```

核心约束：**所有检查通过后才提交**——"确保 Ralph 不会提交破坏性代码"。

## 在循环中的地位

反馈循环同时承担三重职能：
1. **质量门禁**：提交前的硬性检查
2. **循环退出依据**：全绿是 [[机器可验证完成条件]] 的主要来源
3. **标准执行器**：强制执行 [[代码库模式大于指令]] 场景下的显式质量标准
