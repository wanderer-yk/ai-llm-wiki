# 问诊 Agent 四层架构

问诊 Agent 四层架构是交易领域问诊 Agent（[[问诊小助手]]）的总体系统架构，将“可沉淀、可复用、可评估、易迭代”的建设理念落为四个职责明确的层。其独特之处在于把**运营评估层（Ops & Eval）作为一等公民**纳入架构，而非事后补充——这是 [[q-score质量评分机制]] 与 [[反馈回灌闭环]] 得以运转的结构前提。

## 四层职责（原文表格逐字保留）

| 层 | 职责/组件 |
|---|---|
| 接入层（Channels） | 工单、舆情平台、IM 群、合作方咨询入口。特别注意输入冗余与多模态内容（如图片、视频）的预处理，以节约 token 成本。 |
| 编排层（Orchestration） | 意图识别（解释型 / 诊断型）、路由至对应 Agent。 |
| 实现层（Agent） | 包含 LLM、RAG、排查技能文档、公共知识库、上下文组装、工具调用策略等实际执行组件。 |
| 运营评估层（Ops & Eval） | 问答管理、跟进项跟踪、质量评分、报表监控、反馈闭环。 |

## 要点

- 编排层的分流依据来自 [[两类能力形态抽象]]（解释型/诊断型）。
- 实现层中“排查技能文档”与“公共知识库”的分离，即 [[双层召回知识体系]] 的结构基础。
- 运营评估层承接质量评分、报表监控与反馈闭环，使系统成为“越用越聪明的活体”。
