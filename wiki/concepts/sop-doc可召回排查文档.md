# SOP Doc（可召回的排查文档）

SOP Doc（可召回的排查文档）是《让问题不过夜》一文的**核心新范式**，也是全文正式定名“运维友好型问诊Agent构建范式及运营体系”的骨架：以**场景排查文档为最小能力单元**，通过 RAG 精准召回 + 动态注入上下文 + 按手册执行 + 工具调用自主纠错，让 Agent 的能力扩展从“改代码/调提示词/重新编排”变为“写文档”。作者称该范式与主流 Skills 架构理念相通——按需加载、技能固化，提升可控性与稳定性。

## 三大核心思想

1. **文档即技能闭包**：文档对排查所需的字段、枚举、日志、步骤做强约束封装，减少幻觉与自由发挥；
2. **新增能力 = 新增文档**：能力扩展与代码/编排解耦；
3. **维护对象下沉**：从改代码/调 prompt 变为编写维护排查手册，贴近一线同学。

## 排查文档模板（基础四段式，原文逐字）

```bash
# 适用范围
  简单描述适用场景 并给出指令使用示例
# 字段说明（可选）
给出场景依赖字段的说明 如pjyl 字段为1 表示权益已发放
# 核心日志格式（可选）
针对核心日志做些说明 避免模型胡诌
# 排查思路
  描述具体的排查步骤 期间使用工具时，给出使用的参数提示
```

完整生产级示例（评价有礼问题诊断文档）实际包含五部分：适用范围 / 字段说明表（含 `pjyl` 唯一标准）/ 枚举类（RateGiftReasonEnum，22 种未发放原因）/ 常见日志详解（7 条）/ 排查步骤（按用户ID/订单ID 分流、严格顺序、含转人工终止条件）。全文见 [[sources/[202603040830]让问题不过夜交易领域问诊Agent实践]]。

## 执行侧与知识侧配套

- 执行侧：[[手册执行者模式]]——主 Agent 被约束为“手册执行者”，禁止跳步/改序/加步；
- 知识侧：[[双层召回知识体系]]——公共知识库 + 场景技能文档双层召回。
