# 两阶段迁移流程

**两阶段迁移流程**是本文为 [[网盘]] 存量代码转 [[KMP]] 设计的执行编排：提取阶段用 Agent Team 四路并行，转化阶段用 SubAgent 串行推进并以 Memory 传递关键产出，每个执行节点由 Skill 保证输出稳定。流程结构直接由 [[强依赖选型判据]] 推导而来。

## 提取阶段：Agent Team 四路并行

四类提取文件——UI 组件、布局文件、业务逻辑、资源文件——逻辑完全不同但无强依赖，拆给四个专业 Teammate 同时提取。跨类型依赖（如动态 Dialog → 布局文件、API 字符串引用 → 资源文件）由 Mailbox 消息通道实时协调（[[mailbox消息通道]]）。

## 转化阶段：SubAgent 串行 + Memory 传递

串行顺序：**模块生成 → 资源转化 → 业务代码迁移 → UI 转化**。步骤间存在强依赖，通过 Agent-Memory 传递关键产出（[[agent-memory结构化提炼]]）：例如资源转化 SubAgent 写入资源 ID 映射表，UI 转化 SubAgent 读取后准确处理引用。

## Skill 兜底

每个执行节点由 Skill 保证输出稳定；提取阶段使用 extractor → validator → fixer 三 Skill 链，转化阶段复用为 converter → validator → fixer，证明拆分逻辑通用（[[提取校验修复三skill拆分]]）。
