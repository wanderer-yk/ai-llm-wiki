# 四类上下文效果追踪框架

四类上下文效果追踪框架是天猫链路指标章对四类上下文供给的差异化效果追踪方案：SPEC 需求规格、经验沉淀知识库、物料组件知识库、Skills 工作流各有专属关注问题与追踪指标。它与 [[知识资产治理革命]] 中的软资产三重转化互为表里——度量对象正是文档、SPEC、Prompt（工作流）三类软资产。

## 四视角总览

| 视角 | 关注问题 |
|---|---|
| SPEC 需求规格 | 需求描述是否清晰 |
| 经验沉淀知识库 | 踩坑经验是否被复用 |
| 物料组件知识库 | 组件用法是否查到 |
| Skills 工作流 | 最佳实践是否被触发 |

## 一、SPEC 模板追踪

SPEC（技术规格说明）为预置技术方案模板，按需求类型四分类：

| 模板类型 | 适用需求 |
|---------|---------|
| 列表页模板 | 标准 CRUD 列表 |
| 表单模板 | 配置编辑页 |
| 多场景模板 | 复杂业务流程 |
| 基础模板 | 通用简单页面 |

追踪方法为**采纳率反推模板质量**：高频高效模板（多场景模板）作标杆推广，高频低效模板针对性优化。基础模板案例：原仅含简单功能描述框架、采纳率偏低，AI 常遗漏接口字段映射与状态管理逻辑；补充“数据流转说明”“状态变更规则”两个必填项后采纳率显著提升——结论是**结构化约束越强，AI 输出质量越稳定**（与 [[结构化上下文组装]]、[[执行语义冻结]]、[[规格驱动ai开发]] 同族）。

## 二、经验沉淀知识库

存储模型无法从公开资料获取的业务独特知识，三分类：

| 内容类型 | 定义 | 文中示例 |
|---------|------|---------|
| 踩坑记录 | 具体的问题和解决方案 | tsconfig 配置问题、接口兼容性问题 |
| 编码规范 | 团队约定的代码风格和模式 | 状态管理方式、错误处理规范 |
| 业务规则 | 领域特定的逻辑约束 | 价格计算规则、权限校验逻辑 |

追踪方法为**关联分析**（命中某条知识后该会话的代码采纳率）+ 散点图定位。知识质量核心维度是**可操作性**——AI 看了能直接用，而非“知道有这回事但不知道怎么做”。tsconfig 案例：召回率高但采纳率偏低，原文只说“配置 baseUrl 可简化导入”未说明具体配置方式，补充 paths 映射规则和示例代码后采纳率显著提升。**零结果查询**是知识库缺口的直接信号：每周汇总 Top 20，按“出现频次 × 业务影响”排序，作为知识补充输入。

## 三、物料组件知识库

通过 [[mcp]] 工具提供三类能力：

| 能力 | 说明 |
|------|------|
| 组件查询 | 按名称或功能描述检索组件 |
| API 文档 | 组件的 Props、事件、插槽说明 |
| 使用示例 | 典型场景的代码片段 |

使用率低需**二分诊断**：

| 情形 | 诊断 | 干预 |
|------|------|------|
| Agent 没调用 MCP | Prompt 工具引导不足 | 检查 System Prompt 工具使用引导；离线评测加“必须查询组件文档”行为分要求 |
| 调用了但命中率低 | 组件命名与 Agent 理解不一致或文档覆盖不足 | 检查命名一致性（`DatePicker` vs `Calendar`）；补充文档 |

当前文档缺口在业务组件和近期新增组件；团队定期扫描“调用了 MCP 但返回空结果”的查询日志，作为文档补充优先级输入。

## 四、Skills 工作流

| 指标 | 含义 | 低值诊断 | 状态 |
|------|------|----------|------|
| 使用率 | Agent 是否触发 Skills | — | 当前追踪 |
| 采纳率 | Skills 会话代码采纳率 | — | 当前追踪（明显高于普通会话） |
| 触发率 | 符合条件场景中是否被触发 | 场景识别不足 | 下一版本计划 |
| 完成率 | 触发后是否成功完成 | 工作流设计问题 | 下一版本计划 |

**专家经验固化论**：Skills 本质是把“专家经验”固化成可复用流程，标准化工作流确实提升生成质量。与腾讯 [[生产级skill]]、有赞 [[知识复利效应]] 的经验沉淀思路同族。

## 开放问题

- tsconfig 案例与 Skills 对比均无具体数值（“显著提升”“明显高于”）；零结果查询“业务影响”的量化方法未说明；物料组件 MCP 工具接口签名与 Skills 清单未披露；触发率/完成率埋点方案（下一版本）待观察。
