# 编程与工作流同源替代论

编程与工作流同源替代论是 [[沈询]] 在 AI Agent 系列第二篇（2026-02-25）中提出的历史性论断：Workflow 与传统编程本质都是"程序控制的流程流转"，二者是相互替代关系，在没有 AI 的时代就已经充分竞争过，且代码方案已经胜出。这是本文最具辨识度的观点，为"Workflow vs Agent"行业争论提供了历史视角。

## 论断内容

1. **同源性**：Workflow 与传统编程的核心变化都仅在于"在固化的流程中适当地增加 AI 的能力"，除此外其他部分类似，本质都是程序控制的流程流转
2. **替代关系**：二者在无 AI 时代已充分竞争过，不是并行的两条独立路线
3. **竞争结果**：写代码的方案因为其优秀的**复用性和扩展性**成为了更主流的选择
4. **推论**：Agent 不是对传统编程的简单替代或升级——Agent 的决策权完全下放给 Agent 和 Prompt，能够解决原有写程序不能解决的问题（处理不确定性、动态调整策略、理解自然语言意图），是决策权下放后的新范式（见 [[决策权三分法]]）

## 对"Workflow vs Agent"争论的分析价值

该论断暗示 Workflow 不是介于编程与 Agent 之间的第三条独立技术路线，而是编程的低代码形态；其理论上的胜出条件（复用性、扩展性）已被代码满足，因此 Workflow 与 Agent 之争在逻辑上不是"新旧迭代"关系，而是决策权是否下放的范式之别。

## 与有赞立场的跨源张力

与 [[workflow优先于agent]]（有赞 AI 客服，2026-01）形成跨源张力：有赞主张客服场景优先确定性 Workflow 以保结果可控（"宁可让 AI 不回答，也不能让它答错"）；沈询则将 Workflow 定性为与编程同源的旧范式，主张 Agent 是未来。两者并非严格矛盾——场景不同（准确性敏感的客服 vs 追求体验差异化的通用产品），且沈询在同文末尾承认既有系统增强用"代码 + toolcall"最优（见 [[ai增强与agent体验二分选型]]），这一点反而与有赞立场部分收敛。该分歧的裁决线索集中记录于 [[queries/workflow与agent范式之争如何按场景裁决]]，留待 synthesis 裁决。

## 证据强度

属观点性历史论断，原文未附数据佐证；"Agent 是更有机会的新范式"为作者前瞻判断而非被证实事实。全文亦存在内部张力：高调主张 Agent 新范式的同时，末尾给出保守的适用边界。
