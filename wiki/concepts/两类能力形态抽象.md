# 两类能力形态抽象

两类能力形态抽象是 [[顺乾]] 在交易领域问诊 Agent 实践中提出的核心框架：将研发支持问题收敛为**解释型**与**诊断型**两种 Agent 构建范式。其价值在于：不同形态对应不同的工程定义与核心模式，抽象之后 Agent 输出可统一为[[问诊agent结构化输出五要素|五要素结构]]，为评估、运营、迭代奠基；目标是“稳定替代工程师完成标准化支持流程”而非仅仅“回答问题”。

## 解释型（业务答疑）

- **输入**：现象/疑问；**输出**：规则口径说明 + 查证路径 + 结论边界。
- **核心模式**：意图理解 → 知识库召回 → 模型综合 → 结构化解答。
- 相对成熟，非文章重点。

## 诊断型（问题诊断）

- **输入**：带具体 ID 的异常事实；**输出**：证据链 + 定位步骤 + 可执行动作。
- **核心模式**：意图分析 → 按 SOP 调用工具排查 → 综合结论 → 操作建议。
- 需要决策能力与外部系统协同，是文章的主战场。交易域典型根因谱系：链路异常、依赖超时、补偿未触发、消息堆积、状态机阻塞、数据一致性问题。

## 设计含义

抽象直接支撑了 [[问诊agent四层架构]] 中编排层的意图识别与路由（解释型/诊断型分流），也决定了诊断型场景必须走向 [[sop-doc可召回排查文档]] 范式（按手册执行、强约束、可评估）。
