# 并行质量收益论

**并行质量收益论**是本文对 Agent Team 并行价值的重估：并行最初是为了提速，但实际运行中，**专注分工对单类任务质量的提升比速度收益更明显**。正文在"提效心得"中将"并行不只是效率问题"列为独立心得，并在第六章经验总结中再次确认"并行的收益不只在速度上"。

## 机制：专业 Teammate 分工准确率

一个 Teammate 只盯一类文件，会对该类型的依赖模式建立更强识别。文中的具体证据：专注布局的 Teammate 对 include 嵌套引用的识别比通用 Agent 准确很多——专注度带来的模式识别优势是通用 Agent 无法通过更长上下文弥补的。

## 耗时声明（定性）

相比串行，并行总耗时接近四类任务里最慢的那条路径，而非四段累加。这是定性声明，全文无量化提效百分比。

## 立场意义

该论断强化了 [[强依赖选型判据]] 中"无强依赖 → Agent Team"的吸引力：即使速度收益有限，质量收益也足以支持并行选型。这与 [[agent-team选型判据三源对比]] 中 ConardLi [[agent-teams最后选项论]] 的谨慎立场形成对照——本文场景（结构化提取任务）中并行的质量红利清晰可辨。
