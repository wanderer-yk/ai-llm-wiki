# Agent 构建演进三阶段

Agent 构建演进三阶段是 [[顺乾]] 复盘问诊 Agent 构建方式得出的演进路径：初阶 Java 编码驱动 → 进阶提示词内嵌 SOP → Workflow 模式，每个阶段都有明确缺陷，最终引出第四形态 [[sop-doc可召回排查文档]] 新范式。两段代表性提示词原文完整保留在 [[sources/[202603040830]让问题不过夜交易领域问诊Agent实践]] 页。

## 初阶：Java 编码驱动

- 排查逻辑由 Java 代码完全实现，模型仅用于意图识别与工具调用。
- 缺陷：推理能力未充分挖掘、流程固化、灵活性差、难以快速迭代。

## 进阶：提示词内嵌 SOP

- 技能以提示词形式内嵌，灵活性强、减少编码依赖。
- 缺陷：**[[提示词爆炸]]**——多技能共存导致提示词膨胀、上下文混乱、指令跟随能力下降、运行稳定性差、可维护性差。

## Workflow 模式

- 利于原子工具组合。
- 缺陷：新增技能需重新编排、强依赖人工编排、享受模型提升红利有限、可维护性问题未解。

## 平滑迁移方案

- Workflow 架构：加兜底路由，将未命中流程的请求导向 SOP Doc 新范式；
- 智能助手架构：将技能描述从提示词拆出，迁至独立排查文档。

## 定位

该演进序列与 wiki 中 [[workflow优先于agent]]（有赞）、[[六步落地路径]]（zhiyuanfu）同属“渐进式演进”方法论家族，但独特之处在于以**文档为演进终点**而非编排或模型。
