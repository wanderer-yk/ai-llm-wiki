# 局部失败容忍与妥协分级

百度Geek说《Harness Engineering》理念四条之四：**允许局部失败**——1000 个文件失败 5 个，不应阻塞其余 995 个。同时引入妥协分级，避免"99% 搞定"的文件被反复重跑浪费 Token。

## 失败两分类

1. **真搞不定** → revert + 标记 FAILED + 回退人工处理；
2. **能搞定但不完美** → 标记 **DONE_WITH_WARNINGS**，照常合入并记录遗留项。
   例：TS strict 迁移中遗留少量 `any` / `// @ts-ignore`。

## 实证（7.2 JS to TS）

迁移失败的文件**保留原始 JS 版本**并标 FAILED——TS 项目允许 JS/TS 混用，整体仍可构建，不因个别文件回滚整个任务。

## 相关概念

与 [[错误最小范围解决]] 构成错误处理的一对互补理念：一个管隔离（错误不扩散），一个管妥协（不完美可分级放行）。状态分级依赖 [[任务状态自描述]] 的状态机设计（FAILED / DONE_WITH_WARNINGS 均为自描述终态）。
