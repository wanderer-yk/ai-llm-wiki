# 业务域物理隔离

知识存储按业务域物理分区分隔，各业务线知识独立管理、配置独立维护，防止跨业务域知识干扰。

## 设计原理

不同业务域使用不同技术栈（如业务域C 使用 `@internal/pro-components`，业务域B 使用 `@internal/supply-chain-libs`），物理隔离确保 AI 始终使用与当前项目匹配的知识，避免 [[跨业务域知识污染]]——不同技术栈业务域之间知识混用导致 AI 生成错误代码或建议的风险。

## 四类独立配置文件

每个业务域独立维护：

- `agent.md` — Agent 行为定义
- `mcp.json` — MCP Server 配置
- `domain.yaml` — 业务域规则
- `skills/` — Skills 技能包

## 当前覆盖

内部知识存储按业务域物理隔离，包括：通用、某跨境电商、业务域 A/B/C/D 等。

## 与知识泛化论的张力

业务域物理隔离与 [[知识泛化论]]（主张跨需求复用经验）之间存在张力。适用边界可能是"通用域"支持泛化，"业务域"严格隔离的分层策略。同仓库时间近的需求最有价值（需求时间距离衰减量化：近 60% / 中 35% / 远 15%），但跨仓库的通用知识价值定位仍不清晰。

## 作为五大设计原则之一

[[五大设计原则-天猫|五大设计原则]] 第三条："业务隔离 > 全局混杂：物理隔离避免污染"。
