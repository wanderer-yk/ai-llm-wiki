# 可控的不确定性边界

「可控的不确定性边界」是一种架构设计原则：**承认模型概率性的前提下，用确定性的架构组件包裹不确定的模型内核，把不确定性「关进笼子」**——通过编排与路由将「动态生成」转化为「受控执行」。原文金句：「AI 工程的『法』并非放弃控制，而是在承认概率性的前提下，通过架构设计将不确定性『关进笼子』。」

包裹结构（淘天集团搜索团队实践）：

| 层 | 组件 | 作用 |
|---|---|---|
| 前处理 | 输入校验、意图识别 | 在模型介入前收敛输入空间 |
| 模型内核 | 大模型生成 | 唯一的不确定性来源，被限制在边界内 |
| 后处理 | 结果校验、格式化 | 约束输出形态 |
| 安全逻辑 | 敏感词过滤 | 合规底线 |
| 兜底 | 规则兜底、更小更快的模型接管 | 异常时的降级路径 |

建议 4（见 [[AI工程建设五建议]]）补充了四类鲁棒性机制：**校验、回退、多模型投票、人工兜底**——预设模型输出可能波动、偏移甚至失效，把不确定性「封装」在可控边界内。
