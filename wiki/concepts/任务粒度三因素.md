# 任务粒度三因素

百度Geek说《Harness Engineering》6.1 节回答"拆到多细"的框架：合理拆解粒度取决于三个因素——

1. **模型上下文窗口大小**；
2. **单文件平均规模**；
3. **任务推理复杂度**。

## 粒度的双向代价

- **太粗** → 单子任务上下文膨胀，逼近压缩与失忆阈值；
- **太细** → 调度开销与 Prompt 模板 Token 占比过高，编排成本反噬收益。

## 80% 上下文占用检验标准

可操作的启发式校准：跑少量样本观察子任务 Token 消耗——

- 经常**逼近窗口 80%** → 粒度偏粗，应缩小；
- 仅占 **30%-40%** → 粒度偏细，可放大以减少调度开销。
