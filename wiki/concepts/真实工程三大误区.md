# 真实工程三大误区

**真实工程三大误区**是 [[牛潇]] 总结的实践中常见的 [[agent-skills]] 与 [[mcp]] 使用反模式，每个误区包含"症状-后果-解法"的完整逻辑闭环。

## 误区1：用 MCP 实现所有功能

- **症状**：将所有小功能（包括简单条件判断）都用 MCP 实现
- **后果**：业务逻辑与技术实现耦合，过度工程化，维护成本高
- **解法**：优先评估是否需要外部系统访问，简单业务逻辑用 Skills 编排

## 误区2：在 Skills 中硬编码复杂逻辑

- **症状**：在 Skills 中编写超过 2000 行复杂条件判断和数据处理逻辑
- **后果**：决策难以维护，执行不可靠，违反声明式架构初衷
- **解法**：将复杂逻辑拆分为 MCP 工具，Skills 只做编排

## 误区3：忽视安全边界

- **症状**：在 Skills 中暴露敏感操作（如直接数据库写入、支付操作）
- **后果**：数据泄露风险，安全漏洞，缺乏审计追踪
- **解法**：强制敏感操作走 MCP，遵循 [[敏感操作mcp隔离原则]]

## 跨概念关联

这三大误区与 [[ai编程幻觉]] 的防幻觉策略形成互补：不是从模型层面控制，而是从架构层面通过正确的 Skills/MCP 分工避免问题。
