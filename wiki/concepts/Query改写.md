# Query改写

[[意图规划]]的第一子模块，对用户输入进行补全/消解/摘要的预处理流程，确保意图识别与知识召回精准。

## 三类核心动作

| 动作 | 适用场景 | 示例 |
|------|----------|------|
| 多轮会话补全 | 指代不明、上下文缺失 | "它怎么用？" → 补全为完整表述 |
| 指代消解 | 模糊时间、模糊指代 | "去年" → "2024年"，"那边呢" → 具体位置 |
| 长文摘要 | 信息过载、冗长输入 | 提取核心问题，降低延迟和干扰 |

## 工程设计

**入参**：近 3 轮对话历史（超长截断）+ 本轮 Query + 用户基本信息（如所在地）

**输出**：强制 JSON 结构化输出

**模型选型**：几 B 至几十 B 参数的通用小模型，通常无需微调

## 关键工程 Tips

- **用户信息注入**：已验证有效并上线
- **长短期记忆与流程注入**：尚未实践
- **兜底逻辑**：改写失败时降级为原始 Query，主流程绝不中断
- **强制 JSON 输出**与 Wiki 中已有的 [[结构化输出]]（基于 Function Calling）是同一目标的不同技术路径

## ## 第二口径：《RAG全链路技术详解》四类问题（2026-05）

- **指代消解／纠错与去噪／术语对齐／结构转换**——与马上消费口径（本页「三类核心动作」）重叠子项为指代消解，两口径互补：本源面向检索前 query 规整，马上消费面向意图规划前置改写。
