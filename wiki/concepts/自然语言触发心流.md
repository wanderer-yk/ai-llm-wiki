# 自然语言触发心流

"自然语言触发心流"是 [[kiritomoe]] 在 [[ai网关压测项目]] 实践中总结的关键经验，指相比手动执行脚本，通过自然语言触发任务能让 AI Agent 获得更多上下文，从而在失败时自主探索修复，保持连贯的执行状态。

## 核心洞察

### 手动脚本 vs 自然语言触发

| 维度 | 手动执行脚本 | 自然语言触发 |
|------|------------|-------------|
| 上下文 | 仅脚本本身 | 完整问题描述 + 环境信息 |
| 失败处理 | 报错→人工排查 | AI 自主探索修复 |
| 执行连贯性 | 中断→重启 | 不打断 Agent 连贯状态 |
| 修复效率 | 人工多轮调试 | 大概率一次性修复 |

### 为什么自然语言更有效

1. **完整上下文** — 自然语言描述提供了问题的来龙去脉，而不仅仅是命令
2. **Agent 连贯性** — 不打断 Agent 的 [[agent-loop]]，保持在"心流"状态
3. **自主探索** — Agent 可以结合环境信息自主推理失败原因
4. **迭代修复** — Agent 可以在同一个上下文中多次尝试不同方案

## 实践案例

在 AI 网关压测项目中，遇到 O(n²) 拼接数据导致大并发超时的问题时，作者没有手动修改代码，而是通过自然语言向 Qoder 描述问题现象和运行时环境，AI 自主定位到性能瓶颈并一次性修复。

## 与上下文工程的关系

自然语言触发心流是 [[上下文工程]] 的一种实践形态——通过自然语言注入完整的问题上下文，使 Agent 拥有足够的推理依据。与有赞共享技术的 [[结构化上下文组装]] 形成对比：前者强调"描述问题的完整性"，后者强调"注入知识的结构化"。

## 跨领域关联

- 与 [[agent-loop]] 直接相关——心流的本质是不打断 Agent Loop 的 While 循环
- 与 [[task-driven对goal-driven]] 呼应——自然语言触发是 Goal-Driven 的入口
