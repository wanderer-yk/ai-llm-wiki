# 轨迹头尾保护压缩

轨迹头尾保护压缩是 [[hermes-agent]] 对离线 Agent 轨迹（[[agent轨迹]]）的压缩算法，实现于 `trajectory_compressor.py`，采用“**头部保护区 + 中间压缩区 + 尾部保护区**”三区划分。设计依据：头部=任务定义（没有它模型不知道在做什么）；尾部=最终答案（没有它训练信号不完整）；中间=大量试错探索（可用摘要概括）。

## 三区划分

- **头部保护区**（绝不压缩）：System Prompt + 首条人类消息 + 首条 GPT 回复 + 首次工具交互，作为任务锚点。
- **尾部保护区**（绝不压缩）：最后 4 轮对话，保留训练信号。
- **中间压缩区**：冗余探索内容，发给轻量摘要模型生成 `[CONTEXT SUMMARY]:` 摘要。低于 15250 token 的轨迹直接跳过压缩。

## 核心配置（`CompressionConfig`，原样保留）

```ruby
@dataclass
class CompressionConfig:
    tokenizer_name = "moonshotai/kimi-k2.5"  # 精确 Token 计数器
    target_max_tokens = 15250      # 压缩后的目标上限
    summary_target_tokens = 750    # 摘要的 Token 预算
    protect_last_n_turns = 4       # 保护最后 4 轮对话
    summarization_model = "google/gemini-3-flash"  # 轻量级的摘要模型
    max_concurrent_requests = 50   # 并发摘要请求数
```

Token 计数通过 HuggingFace Tokenizer（`AutoTokenizer`）精确进行，与实时压缩的“4 字符≈1Token”粗估形成对照（见 [[双压缩范式对比]]）。

## 定位

与运行时上下文压缩（[[比例阈值压缩]]）和既有 [[上下文压缩策略]] 页记录的 Claude Code 摘要式压缩、OpenClaw 分阶段压缩构成三方对照：本算法的压缩对象是**训练数据**而非运行时上下文，是压缩问题的第三种范式。摘要预算（750 token）与 [[分块token预算推导]] 的预算思想同族。
