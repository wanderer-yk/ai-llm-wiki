# 向量检索 RAG

基于向量嵌入的检索增强生成（RAG）技术路径，用于代码搜索领域。擅长语义理解，但在跨文件/调用链分析上存在固有瓶颈。

## 核心流程：双阶段流水线

### 索引阶段
代码 → [[代码安全扫描|敏感信息扫描]] → 分块 → 嵌入（Embedding）→ 向量库

### 查询阶段
提问 → 嵌入 → 检索（Top K）→ Prompt 组装 → LLM 生成回答

## 分块策略

| 策略 | 描述 | 适用阶段 |
|------|------|---------|
| 固定大小分块 | 滑动窗口+重叠区 | 项目初期，平衡成本与效果 |
| 语义分块 | 余弦相似度阈值切割 | 精细化阶段 |
| 场景化分块 | 按语法边界/章节切割 | 特定场景优化 |

[[有赞技术中台]]在项目初期选用固定大小分块，在成本与效果间取得平衡。

## 嵌入模型选型

有赞通过内部业务逻辑测试集横向对比国内外嵌入模型，最终选出相关代码召回率达 95% 的模型（具体名称未披露）。

## 向量检索算法

选用 **HNSW（分层可导航小世界图）** 算法，采用"顶层粗搜+底层精搜"策略，支持百万级向量高效检索。相似度度量选用**余弦相似度**，关注向量方向差异而非绝对距离，更贴合语义关联需求。

## 框架选型

选用 [[llamaindex|LlamaIndex]] 而非 LangChain，理由为轻量化封装和多模型厂商对接能力。

## RAG 技术瓶颈

详见 [[rag技术瓶颈]]。RAG 擅长少量文件语义找回，但在跨文件/跨仓库/调用链/继承链/影响范围分析等长链条结构化任务上失效，需 [[ast加符号表联合分析|AST+符号表]] 互补。
