# LLM as Judge

LLM as Judge 是天猫品牌行业前端团队 [[垂直化业务评测集]] 的评测工具组件（与"代码采纳率计算"并列，见 SWE-bench 对比表的评测工具行），指用大模型代替字符串匹配或单元测试来评判 AI 生成代码是否满足业务需求。

## 评分机制

- 每个评测用例包含若干 **refAnswers**（参考答案点），LLM 逐点评判，输出 **0 / 0.5 / 1 三档评分**
- 有测试覆盖的场景（数据处理逻辑、API 调用验证）可配置 **testCases** 作为客观验证补充，与 LLM 评分加权融合（融合权重来源未披露）

## 理论依据：前端多解性

前端需求存在多种功能等价实现，无法用字符串匹配判定正确性，必须由 LLM 做语义层面的功能等价判断。

## 泛化适用场景

作者给出泛化论断：LLM as Judge 适用于任何"多种正确实现"或"正确性需语义理解"的场景——后端业务逻辑、数据处理管道、配置文件生成、文档注释；共同判据是**无法用字符串匹配或单元测试覆盖所有正确答案**。

## 可信度对冲

针对"LLM 评分主观"的局限自认，团队以 [[评测可信度保障四机制]] 工程对冲，其中人工抽检显示 LLM 评分与人工复核一致性 > 90%，并辅以多模型交叉验证、版本基线对比与轨迹存档复盘。

## 与美团 Judge Model 的区别

美团 [[高阶模型审查低阶模型]] 是编码产出的审查机制（Judge Model 审查低阶模型代码），本概念是**离线评测打分**机制——同族但场景不同，不宜混同。
