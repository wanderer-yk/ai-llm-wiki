# 摘要分层降级策略

摘要分层降级策略是 [[openclaw]] `compaction.ts` 中摘要生成的三层函数族与逐级兜底设计：顶层 `summarizeInStages()` 路由 → 分块 `summarizeChunks()`（单块最多 3 次重试）→ 兜底 `summarizeWithFallback()`（先完整摘要，失败则排除过大消息再试，仍失败返回默认文本 "No prior history."）。

分层设计（原文）：

```
顶层策略: summarizeInStages()
  ├── 判断消息量小/token少？ → 直接走 兜底方案 summarizeWithFallback()
  └── 否则，按token比例分割 → 各块summarizeChunks()  → 合并summary → 最终summary

分块策略: summarizeChunks()
  ├── 处理单个消息块
  ├── 支持最多3次重试
  └── 每个chunk生成summary结束后，合并最终Summary

兜底策略: summarizeWithFallback()
  ├── 先尝试完整Summary
  ├── 如果失败 → 排除过大的消息后再试
  └── 如果还失败 → 返回默认文本 "No prior history."
```

Summary 内容特别要求保留：活跃任务、重要决策结论、TODO、承诺、不透明标识符（UUID、哈希等原文保留）；送入摘要前先经 `stripToolResultDetails()` 清理工具输出 details 字段（与 [[函数结果清理机制]] 主题呼应）。工程保障四项：`EMBEDDED_COMPACTION_TIMEOUT_MS = 300000`（5 分钟超时）、会话写锁、`identifierPolicy: "strict"`、压缩模型可经 `openclaw.json` → `agents.defaults.compaction.model` 配置为更便宜模型。

与 Claude Code 的 [[九段式结构化摘要模板]] 构成跨框架对照：前者重工程降级链，后者重摘要内容结构。
