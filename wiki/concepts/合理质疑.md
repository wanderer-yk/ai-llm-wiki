# 合理质疑

**合理质疑**是提升 AI 生码准确度的一种认知维度技巧：当 AI 给出不合理的实现时，开发者应明确质疑其方案并给出优化方向，而不是照单全收。它与[[严厉语气]]（语气维度）共同构成《天猫新品团队AI编码实战指南（下）》第 5.3 节"还能怎么提升其准确度"的双支柱，[[sources/[202605081607]天猫新品团队AI编码实战指南下|来源]]。

## 现象诊断

模型常以"完成用户需求"为第一优先级，倾向直接解决问题而忽视项目架构稳定性与维护成本——修复 bug 场景尤为明显。

## 典型案例

AI 修复依赖缺失问题时，会强行将原本在 Node 环境加载的功能包也加载进浏览器，导致项目不稳定；而该项目其实已有 Node 与浏览器环境通信的成熟机制。这类破坏性改动应被明确质疑并给出优化方向（配图图注："对 AI 不合理实现要质疑"）。

## 质疑模板（原文逐字）

```
"请尊重项目原本的架构，把破坏性的改动归位，按照更合理的方式进行修复"
"我认为你的实现有待商榷，你重新思考下这个问题并给我更好的解决方案"
```

## 关联

- 与 [[AI目标漂移约束]] 同族：合理质疑是 prompt 级的反向纠偏手段，在 AI 偏离架构约束时将其拉回。
- 与 [[严格解耦架构设计防技术债]] 同系列：核心诉求是保护项目架构不被 AI 的"最短路径"实现破坏。
- 场景归属：[[报错调试]]（bug 修复是质疑最高频的场景）；架构诉求与 [[AI友好代码架构]] 一致。
