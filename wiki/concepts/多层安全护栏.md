# 多层安全护栏

多层安全护栏指围绕 Agent 运行时与扩展加载过程设置的纵深防御机制。来源文章将其归于 [[hermes-agent]]，列出两个条目：**防 Prompt 注入的内置检测拦截**，以及 **Skill 文件加载前的静态代码分析与安全扫描**。它与插件开放性、子 Agent 委派共同构成"灵活性与合规性平衡"的安全面。

## 两个条目

1. **Prompt 注入防护**：内置检测并拦截注入攻击——对支持第三方消息平台接入的常驻 Agent 而言是第一道防线
2. **Skill 加载前扫描**：对 Skill 文件先做静态代码分析+安全扫描再加载——对自进化系统而言是必需防线，因为 Skill 是系统自己生成、持续变更的代码资产

## 在安全体系中的位置

- 与 [[受控子Agent机制]] 的工具黑名单、上下文片段化授权共同构成运行时隔离
- 与 [[安全边界三原则]] 的设计意识一致：开放扩展必须配套显式边界
- 与 [[代码安全扫描]] 同类：把静态扫描作为 AI 生成/加载代码的准入门禁
- 对应 [[agent-control-plane]] 中"权限/边界/审计"的控制面职责，是 [[harness-engineering]] "安全"要素的落地

## 开放问题

- Prompt 注入检测与 Skill 静态扫描的具体实现细节（规则库、扫描器、拦截策略）来源未披露
- 护栏与 [[插件化生态扩展]] 的接口关系（扫描发生在插件加载管线的哪个环节）未说明
