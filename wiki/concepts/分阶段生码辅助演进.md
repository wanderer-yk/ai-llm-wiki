# 分阶段生码辅助演进

**分阶段生码辅助演进**是天猫新品营销技术团队在小二端 AI 生码上呈现的三阶段演进路径：初期统一生成方案 → 中期工具补经验短板 → 后期无感知识库，各阶段均由真实反馈驱动迭代，[[sources/[202605081607]天猫新品团队AI编码实战指南下|来源]]。

## 三阶段

1. **初期——统一生成方案**：面向"前端练习生"（转型后端同学）与多种编码工具，目标是风格一致代码 + 贴近小二端视觉规范 + 一定 AI 迭代成功率；手段为小二端开发培训、基础代码实现规范（页面间完全解耦 + 代码约束）、高频页面代码模版。
2. **中期——辅助补齐前端经验短板**：针对"需求描述不准确"与"垂类场景/复杂问题没有经验"两类高频问题，引入 AI案例实践中心（标准化 prompt 模版）、天猫新品业务编码助手（MCP 速查工具）、基于 Gemini 3.0 特调的图片转结构化提示词工具、生码沉淀机制。
3. **后期——需要更简单、无感、且一致的方案**：体验反馈显示用户倾向基础 Chat 模式、"甚至不想配mcp"、不想跳出编辑器；对策为轻量级团队知识库（git + npm 包 + 文件链接渐进式披露 + curl 读 CDN + 编辑器 Rules 接入 + CodeWiki 问答），达成"及时更新、不依赖编码工具、支持问答、使用无感"的统一收口。

## 演进规律

- **反馈驱动**：每阶段的对策都来自上一阶段的真实使用反馈，中期以 MCP 工具为核心对策、后期用户却"不想配mcp"，是典型的方案 pivot（记录为演进证据而非矛盾）。
- **摩擦递减**：从"要求学习规范"到"工具辅助"再到"无感注入"，对用户的额外操作要求单调下降（[[无感辅助]]）。
- **未解尾巴**：演进末端仍遗留 [[精细化微调困境]] 与 [[开放式场景一致性难题]] 两个自陈未解难题。
