# 三范式量化评测基准

"三范式量化评测基准"是《[202604231830]从可观测到可理解用UModel构建Agent原生的代码知识图谱》展望部分提出的**规划中**评测方案（截至文章发布未落地、无实测数据）：以 SWE-bench 式量化评测，对三种代码理解接入范式做对照裁决。

## 评测设计（规划）

| 维度 | 内容 |
|------|------|
| 范式对照 | Model + Bash（Agentic Search）vs Model + CodeWiki（LLM 文档）vs Model + UModel（知识图谱） |
| 评测场景 | 影响分析、调用链追踪、架构违规检测、RCA 根因定位 |
| 评测指标 | 准确率、召回率、推理步数、Token 消耗 |
| 形式 | SWE-bench 式量化评测 |

规划主体为阿里云云原生可观测团队（作者自称归属）。

## 论证意义：范式之争的操作化

该基准直接把文章前半段的范式之争操作化为可度量命题：

- "agentic search > RAG"（Anthropic 内部测试，转述）vs "CodeIndex 是 AI IDE 主流"（工程事实）——两者各执一词，当前证据均为单方口径。
- 四个评测场景恰好对应两流派共同失效的三类问题（影响范围分析、跨域故障归因/调用链、架构边界检查）加 RCA。

在实测数据出现前，本文三案例只能视为 Demo 级证据（自报口径），该基准条目已列入 [[ai工程量化效果声明追踪]] 的"承诺未兑现"追踪清单。

## 与评测方法论的呼应

- 与有赞 [[agent评测四要素]]（评测对象/数据集/指标/反馈闭环）框架吻合：范式=对象，四场景=数据集维度，四指标=指标体系。
- 与小红书 [[评测集优先于知识库]] 主张同向：先建可度量评测，再比较方案优劣。
