# 活文档机制

通过 `/opsx:archive` 命令实现项目规范文档与代码的自动同步，消灭"僵尸 Wiki"问题。

## 核心原理

1. 开发阶段，规范增量存储于 `openspec/changes/[变更名]/specs/` 草稿目录
2. MR 通过后执行 `/opsx:archive`，将规范增量合并到 `openspec/specs/` 主目录
3. 清空变更草稿，`openspec/specs/` 始终与代码保持同步

## 解决的痛点

直接解决 AI 辅助编码的第四大痛点"文档脱节"——文档与代码不在同一版本控制系统导致的天然失同步问题。通过将规范文档纳入代码仓库，利用 archive 命令自动同步，使文档成为"活体"。

## 项目目录结构

```
openspec/
├── config.yaml          # 项目配置（技术栈/代码规范/业务背景）
├── specs/               # 归档活文档（按功能名组织）
│   └── [功能名]/spec.md
└── changes/             # 变更草稿（按任务名组织）
    └── [任务名]/
        ├── proposal.md  # 为什么做/做什么
        ├── design.md    # 怎么做
        ├── tasks.md     # 施工清单（≤15项）
        └── specs/       # 规范增量
```
