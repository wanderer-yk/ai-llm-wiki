# 执行收回论

执行收回论是《Claude Code 源码拆解》提出的判断标准：多 Agent 从 demo 走向系统的分水岭，是任务系统能否「把分出去的执行重新收回来」。作者进一步以内部平台视角指出，「分出去之后还能被管理、被追踪、被恢复」是产品能否进入团队协作链路的决定因素——执行体若收不回来，再智能也只是失控的后台进程。

收回能力的三个抓手：

- **管理**：状态可见、可取消（Task 的 status/cancel）
- **追踪**：进度与通知回流主会话（progress/notifications，见 [[任务结果回流]]）
- **恢复**：可 resume、可从磁盘回灌（resume/evictAfter，见 [[任务生命周期治理]]）

与 [[任务对象化判据]] 互为表里：对象化是收回的前提，收回是对象化的目的。多 Agent 因此从「智能 feature」变成「任务系统的一个后端」。
