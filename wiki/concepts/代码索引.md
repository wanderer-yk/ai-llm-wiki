# 代码索引

通过特定技术为代码库建立"智能地图"，实现快速定位目标代码的能力。代码索引关联代码的准确性直接决定大模型输出质量（[[gigo原则]]）。

## 三大使用场景

1. **IDE 跳转**：开发者日常编码中的符号定义/引用跳转
2. **开发者代码定位**：在海量代码中快速找到特定功能的实现位置
3. **非开发人员代码了解**：产品经理、测试等非开发角色理解代码逻辑

## 主流方案

### 向量嵌入索引（RAG）
详见 [[向量检索rag]]。擅长语义理解，在跨文件/调用链分析有瓶颈。

### AST 索引
详见 [[ast加符号表联合分析]]。擅长结构化分析、调用链追踪。

### ES 全文索引
基于 Elasticsearch 的文本搜索方案，适合关键词精确匹配。

## 自建代码索引的三大动机

1. **支撑 AI 编码**：代码索引是 AI 编码辅助的基础设施，[[gigo原则|索引质量决定输出上限]]
2. **保障代码安全**：避免将代码发送至第三方服务，通过内部[[代码安全扫描|敏感信息扫描]]脱敏
3. **降低使用成本**：第三方 AI 编程工具单次问答成本可达数美元，自研方案可控制在几毛钱人民币

## 业界方案对比

| 工具 | 索引策略 | 特点 |
|------|---------|------|
| [[cursor]] | grep + Vector Index + [[merkle-tree增量索引]] | 混合策略，Merkle Tree 快速增量更新，语义化分块 |
| [[claude-code]] | 纯 grep 文本匹配 | 实现简单但 Token 消耗多、上下文冗余 |
| [[aider]] | [[repo-map方案]] | 对大仓库处理不足，效果稳定性欠佳 |

## 成本权衡动态

Token 成本长期下降趋势可能改变 RAG vs 纯文本匹配的成本权衡：RAG 前期索引成本高但 Token 消耗少，纯匹配实现简单但长期成本高。
