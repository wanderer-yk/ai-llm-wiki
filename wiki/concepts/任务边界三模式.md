# 任务边界三模式

百度Geek说《Harness Engineering》"任务边界清晰"理念的具体实现分类。前提：每个子任务边界由**输入/输出/约束三要素**定义，子任务不共享状态、不交叉引用——隐式依赖如多米诺骨牌，一处倒处处倒。

## 三种模式（按任务间关系）

1. **无依赖 → 直接并行**
   例：i18n 中文硬编码独立提取，各文件互不相干，全部并发。
2. **有依赖 → 拓扑排序**
   例：JS to TS 迁移，叶子文件（无下游依赖）先迁移；分组前做依赖分析、按拓扑序排优先级，**同优先级并行、跨优先级串行**。7.2 场景实证。
3. **有冲突 → 物理隔离**
   例：Code Review 中各文件都可能改公共配置；各子任务在**独立 Git Worktree** 操作，冲突推迟到合并阶段、由 Agent 在**静止状态**（所有子任务执行完毕）下解决——静止状态解冲突效果远好于多 Agent 竞态实时协调。

## Agent Teams 的位置

Agent Teams 网状协作因通信开销与不确定性显著，仅作最后选项（→ [[agent-teams最后选项论]]）；与 ConardLi [[并行开发隔离机制]] 的 Worktree 实践同向，构成潜在比对项。
