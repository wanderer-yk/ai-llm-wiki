# 代码作为产研协作中间态

[[柚漫剧团队]] 研发章（4.4）的标题级趋势论断：传统链路中 PM→PRD、UE→设计稿、研发编码各环节**形态不同、信息损耗**；当 UE 用 Figma Make 直接产出可运行代码、FE 做工程化处理而非从零还原时，**代码本身成为产研协作的统一中间态**——这可能是未来产研合作趋势。

## 适用边界（含经验四"承认边界分场景落地"，并入本页）

- **新项目**：重交互、无历史包袱，适合整体生成流程。
- **存量项目**：拆分模块——UE 负责关键模块动效代码输出，FE 按耦合程度选择直接采用，或作为参考输入给 Coding Agent 做工程适配。

## 支撑与关联

- 工具支点：Figma Make（漫剧官网项目实证，见 [[柚漫剧APP]]）。
- 上游机制：[[设计即代码]]（研发规则框架内调优）。
- 协作保障：[[跨角色前置对齐架构]]——生成前不对齐整体结构则返工成本高。
- 演进规划：Figma→Mermaid→代码链路（4.6，未建独立页）。
