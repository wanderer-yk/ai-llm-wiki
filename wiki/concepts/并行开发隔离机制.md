# 并行开发隔离机制

web-video-presentation 为解决"多个 Agent 同时改同一个项目会不会互相冲突"而设计的四条严格隔离机制：

1. **每章独立文件夹**：如 `src/chapters/01-intro/`、`src/chapters/02-core/`；
2. **每章独立 CSS 前缀**：如 `.intro-hero`、`.core-card`，避免样式类冲突；
3. **主题 token 兜底**：全局 CSS 变量统一视觉基调；
4. **风格不强求一致**：允许章节间存在合理差异。

## 因果链

正文明确给出架构级主张：章节间**严格物理隔离 → 天然支持多 Agent 并行编写** → 大项目（10 章、100+ 步）单 Agent 太慢时启用 Agent Teams/SubAgent 并行，最大并行 3 个，每个 Agent 输入包四件（自己负责的章节大纲、Skill 规范、主题变量、第一章代码作参考），互不干扰。

该机制与苏雄 800 行框架的 [[子agent单进程并发模型]]、[[互斥锁与暂存队列]] 是多 Agent 并发治理的不同路线：本文靠**物理隔离消解冲突**，苏雄靠**单进程调度串行化冲突**。
