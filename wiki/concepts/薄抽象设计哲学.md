# 薄抽象设计哲学

薄抽象设计哲学指在 Agent 框架设计中优先选择**最薄的抽象层、显式控制流、贴近模型 API** 的实现，而非多层中间件或框架封装。其收益是工程确定性：系统边界清晰、运行路径可追踪、问题易定位，且利于后续扩展 Memory、调度、持久化；推论是「中间层越薄，调试越容易」。与 [[极简agent设计哲学]]（279 行单文件）同谱系，[[零框架依赖]]（不依赖 LangChain、直连 Anthropic SDK）可视为其子面。

## 苏雄 800 行框架中的六个实例

1. **Tool 四要素无中间层**：`toSchema()` 直接输出 Anthropic function calling schema，`input_schema` 类型直接复用 SDK 的 `Tool` 类型，SDK 类型即唯一 schema 定义（见 [[tool抽象四要素]]）。
2. **工具层即能力边界**：`exclude()` 过滤工具子集即为子 Agent 权限控制，无需独立权限层（见 [[子agent工具排除机制]]）。
3. **回调注入消息通道**：MessageTool 构造时注入 `sendCallback`，REPL 下即 `console.log`，Bot 下替换为 Telegram/Discord 发送函数，「工具本身不关心消息最终去向」，切换接入层零改动（见 [[入站消息总线]]）。
4. **出站入站分离**：MessageTool（出站）与 MessageBus（入站）方向相反、无直接代码耦合，「双通道消息机制，互不耦合」。
5. **显式并发控制**：不用并发库，用一个布尔标志 + 数组显式实现互斥锁与暂存队列（见 [[互斥锁与暂存队列]]）。
6. **零框架依赖**：直连 Anthropic SDK，完全控制 API 交互细节，调试无需穿透框架抽象层；代价是部分基础能力需自己实现。
