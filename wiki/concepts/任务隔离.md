# 任务隔离

以任务为单位隔离上下文的架构模式：每个任务拥有独立的上下文窗口，任务内部仍采用 [[追加式上下文]]，任务间互不干扰。

## 核心思路

```
对话驱动：  一个大上下文窗口 → 所有任务混合
任务隔离：  Task A 上下文 | Task B 上下文 | Task C 上下文
```

## 优势

1. **消除话题混杂** — 不同任务的上下文完全隔离
2. **成本与复杂度成正比** — 简单任务只需少量 token
3. **天然支持并行** — 多任务可并发执行
4. **失败隔离** — 一个任务的上下文膨胀不影响其他任务

## 代价

1. **丧失跨任务连贯性** — 任务间无法直接共享上下文
2. **跨任务信息传递需额外机制** — 共享摘要、会话关联等
3. **增加系统复杂度** — 任务管理、调度、结果聚合

## 取舍逻辑

| 模式 | 优势 | 代价 | 适用场景 |
|------|------|------|---------|
| 对话驱动 | 入门门槛低、模型兼容好 | 话题混杂、成本失控 | 用户交互型产品 |
| 任务隔离 | 效率高、成本低 | 跨任务信息断裂 | 工程化/自动化场景 |
