# Agent协同模式

[[上下文工程]]第三大组件（Agent 接入）的两种核心模式，构成从简单问答到复杂流程任务的完整能力拼图。

## 模式一：智能规划模式（MCP 自主调度）

将业务功能封装为独立工具，由大模型根据任务目标自主规划调用链。

**适用场景**：流程灵活多变、多轮交互、有一定容错率的任务

**核心设计**：

- 模型作为调度大脑，自主决定工具调用顺序和参数
- **系统工具**（System Tools）定义在主 System Prompt 中：向用户提问工具、信息总结工具、多选项选择工具、任务完成判断工具——是流畅多轮交互的基石
- **安全铁律**：所有涉及数据写入或真实操作的工具，执行前必须强制获取用户明确授权

## 模式二：精准路由模式（意图→专用 Agent）

智能助手担任路由中枢，意图识别模块配置动态路由规则，直接定向调用对应业务 Agent，以流式接口接收结构化结果。

**适用场景**：已存在大量高度工程化专用 Agent 的场景

**两个工程要点**：

- **权限控制下沉**：业务 Agent 调用权限由提供该 Agent 的业务部门自行管控，权责对等
- **渲染能力开放**：中心系统须正确解析并渲染业务 Agent 返回的富文本（Markdown/图表/自定义 UI 组件）

## 与其他方法论的关联

- **安全铁律**（数据写入前强制用户授权）与 [[human-in-the-loop]] 概念高度一致
- **精准路由模式**（意图→专用 Agent）与 [[agentscope]] 多智能体框架中的 Agent 路由问题存在技术类比
- **系统工具设计在主 System Prompt** 与 [[多agent角色思维隔离]] 通过 Prompt 分配角色的思路有共通之处
