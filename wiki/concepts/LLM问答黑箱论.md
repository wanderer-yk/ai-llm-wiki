# LLM 问答黑箱论

LLM 问答黑箱论是[[觖弦]]在文章结尾感言中提出的对 LLM 使用者视角的本质概括：**无论 LLM 内部能力多丰富，其对使用者而言本质上只有一个能力——「你问，我答」**；因此一切工程化工作都是「调整输入内容」的衍生。

## 论证结构

这一论断为 [[harness工程三部曲演进论]] 提供了逻辑起点：既然 LLM 对外接口收敛为「问→答」，那么 Prompt Engineering（打磨问法）、Context Engineering（组装问的上下文）、Harness Engineering（工程化地决定问的内容）就都可以还原为同一个问题——「有限的上下文窗口中该放什么内容」（详见 [[上下文窗口四要素]]）。

## 跨源印证

- 马上消费的 [[上下文工程]] 同样把「知识注入+数据注入+Agent接入」的上下文管理认定为 Agent 框架的「最大变量与智能核心」——与本论断同以「上下文窗口放什么」为工程化核心命题；
- 腾讯 yabohe 的 [[agent框架三要素]] 从框架视角把 Context Engineering 列为三要素之一的「连接核心」，可视为黑箱论在框架层的对应物：LLM Call（答）+ Tools Call（答的过程）+ Context Engineering（问什么）。

## 局限

黑箱论刻画的是**使用者视角**；LLM 内部的推理、训练与对齐机制不在其解释范围内。它也不否定模型能力差异——而是主张模型能力差异最终都要通过「输入内容」的通道才能作用于输出。
