# 同目录文件同组原则

百度Geek说《Harness Engineering》的子任务分组依据：**分组的单位是依赖关系而非行数凑巧**——共享 import / 类型定义 / 配置文件的文件应归入同组，以保证局部上下文完整性。

## 理由

- 同目录文件通常共享依赖与约定，同组处理时 Agent 无需跨组猜测上下文；
- 在 Code Review 场景中，**同目录文件同组审查质量更高**（7.1 实证）；
- 在 JS to TS 迁移中，同目录归组与依赖拓扑排序配合，减少跨组类型断裂（7.2 实证）。

## 组合使用

同目录同组回答"和谁一组"，[[任务粒度三因素]] 与 [[3000行经验上限]] 回答"组多大"，[[任务边界三模式]] 回答"组间如何调度"——三者共同构成 6.1 拆解方法论。
