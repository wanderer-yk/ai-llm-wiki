# 概率级联故障

[[韩春]] 提出的 LLM 时代故障模型变迁。传统故障链是物理资源拥塞驱动，应对手段（扩容/熔断/限流/降级/分库分表）确定性有效；LLM 时代出现全新的概率级联故障链（正文原表）：

| | 故障链 |
|---|--------|
| 过去 | 物理资源不足 → 服务性能下降 → 依赖服务超时 → 级联故障 → 系统雪崩 |
| 现在 | 单步推理错误 → 错误前提传播 → 后续步骤基于错误前提 → 最终结果错误 → 业务影响 |

## 传统体系的漏洞

传统体系并非无懈可击：底层物理链路共享，可被击穿——作者转述 2025-10 AWS us-east-1 持续 15 小时故障（竞态条件致 dynamodb 域名解析为空）为证（未独立核实）。

## 工程含义

- 测评须覆盖**变更时 + 运行时**两个时点，并引入准实时反馈链路；
- 多层防御会失效的原因见 [[瑞士奶酪模型]]；
- 补救方向是 [[真实世界负反馈]]——用物理世界真实影响作为反馈信号，跳脱 LLM 语义空间；
- 与 [[agent评测四要素]]、[[q-score质量评分机制]] 构成评测方法论的故障模型基础。
