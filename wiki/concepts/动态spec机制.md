# 动态 spec 机制

动态 spec 机制是 [[qoder]] Quest 模式的核心动态机制之一，指 spec 在 Quest 中并非死板的 SOP（标准操作流程），而是一个支持动态触发的活文档。

## 核心特征

### 非死板 SOP

传统 SDD 工具的 spec 通常是预定义的步骤清单，需要按顺序执行。动态 spec 机制打破了这一限制：

- **手动触发** — 用户可手动勾选需要执行的 spec 项
- **自动触发** — 模型可根据上下文自动决策何时触发哪个 spec 项
- **动态生成** — spec 内容可根据项目进展和用户反馈动态更新

### 活文档属性

动态 spec 是"活"的——它随着项目演进不断更新，而非一次生成后冻结。这与腾讯 [[活文档机制]] 的理念一致：文档应与代码同步演化，避免僵尸 Wiki。

## 与其他文档策略的对比

| 策略 | 来源 | 特征 |
|------|------|------|
| 动态 spec | Qoder Quest | 手动/自动触发，活文档 |
| [[ssot单文档策略]] | Specflow | 所有信息集中在 plan.md |
| 多文件分目录 | 腾讯 OpenSpec | 按职责分文件管理 |
| [[多源分治策略]] | 爱奇艺数据库 | 信息按职责分配到多个稳定位置 |

动态 spec 的独特贡献在于"触发方式的灵活性"——不是文档存放在哪里的问题，而是文档何时被激活的问题。

## 跨领域关联

- 与 [[规格驱动ai开发]] 的核心理念一致——以规格文档为"契约"驱动 AI 代码生成
- 与 [[执行语义冻结]] 互补——spec 生成后冻结执行语义，但 spec 本身是动态的
- 与 [[sdd留痕进化论]] 呼应——spec 的动态更新本身就是一种"进化留痕"
