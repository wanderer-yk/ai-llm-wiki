# 执行语义冻结

[[harness-engineering]] 方法论中的核心概念，指在让 agent 进入实现之前，必须将运行模式、输入输出、异常口径、非目标范围、回滚方式等执行语义提前写清并固定。

## 问题定义

后端任务反复不是因为代码难，而是执行语义没有冻结。Agent 产出停在"看起来可以跑"却无法交付，根因是以下五个维度未提前明确：

1. **运行模式** — 命令触发/定时任务/消费链路/API/数据同步/配置驱动
2. **输入输出** — 配置/参数/文件/API/消息的来源和格式
3. **异常口径** — 重试/跳过/停止/回滚的决策边界
4. **非目标范围** — 明确不在本轮处理的边界
5. **回滚方式** — 失败后的恢复策略

## 后端任务七问

计划文件应回答的七个关键问题：

1. 入口命令与触发方
2. 输入来源（配置/参数/文件/API/消息）
3. 核心对象装配与必校字段
4. service/repository/gateway/adapter 职责划分
5. 失败策略（重试/跳过/停止/回滚）
6. 成功与失败的验证命令或 runbook
7. 结果写回目标

## 与相关概念的关系

- 与 [[研发范式前移]] 是同一理念的不同表述：将问题解决从编码调试期前移至需求设计期
- 与 [[ai编程幻觉]] 直接呼应：幻觉不仅源于上下文不完整，更源于执行语义未冻结导致的多维度猜测
- 是 [[harness-engineering]] 五要素中"执行依据"的具体化实践
