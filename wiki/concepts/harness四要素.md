# Harness 四要素

Harness 是围绕 Agent 构建的测试、验证与约束基础设施。来源给出其最低构成——**四要素**：

1. **验收基线**：判定任务完成的可执行标准（知道什么算对）；
2. **执行边界**：Agent 能做什么、不能碰什么（能碰什么）；
3. **反馈信号**：让 Agent 感知对错的自动化机制（错了如何得知）；
4. **回退手段**：出错后恢复到已知良好状态的能力（错了如何恢复）。

## 核心论点

"决定系统能否稳定运行的是外围工程条件"，更贵模型的提升常低于预期。

> [!warning] 可验证性边界（重要限定）
> 该论断在高可验证任务（如代码编写）上最成立；在开放式研究、多轮协商等弱验证任务中，模型上限仍然更关键——不可将此论断无条件外推。

## 术语辨析：两个 harness 语境

本页的 harness 是通用工程基础设施概念，一手出处为参考文献 [1] OpenAI《Harness engineering》。而既有页 [[harness-engineering]] 记录的是爱奇艺数据库团队的同名研发方法论——二者同名词、不同脉络，引用时须分源。

## 与任务四象限的关系

[[任务四象限]]（任务清晰度 × 验证自动化程度的 2×2 模型）是四要素的图示化延伸：

- 右上角（目标明确 + 可自动验证）：最适合 Agent；
- 左上角：吞吐天花板是人的审查速度；
- 右下角："高效地往错误方向跑"；
- 左下角：Agent 基本无用。

**Harness 的使命就是把任务推向右上角。**

## 跨团队印证

- [[harness-engineering]]（爱奇艺数据库团队）：五要素工程化 harness（任务入口、执行依据、工具边界、验证反馈、结果记录），与本四要素高度同构。注意其属于与 OpenAI harness 不同脉络的同名方法论，见上文"术语辨析"。
- [[脚手架优于模型]]（zhiyuanfu）：脚手架升级成本 +50%、效果 +200%；对比模型升级成本 +300%、效果 +20%。
- [[agent生产落地环境重构论]]（vivo 丁俊杰）：环境改造先于能力提升，"Agent 越强风险越大（环境不就绪时）"。
- [[验证门禁化]]：验证从"建议检查"升级为硬性阻断规则，是"执行边界 + 反馈信号"的工程化落地。

参考文献 [1] OpenAI《Harness engineering: leveraging Codex in an agent-first world》既是本页 harness 概念的一手出处，也是来源中 OpenAI Agent 优先开发案例的一手出处。
