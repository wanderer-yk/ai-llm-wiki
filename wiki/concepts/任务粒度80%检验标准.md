# 任务粒度 80% 检验标准

任务粒度 80% 检验标准是《Harness Engineering: 让 Coding Agent 可靠完成长程任务》6.1 给出的拆解粒度校准启发式：粒度设计不能只靠先验推算，落地时跑一批样本子任务，观察其 Token 消耗占模型上下文窗口的比例，以此校准拆分尺度。

## 判定规则

- **经常逼近窗口 80%** → 粒度偏粗，应继续缩小，避免逼近上限时触发 [[上下文焦虑]]（提前收尾、谎报完成）与完成质量劣化；
- **仅占 30%-40%** → 粒度偏细，可放大以减少调度开销与 Prompt 模板 Token 占比。

## 在粒度方法论中的位置

粒度决策由三部分构成：[[任务粒度三因素]]（上下文窗口大小、单文件平均规模、任务推理复杂度）提供先验框架；[[3000行经验上限]] 与 [[分块token预算推导]] 提供经验公式与预算推演；80% 检验标准提供实测校准闭环。三者共同服务于 [[长程任务四原则]] 中"任务拆解"原则的落地。

## 双向代价背景

粒度太粗导致单子任务上下文膨胀，威胁 [[完成真实性]]；粒度太细则调度开销与 Prompt 模板 Token 占比过高，抬高成本——80% 检验标准正是为在这两个失败方向之间定位而设，配合 [[子任务CLI化]] 的调度开销约束使用。
