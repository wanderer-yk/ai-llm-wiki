# 无感辅助

**无感辅助**是天猫新品营销技术团队在工具/知识方案设计中确立的体验哲学：用户停留在基础 Chat 对话模式，零额外操作——不配 MCP、不跳出编辑器、不学习新流程——知识与规范经底层设施自动生效，[[sources/[202605081607]天猫新品团队AI编码实战指南下|来源]]。

## 来源：真实采纳摩擦

该哲学源于小二端后期的用户反馈：大部分人倾向基础 Chat 对话模式，"不想使用类 Spec 的规划模式"、"不想跳出编辑器进行额外的操作（甚至不想配mcp）"。团队据此将方案从"要求用户改变工作方式"转向"让基础设施适配用户习惯"。

## 实现载体

- 编辑器 Rules 配置即接入（无独立操作界面）；
- AI 通过 curl 直读 npm 包 CDN 资源获取知识（[[npm包知识库架构]]）；
- 类 Skill 封装的公共知识库（[[类skill公共知识库]]）；
- 最终达成统一知识源四特征之一"使用无感"（[[统一收口]]）。

## 意义

无感辅助本质上是对工具采纳成本的战略性归零：任何需要用户"多做一步"的方案都会在该团队的真实环境中被淘汰。这与 [[知识库降熵论]]（知识库的本质是降低人机协作的信息传递成本）在动机层面一致，也为 [[mcp]] 等需要显式配置的协议形态提供了重要的落地摩擦证据。
