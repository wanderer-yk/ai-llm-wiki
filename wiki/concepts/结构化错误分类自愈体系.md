# 结构化错误分类自愈体系

结构化错误分类自愈体系是一种 Agent 错误处理方法：将运行时错误做**穷举式标准化分类**，并为每类预设自动恢复策略（Recovery Strategy：重试、降级或修正），使系统不再笼统处理 "Error"，而是按类型快速识别并自愈。来源文章将其归于 [[hermes-agent]]：在 `agent/error_classifier.py` 中定义了 14 种错误类型，避免模型因单次失败而中断整个长上下文任务。

来源文章的动机判断：长程任务中系统报错是 Agent "崩溃"或陷入死循环的主因，因此错误分类的粒度直接决定长程稳定性问题的可控程度（参见 [[长程任务三困难]]）。

## 14 种错误分类表（`agent/error_classifier.py`）

| 错误类型 | 含义 | 典型场景 |
|---|---|---|
| `auth` | 认证失败 | API Key 无效 |
| `auth_permanent` | 永久认证失败 | 账号被封禁 |
| `billing` | 账单问题 | 额度用完 |
| `rate_limit` | 请求过多 | 被限流 |
| `overloaded` | 服务器过载 | 服务器忙 |
| `server_error` | 服务器错误 | 5xx 错误 |
| `timeout` | 请求超时 | 网络问题 |
| `context_overflow` | 上下文溢出 | 消息太长 |
| `payload_too_large` | 请求体太大 | 413 错误 |
| `model_not_found` | 模型不存在 | 模型名错误 |
| `format_error` | 请求格式错误 | 参数问题 |
| `thinking_signature` | 思考签名错误 | Anthropic 特有 |
| `long_context_tier` | 长上下文限制 | Anthropic 特有 |
| `unknown` | 未知错误 | 需要重试 |

## 方法论定位

- 与 [[错误处理三机制]]、[[局部失败容忍与妥协分级]]、[[错误最小范围解决]] 同属"让局部失败不放大为全局失败"的工程语族；Hermes 的特色是把错误类型学做成了**穷举式标准化清单**
- 与 [[漂移比崩溃危险]] 形成互补视角：该体系防的是"崩溃/死循环"类失败，漂移类风险需另外的可观测手段
- 是 [[harness-engineering]] 中"自愈"要素的具体实现，配合 [[全生命周期hook机制]] 的监控能力构成运行时保障
