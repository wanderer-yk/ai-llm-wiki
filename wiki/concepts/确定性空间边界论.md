# 确定性空间边界论

确定性空间边界论是 [[阳凯]] 得物技术 Spec Coding 实战全文的哲学总结：**用结构化的规范和工作流把不确定性消除在执行之前——AI 负责在确定性空间里高速执行，人负责维护和扩展那个确定性空间的边界**。作者以杠杆比喻收束全文：**规范是杠杆，AI 是力，Spec 工作流是支点**——人投入在规范与工作流上的每一点结构化，都会被 AI 的高速执行放大。

## 要点

- 确定性空间由 [[三层规范体系]]（约束/示范/视觉）与 Spec 工作流（proposal→design→specs→tasks）共同圈定；
- 人的角色不是被 AI 取代，而是从「在空间内执行」迁移到「在空间边界处扩展」——与 [[开发者角色重构]] 互为表里；
- 该论断为 [[需求颗粒度三档协作模式]] 提供底层解释：颗粒度越大的需求，不确定性越高，越需要先扩展确定性空间（写 Spec）再执行。

## 谱系与关联

- 与得物前文 [[人机协作新型开发范式]] 直接延续；
- 与 zhiyuanfu [[脚手架优于模型]]（脚手架升级成本 +50% 效果 +200%，模型升级成本 +300% 效果 +20%）共享「先建确定性结构再谈模型能力」的立场；
- 与 [[增强自我而非取代自我]] 的共同点：AI 价值释放依赖人先构建结构化边界。
