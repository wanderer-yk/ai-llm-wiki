# Diff 预处理流水线

## 定义

Diff 预处理流水线是 [[货拉拉大前端]] AI Code Review 系统的核心模块之一，旨在对 GitLab Webhook 传入的原始 Diff 数据进行清洗、过滤和语义重塑，为后续的 RAG 召回和深度 Review 提供高质量输入。

## 设计动机

直接将原始 Diff 投喂给大模型存在两大问题：
1. **Token 消耗**：大量非逻辑文件变更（配置文件、样式文件、资源文件等）浪费 Token 预算
2. **注意力分散**：冗余信息干扰模型对核心逻辑变更的关注，降低审查质量

这体现了 [[gigo原则]]（Garbage In Garbage Out）——代码审查的输入质量直接决定 AI 审查输出质量。

## 核心步骤

### 1. 特征过滤

剔除非逻辑文件类型，包括但不限于：
- `.json`（配置文件）
- `.png` / `.jpg` / `.gif`（图片资源）
- `.lock`（依赖锁定文件）
- `.css` / `.scss` / `.less`（样式文件）

仅保留与业务逻辑相关的代码变更。

### 2. 切片化

将过滤后的 Diff 按文件维度切分为可管理的单元，为后续的分片处理（参见 [[长diff分片并发与报告整合]]）做准备。

### 3. 语义重塑

语义重塑是预处理流水线的关键步骤。在进入正式审计之前，先让模型分析两个问题：
- **"这段代码在做什么"**：理解代码的功能意图
- **"改动意图是什么"**：理解本次变更的目的

语义重塑的产出不是审计结论，而是为后续 [[rag经验召回引擎]] 的精准匹配和深度 Review 的上下文理解奠定基础。

### 4. 原实现方法补全

对于被修改的逻辑方法，补全其原始实现代码，使模型能够同时看到"修改前"和"修改后"的完整上下文，更准确地判断变更影响。

## 与其他代码理解方案的对比

- 与 [[code-insight]]（有赞）的相似性：都使用 AST/RAG 技术进行代码理解，但有赞聚焦搜索与问答场景，货拉拉聚焦审查场景
- 与 [[代码索引]] 的关系：预处理流水线是代码索引的一种轻量级应用——不做全量索引，而是针对每次 Diff 进行即时分析
- 与 [[ast加符号表联合分析]] 的关系：有赞 Code Insight 使用 AST + 符号表构建调用关系图谱，货拉拉预处理流水线更侧重语义层面的变更理解

## 输出

预处理流水线的输出包含：
- 过滤后的逻辑代码 Diff
- 语义简要（代码功能与改动意图描述）
- 被修改方法的原实现代码

这些输出将作为 [[rag经验召回引擎]] 的查询输入和深度 Review Prompt 的组成部分。
