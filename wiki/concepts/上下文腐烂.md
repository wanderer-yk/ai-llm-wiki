# 上下文腐烂（Context Rot）

上下文腐烂（Context Rot）是由 [[anthropic|Anthropic]] 提出并命名的现象：随着上下文长度爆炸式增长，模型出现性能下降、注意力分散和信息利用效率降低。从长会话的角度看，它也可被刻画为：随着对话轮次增加，LLM 对早期指令的注意力和精确度线性下降——这是常规智能体在长会话中的核心痛点之一。

## 表现形式

- **性能下降**——模型在长上下文中的推理质量不如短上下文
- **注意力分散**——关键信息被淹没在海量上下文中（"Lost in the middle"现象）
- **信息利用效率降低**——模型无法有效利用已有上下文中的信息

## 对 Agent 的影响

上下文腐烂对长时间运行的 Agent 系统影响尤为严重。即使如 [[gpt-5|GPT-5]] 或 [[claude-opus|Claude Opus]] 等支持超长上下文输出的模型，在 Agent 频繁调用工具时也必然遭遇上下文腐烂，导致模型性能不升反降。

这意味着**仅靠扩大上下文窗口无法解决问题**，必须引入工程化手段。

其典型载体是 [[追加式上下文]]：对话历史只增不减，导致 token 随轮次线性增长。

## 缓解策略

不同系统给出了不同的应对路线：

### Deep Research 的工程化手段

[[deep-research|Deep Research]] 采用多种策略缓解上下文腐烂：

- [[双层级agent架构|双层级 Agent 架构]]——分离监督者与执行者的上下文
- [[上下文卸载技术]]——将信息存储于活跃窗口之外，按需检索
- [[分级存储架构]]——按重要性和使用频率分级保留信息
- [[智能剪枝策略]]——用小模型预先提取核心信息

### Ralph Loop 的"刷新上下文"路线

[[ralph-loop|Ralph Loop]] 的解法不压缩、不总结，而是**每轮循环开启全新会话**：Agent 靠文件读取工具扫描项目结构与日志（progress.txt、prd.json）同步状态，状态本身由 [[状态外置持久化]] 三组件承载。上下文因此始终"新鲜"，而记忆沉淀在文件系统而非对话历史中。

### 各路线对比

> 以下对比出自 [202601270830]从ReAct到RalphLoopAIAgent的持续迭代范式.html 的视角。

- **总结/截断**：常规手段，有信息损失
- **[[观察掩码]]**：保留最新 N 轮、其余占位，优于 LLM 总结但上限仍低
- **Ralph 即时上下文加载**：每轮全新，处理规模可远超单次窗口容量

### 路线定位与关联概念

- **压缩派**：[[上下文压缩策略]]、[[compaction双触发模式]]、[[openclaw上下文压缩流水线]]——OpenClaw 路线的"压缩派"解法
- **分类归属**：按 [[上下文缩减卸载隔离三分法]] 的缩减/卸载/隔离三分类，Ralph 的"刷新上下文 + 状态落盘"属于**卸载**路线的极致形态
