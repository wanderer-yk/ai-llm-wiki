# agent-memory 结构化提炼

**agent-memory 结构化提炼**是本文 SubAgent 层的产出传递机制：每个 SubAgent 把关键信息提炼成结构化文件（Agent-Memory），下一个 SubAgent 启动时读取。其核心界定是：**Memory 文件不是对话记录备份，而是"后续步骤需要什么"的提炼**——原样传递对话历史没有意义，上下文一样会膨胀。

## 内容示例

只提炼后续步骤需要消费的结构化关键信息：

- 资源映射表
- 模块结构配置
- 已确认的接口契约

## 落地案例

资源转化 SubAgent 写入资源 ID 映射表 → UI 转化 SubAgent 读取后准确处理引用。这一"写入 → 读取"的接力是转化阶段串行流程（模块生成 → 资源转化 → 业务代码迁移 → UI 转化）的粘合剂（[[两阶段迁移流程]]）。

## 经验原则

第六章将机制原则化为：**Memory 文件要提炼，不要备份**——并且"这条原则在实践中需要反复强化"，说明违背直觉、容易被"多留点信息更保险"的习惯侵蚀。

## 与既有概念的关系

- [[file-as-progress状态持久化]]：同属"用文件承载任务间状态"的路线，本文强调文件内容必须是提炼后的结构化信息
- [[长记忆四件套]]（小红书 PMO）：跨会话长记忆的工程化方案，可与本文的步骤级 Memory 传递做粒度对比
