# 场景/采样两阶段解耦

场景/采样两阶段解耦是 [[ragas]] 测试集生成的核心架构模式：把"出什么题"（场景规划）与"怎么写题"（样本生成）拆分为两个独立阶段——`_generate_scenarios` 负责确定性调度（不调用大模型、只查知识图谱），`_generate_sample` 负责调用 LLM 实际产出题目与答案。该契约由《[[sources/[202605181736]RAG全链路技术详解]]》在评测集生成章节通过自定义 Query Synthesizer 示例代码首次完整披露。

## 两阶段机制

**第一阶段：`_generate_scenarios(n, knowledge_graph, callbacks)` —— 场景规划（确定性）**

- **不调用大模型**，只在知识图谱（KG）上"查地图"；
- 在 KG 中寻找有关系的节点，决定 n 道题分别用哪些节点作为素材；
- 给每道题贴上标签（如：这道题用"正式"风格，由"经理"身份提问）——这正是 [[场景生成]] 四参数（节点 × 查询长度 × 查询风格 × 人设）在代码 API 层的落地；
- 输出一组 Scenario（方案列表）。

**第二阶段：`_generate_sample(scenario, callbacks)` —— 样本生成（LLM 执行）**

- 输入一个 Scenario（包含节点文本、人设、风格等）；
- 把文本和要求塞进 Prompt，调用 LLM，让 LLM 同时返回：问题是什么？标准答案是什么？
- 输出 `SingleTurnSample(user_input, reference_contexs, reference)`——**reference（参考答案）与 reference contexts 在此阶段生成**，补全了"评测集自动生成"链条的最后一环。

## 代码契约（源文示例逐字保留）

```python
from dataclasses import dataclass
from ragas.testset.synthesizers.base_query import QuerySynthesizer

@dataclass
class EntityQuerySynthesizer(QuerySynthesizer):
    async def _generate_scenarios(self, n, knowledge_graph, callbacks):
        """
        这个方法不调用大模型去写问题，它只是在查地图（KG）。
          1. 输入：你想要几道题（n），以及知识图谱（KG）。
          2. 它做的事：
            在 KG 中寻找有关系的节点。
            决定这n道题分别用哪些节点作为素材。
            给每道题贴上标签（如：这道题用"正式"风格，由"经理"身份提问）。
          3. 输出：一组 Scenario（方案列表）。
        """
        return scenarios

    async def _generate_sample(self, scenario, callbacks):
        """
        1. 输入：一个 Scenario（包含节点文本、人设、风格等）。
        2. 它做的事：
          把文本和要求塞进 Prompt。
          调用 LLM。
          让 LLM 返回：问题是什么？标准答案是什么？
        3. 输出：一个 TestsetSample（一道完整的题目）。
        """
        return SingleTurnSample(user_input=query, reference_contexs=contexts, reference=reference)
```

## 设计价值

1. **调度与生成分离**：场景规划是确定性的 KG 查询，可精确控制题型分布与查询空间覆盖；LLM 成本只在样本生成阶段发生。
2. **扩展成本低**：自定义合成器只需继承 `ragas.testset.synthesizers.base_query.QuerySynthesizer` 并实现两个异步方法，即可"完成场景生成以及评测集的产出"。
3. **与查询类型分类联动**：多跳问题生成难度（见 [[ragas查询类型分类]]）由 KG 建边在规划阶段解决，样本阶段只需按 Scenario 串联生成。
