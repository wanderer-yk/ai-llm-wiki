# 分支控制

分支控制是天猫新品营销技术团队在"问题调试"章提出的新建/微调场景版本管理对策：由于 AI 生码是覆盖式的（每次生成直接覆盖既有代码、不产生增量历史），微调阶段必须及时 Commit 存档，否则一次错误修改就可能让此前所有可用的版本全部丢失。

## 原文论证

「AI 生码是覆盖式的，没有及时存档会因为某些错误修改导致代码混乱、前功尽弃」。对于工具自带的回退能力，团队的判断是：「现有生码工具均有一定回退功能，但是不能过于信任」——回退功能是兜底而非依赖对象，主动 Commit 才是第一防线。

## 与迭代型 git 策略的分工

- [[分支控制]]（本概念）：面向新建页面与微调场景，动作是"及时 Commit 保存版本"，解决覆盖式生码的存档缺口；
- [[迭代型需求git版本管理策略]]：面向复杂迭代场景，动作是"多方案对比用分支 / 版本管理用 commit"，解决多方案与回退需求。

## 跨来源对照

与腾讯的[[原子化变更原则]]（一次 Change 一个需求、小步快跑）在"小颗粒提交"上互补：分支控制强调提交时点（覆盖发生前），原子化变更强调提交粒度。
