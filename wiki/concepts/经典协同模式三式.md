# 经典协同模式三式

**经典协同模式三式**是 [[牛潇]] 提出的 [[agent-skills]] 与 [[mcp]] 协同工作的三种经典架构模式。

## 模式1：分层架构

**核心**：Skills 定义 why/what，MCP 提供 how，严格分离关注点。

**四原则**：
1. **关注点分离** — Skills 管业务，MCP 管技术
2. **变更独立性** — 修改部署流程不需要修改 MCP 服务，反之亦然
3. **复用性** — MCP 工具（如 `run_tests`、`upload_to_s3`）具有跨 Skill 复用性
4. **安全与灵活性平衡** — MCP 提供安全边界，Skills 提供业务灵活性

**与 Wiki 关系**：[[skill-command-mcp三层架构]] 是本模式的实践形式。

## 模式2：技能驱动型 MCP

**核心**：Skill 中用条件逻辑动态选择最合适的 MCP 工具。

**条件路由示例**：
```yaml
if data_freshness == 'real-time' → mcp_live_data_feed
if data_volume > 1GB → mcp_batch_processing
if security == 'sensitive' → mcp_encrypted_channel
```

**价值**：最大化灵活性，适应复杂多变业务需求。

**与 Wiki 关系**：[[skill功能聚合]] 是本模式的体现——Skill 作为功能聚合的"说明书"，根据条件动态路由。

## 模式3：MCP 增强型技能

**核心**：MCP 工具基于历史数据分析+ML 推荐最优工作流，形成闭环学习系统。

**实现**：`SkillEnhancementMCP` 类的 `get_optimal_workflow` 方法，通过 `analytics_db.get_task_metrics` 获取历史数据 + `recommender.predict_optimal_workflow` 推荐最优流程。

**价值**：数据驱动的自我优化，Skills 定义随数据进化。

**与 Wiki 关系**：[[数据自迭代]] 是本模式的理念先驱——AI 质检+数据反馈驱动的持续自我优化闭环。

## 开放问题

- 模式3 闭环学习系统的实际落地效果（推荐准确率、学习收敛速度）缺少量化数据
- 三种模式之间的选择标准未明确说明（何种场景选哪种模式）
