# 评估图（Evaluation Graph）

评估图是 [[AssistantAgent]] 评估模块（Evaluation）中用于**多层次意图识别**的核心结构：以有向图方式组织多个评估项，通过 `dependsOn` 声明前置依赖，系统自动构建评估图并按拓扑执行——无依赖项并行、有依赖项顺序执行、后续评估项可访问前置评估项的结果；评估结果（五种类型）汇聚为评估上下文，传递给 [[PromptBuilder条件化动态组装]] 驱动动态 Prompt 组装。

## 双层并行结构

| 层级 | 执行方式 | 评估项 | 输出 |
|------|---------|--------|------|
| 输入 | — | 用户输入（示例："查询今日订单"） | 原始 Query |
| Layer 1 | 并行执行 | 是否模糊？（清晰/模糊）；输入改写（增强） | 模糊标记 + 改写后内容 |
| Layer 2 | 基于改写内容，并行执行 | 检索经验（有/无）；匹配工具（有/无）；搜索知识（有/无） | 三维评估结果 |
| 整合 | 汇聚 | 整合不同维度评估结果 → 传递给后续模块 | 评估上下文 |

Layer 1 回答"输入是否清晰并改写增强"，Layer 2 在改写后内容上并行探测三类资源可用性（经验/工具/知识），直接决定后续 Prompt 组合路由与执行策略。

## 双评估引擎

- **LLM 评估**：支持自定义 `customPrompt` 或默认组装，可配置 `description`、`workingMechanism`、`fewShots`。
- **Rule-based 评估**：自定义 `Function<CriterionExecutionContext, CriterionResult>` 规则函数，适合阈值检测、格式校验、精确匹配等无需模型推理的场景。

## 五种评估结果类型

`BOOLEAN` / `ENUM` / `SCORE` / `JSON` / `TEXT`——统一传递给 Prompt Builder 作为条件匹配依据。

```java
// Rule-based 评估：用户自定义规则函数
Function<CriterionExecutionContext, CriterionResult>
// 依赖声明：评估项前置依赖
dependsOn
// 评估 Prompt 自定义配置项
customPrompt; description; workingMechanism; fewShots
// 评估结果类型
BOOLEAN | ENUM | SCORE | JSON | TEXT
```

## 与既有概念的关联

- Layer 1 的"输入改写（增强）"与 [[Query改写]]（多轮补全/指代消解/长文摘要）同构；"是否模糊"判断与 [[意图规划]] 的意图识别思路同族。
- Layer 2 的三维探测（经验/工具/知识）将 [[经验学习与快速响应]]、[[CodeactTool工具体系]]、[[多数据源统一检索]] 的可用性前置为结构化评估，是"先评估后执行"的确定性设计。
- 未见披露：经验检索命中/未命中如何影响 Layer 2 与 Prompt 组合的完整联动细节。
