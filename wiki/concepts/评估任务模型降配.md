# 评估任务模型降配

评估任务模型降配是 Skill 评测的成本优化策略：将评测流水线中低复杂度环节（如触发检测）从高阶模型（Opus 级）切换到轻量模型（claude-haiku），在不损失任务质量的前提下大幅降低成本。

## Issue #514 的实证背景

GitHub Issue #514 揭示 [[skill-creator]] 的成本问题根源：SKILL.md 第 385 行指示 `run_loop.py` 使用 `--model <session-model>` 透传会话模型，导致 20 个评估查询 × 3 次运行 = **60 个并发 Opus 级会话**，单次优化循环消耗约 69% 的 5 小时配额、产出 0 条可执行结果。

## 降配方案与量化收益

社区建议将 eval 默认模型改为 claude-haiku：**成本降低 10-20 倍，触发检测精度等价**。机制依据：触发检测本质是"是/否"二元信号，不需要 Opus 级推理能力。截至成文（2026-05）Issue 仍处 Open 状态，修复建议上游未采纳。量化口径（"10-20 倍"）为社区数据，登记 [[ai工程量化效果声明追踪]]。
