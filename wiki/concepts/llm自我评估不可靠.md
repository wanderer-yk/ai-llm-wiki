# LLM 自我评估不可靠

LLM 自我评估不可靠是《从 ReAct 到 Ralph Loop》一文的根因诊断：AI 编程助手的四大困境——过早退出、单次提示脆弱、重新提示成本高、上下文断裂——共同根因是 LLM 在**主观认为"完成"时退出，而非达到客观可验证标准**。模型的"我觉得做完了"与任务的真实完成状态之间存在系统性偏差。

## 由此推出的工程结论

1. 退出判定权必须外置（[[循环控制外部化]]）
2. 完成标准必须机器可验证（[[机器可验证完成条件]]）
3. 外部信号必须强制拦截退出（[[stop-hook拦截机制]]）

## 跨来源互证

- [[llm不确定性物理不可消除]]：LLM 输出的不确定性无法从物理上消除，只能通过工程手段约束——本文是"用外部循环约束不确定性"的实例。
- [[reflection模式]]：反思机制（Reflexion/Self-Refine/CRITIC）同样建立在"自我评估有局限、需外部信号校准"的前提上，两条脉络方向一致。
- 与 [[反馈循环护栏]] 的论断呼应：没有客观反馈时，Agent 产出"看起来正确但实际有问题"的代码。
