# 业务 diff 等价物

由 vivo [[ding-junjie]] 提出，是 [[agent-canvas沙盘机制]] 四步路径的第三步。核心思想：为缺乏 git diff 的业务世界**人为构造变更对比能力**。

## 问题定义

代码世界有 git diff 天然支持变更追踪，但业务世界（广告计划、价格规则、listing、库存策略、审批版本等）天然缺乏这种能力。如果"无法知道到底改了什么"，Agent 在业务场景中的审阅、审批和回溯就失去了基础。

## 解决方案

为每类业务对象构造变更前后对比：

- **广告计划**：投放策略/预算/定向人群的改前后对比
- **价格规则**：促销规则/折扣力度的改前后对比
- **Listing**：标题/描述/图片/属性的改前后对比
- **库存策略**：备货量/安全库存/补货规则的改前后对比
- **审批版本**：每次审批提交的完整快照与差异标注

## 与 Wiki 其他概念的关系

- 与有赞 Code Insight 的 [[影响范围分析]]（基于 AST+符号表的代码变更影响推导）同属**变更可追溯性谱系**——前者针对业务配置变更，后者针对代码结构变更。
- 与 [[agent可观测性六维度]] 中的"step"维度（每一步做了什么）形成互补——diff 等价物关注"改了什么"，可观测性关注"正在做什么"。
