# 跨系统数据关联机制

跨系统数据关联机制是天猫品牌行业前端团队 [[三层ai-coding度量体系]] 中结果指标的**基础设施前提**：以 `(repo_project, branch)` 为关联键，打通 AI 编码平台任务数据与内部迭代/需求系统，使"追踪终点延伸到代码合并上线"（[[追踪终点延伸论]]）从理念落到实现。

## 数据流程（三步）

1. AI 出码完成后**实时上报 Diff**
2. 发布记录 **T+1 同步**
3. **定时任务**匹配计算采纳率

## Diff 端实现

- **Merge Commit 识别**：发布记录中的 `repo_commit_id` 通常为最后一次提交，需通过 GitLab API 向后查找第一个标题包含 "Merge commit" 的提交，以获取功能分支合入主分支的全部变更
- **规范化比对**：去除注释、合并空白、统一引号和分号风格后逐行比对，消除格式差异误判
- **多次出码合并**：同一 `(repo_project, branch)` 下所有 AI Diff 记录合并后再比对（详见 [[代码采纳率]]）

## 已知边界与开放问题

- `(repo_project, branch)` 关联键在多分支、跨需求场景下的匹配边界文中未讨论
- Merge Commit 标题匹配在 squash merge、rebase 等非标准合并方式下的鲁棒性存疑
- 规范化比对对重命名、重构、移动等非格式性修改的判定能力未说明（"逐行比对"无模糊匹配容差）

该机制支撑 [[需求覆盖率]] 与 [[代码采纳率]] 两项结果指标的计算。
