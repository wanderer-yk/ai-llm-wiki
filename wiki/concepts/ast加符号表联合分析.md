# AST加符号表联合分析

抽象语法树（AST）与符号表（Symbol Table）结合的代码结构化分析技术，是 [[向量检索rag|RAG]] 路径的关键互补方案。两者各有所长，联合使用可构建完整的[[调用关系图谱]]。

## AST 的作用与局限

**作用**：解析程序骨架结构，明确"哪里调用了某个函数"，提供函数调用关系。

**局限**：无法定位标识符的定义位置与参数类型信息。

## 符号表的作用

符号表作为标识符的"注册表"，记录以下信息：
- 名称
- 类型
- 作用域
- 定义位置

符号表补全了 AST 无法提供的定义定位与参数信息缺口。

## 联合分析成果

AST + 符号表联合分析可构建[[调用关系图谱]]，实现：
- 精准[[影响范围分析]]：代码修改后自动推导受影响的上游调用链路和 API 接口
- 跨方法链路追踪：如 method3→method5→method1→Dubbo API 的完整调用链
- 测试用例影响面评估：推导受影响 API 接口后结合大模型生成[[测试用例生成|测试用例]]

## 与 RAG 的互补关系

| 维度 | RAG | AST+符号表 |
|------|-----|-----------|
| 擅长 | 语义理解、少量文件检索 | 结构化分析、调用链追踪 |
| 瓶颈 | 跨文件/调用链分析 | 语义理解 |
| 适用 | 代码问答、语义搜索 | 影响范围分析、调用链生成 |
