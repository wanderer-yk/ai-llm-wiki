# 垂直化业务评测集

垂直化业务评测集（文中正式命名“垂直化评测基准”）是 [[天猫品牌行业前端团队]] 为“真实有效地反映特定业务场景的 AI 生码能力”而构建的离线评测基准：数据全部来自真实历史需求，评测维度针对具体业务场景设计，核心目标是真实反映“我们的组件库、我们的业务场景、我们的代码规范”下的 AI 生码能力。整体结构借鉴 SWE-bench（评测数据集 + 评测方法 + 排行榜）但做业务定制。

## 通用基准三缺陷（中后台前端场景）

1. **多解性**：同一需求存在多种等价实现；
2. **测试成本高**：交互类需求难以自动化验证；
3. **过程盲区**：只看结果，不看 Agent 是否查阅正确资料。

## 与 SWE-bench 对比

| 组成部分 | SWE-bench | 垂直化评测基准 |
|---|---|---|
| 评测数据集 | 2294 个 GitHub Issue（Python 后端） | 真实历史需求（针对特定业务场景） |
| 评测方法 | 测试通过即正确（二元判定） | 复杂度矩阵 + 量化评分（结果分 + 行为分） |
| 评测工具 | 测试执行框架 | LLM as Judge + 代码采纳率计算 |

## 评测基准五步设计法（可迁移）

明确评测目标 → 选择核心维度 → 构建数据集 → 设计评分模型 → 建立对比基线。作者声明无论何种场景均可按此框架设计自己的评测基准。

## 组成落地

- **数据集**：60 个真实历史需求用例，覆盖 9 象限，逐例人工审核，质量优先于数量。
- **评测方法**：[[复杂度矩阵]]（主维度定分格）+ [[结果过程双视角评分模型]]（次维度定打分）。
- **评测工具**：[[llm-as-judge]]（逐 refAnswer 0/0.5/1 三档语义评分）+ 代码采纳率计算。

## refAnswers 评分点机制

每个评测用例含若干 refAnswers（参考答案点）；代码规范要求、上下文依赖程度等非主维度不进入矩阵，而是作为 refAnswers 的评分点体现——“主维度定分格、次维度定打分”的分层设计。

## testCases 客观验证补充

有测试覆盖的场景（数据处理逻辑、API 调用验证）可配置 testCases 作为客观验证补充，与 LLM 评分加权融合（融合权重未披露）。

## 可信度

LLM 评分主观性经 [[评测可信度保障四机制]]（人工抽检一致性 > 90% 等）工程对冲。
