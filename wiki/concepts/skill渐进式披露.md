# Skill 渐进式披露

Agent Skill 的三级 Progressive Disclosure 设计：知识按需加载而非全量注入上下文。

## 三级结构

1. **description 索引**：YAML frontmatter 的 `description` 字段，常驻系统提示词，作用类似索引——含"干什么用/核心能力/什么时候触发"三层信息，命中才加载；可同时挂载几十个 Skill，激活判断成本仅为几十行短文本比对。
2. **SKILL.md 正文**：核心指令、工作流程、关键示例，激活后读取。
3. **references/ 与 scripts/**：详细文档与可执行脚本，仅在执行过程确实需要时查阅/调用。

## 设计动机（双论点）

- **Token 效率**：不把所有知识塞进上下文，避免信息过载。
- **注意力聚焦**：注意力随上下文变长而衰减，各阶段只关注最相关信息。总结章进一步定论：渐进式披露不仅节省 Token，**更重要的是提升注意力分配效率**。

## 多层渐进模式

编写层面的具体手法：SKILL.md 只放主干，详细文档放 `references/` 并在正文中明确路径引用，保证 Agent 知道资源存在但不全量加载——与三级披露形成完整闭环。确定性逻辑则进一步下沉到脚本（见 [[skill脚本自动化原则]]）。

## 跨来源印证

"注意力即稀缺资源"与 [[上下文工程]]、[[极简agent设计哲学]]（代码简洁性 = 上下文清晰度）、有赞 [[渐进式披露替代向量检索]]（目录结构即检索路径，零基建依赖）多来源趋同。
