# 手册执行者模式

手册执行者模式是 [[sop-doc可召回排查文档]] 范式的执行侧配套约束：主 Agent 被明确定位为**“手册执行者”而非“诊断专家”**——召回的排查手册（SOP Doc）是唯一真理来源，Agent 的价值在于忠实、透明、可核查地执行手册，而不是凭借模型自主知识自由发挥。

## 四硬约束

1. 禁止跳步；
2. 禁止改序；
3. 禁止加步；
4. 手册为唯一真理来源（禁止自主知识替代）。

## 执行规范要求

- 执行透明化：执行过程需标注（如【执行手册第X步】）；
- 思考透明、条件判断显式化；
- STEP 1 知识库解析为必做步骤，收不到 `${REFERENCE_DOC}` 则立即停止；
- 无匹配文档时按固定话术转人工：“抱歉，这个问题我无法回答，请联系值班同学”。

## 设计—评估闭环

[[评分agent坏样本聚焦]] 的扣分明细项——“跳步执行”“引用过时文档”“未按手册顺序操作”——与上述硬约束**一一对应**：手册执行者模式的约束即是评分标准的度量对象，两概念构成完整的设计-评估闭环。这与 [[验证门禁化]]（vivo）、[[harness四强制约束]] 同属“硬约束 + 违规可度量”概念家族。

## 主 Agent 提示词结构

源文记载主 Agent 提示词重构包含“四硬约束 + 三步工作流 + 六段回答格式”，完整提示词原文在存档中部分截断，可确认的要点即上述四硬约束与执行规范；三步工作流与六段回答格式的逐字内容待补。
