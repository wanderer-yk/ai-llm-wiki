# Agent 生产落地四层框架

由 vivo [[ding-junjie]] 在《[[sources/[202604152000]OpenClaw落地到生产实际应用的一种可能的路径]]》第三章提出，将 [[coding-agent四特征]] 从"代码环境的天然属性"转化为"业务世界的工程化构建目标"。核心论断：**Agent 生产落地的关键不在于模型能力提升，而在于将开放、分散、难回滚的业务执行环境重构为具备四层能力的操作空间**。

## 四层框架

### 可视化层
让 Agent 在做什么、为什么做、依据什么、产出物是什么、谁审批的、执行到哪一步——全部透明可见。目的不是"好看"，而是建立最基础的控制感。

### 封闭层
将开放世界中模糊的业务任务重构为边界明确的执行单元——**工作单元封装**：明确输入/输出、可访问系统、可操作对象、审批节点、状态门控。封闭层缺失则 Agent 只能停留在"辅助建议"阶段，无法进入"自主执行"。

### 验证层
回答"凭什么算通过"的问题。需垂直领域自建 gate，场景化差异显著：
- **软件**：CI/test/code review
- **电商**：规则校验/库存校验/预算校验/沙盘预跑/人工审批
- **运营**：投放限制/品牌规范/灰度放量

验证层无 gate 则系统"只有执行，没有交付"。详见 [[验证门禁化]]。

### 回滚层
最容易被忽略但最决定生产可用性的部分。**恢复稳定状态**不是简单的"撤销上一步"，而是一套复合能力：推迟执行、灰度放量、补偿动作、版本快照、沙盘预跑、退回待修改状态。业务动作（改价格/投广告/发促销）一旦执行，影响已扩散到转化/预算/库存/用户体验/品牌感知，**业务环境不可逆性**使其无法简单回滚。

## 从四层到六条件

总结章将四层框架进一步凝练为 **Agent 生产环境六条件**：

1. 任务和沟通**可视化**
2. 权限与边界**相对封闭**
3. 执行结果**可以验证**
4. 高风险动作**可以推演**（新增，对应沙盘机制）
5. 失败结果**可以回滚/补偿/打回**
6. 所有变化**都有产物、有历史、有责任归属**（新增，对应审计追溯）

## 核心风险论断

> "如果没有把环境改造好，Agent 越强，风险反而越大。"
> "多 agent 编排、角色分工、调 prompt、换模型，最后都只是把更强的执行能力放进一个没有护栏的环境里。"
