# 回复渠道路由（Reply Channel）

回复渠道路由（Reply Channel）是 [[AssistantAgent]] 的多渠道回复模块：Agent 产出的回复经"回复渠道路由"分发至不同落地端，支持**同步 + 异步**双模式；回复动作为**配置驱动**动态生成的工具（如 Agent 主动调用 `send_message(text="分析结果.")`），无需为每个渠道编码。扩展渠道需实现 `ReplyChannelDefinition` SPI（方法签名原文未披露）。

## 四类渠道（正文长名为准，图内短名备注）

| 渠道标识 | 回复形式 | 落地端 |
|------|------|------|
| DEFAULT | 文本回复 | 控制台终端回复 |
| IDE_CARD | 卡片展示 | IDE 富文本卡片 |
| IM_NOTIFICATION（图内短名 IM_NOTIFY） | 消息推送 | IM（钉钉/飞书/企微，可扩展） |
| WEBHOOK_JSON（图内短名 WEBHOOK） | JSON 推送 | 第三方系统 |

## 六项核心能力

1. 多渠道路由；
2. 配置驱动：动态生成回复工具，无需编码；
3. 同步 + 异步支持；
4. 统一接口；
5. 内置 `IDE_TEXT` 演示渠道；
6. `ReplyChannelDefinition` SPI 扩展。

## 开箱即用面很薄

内置渠道仅 `IDE_TEXT`（演示用）；`IDE_CARD`、`IM_NOTIFICATION`（钉钉/飞书/企微）、`WEBHOOK_JSON` 均需用户通过 `ReplyChannelDefinition` SPI 自行实现——即渠道扩展成本在用户侧，框架提供的是路由机制与统一抽象。

## 与既有概念的关联

- "同步 + 异步双模式"与 [[即时响应到异步交付]]（AI 系统从同步问答向异步任务交付演进）互相印证。
- 与 [[openclaw-channel架构]]（OpenClaw 的多端 channel 架构）为跨框架比较候选：二者都将"渠道"抽象为可扩展的接入层，差别在于 OpenClaw 以 IM 平台双向对话为中心，Assistant Agent 以助手回复的分发与推送为中心。
