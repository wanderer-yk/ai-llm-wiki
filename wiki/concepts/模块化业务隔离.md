# 模块化业务隔离

## 定义

模块化业务隔离是 [[mcp-server-ts]] 框架的核心设计原则之一：将所有功能拆为独立模块，开发者仅需在指定文件（`tools/` 目录）编写业务逻辑即可创建 MCP 服务，核心协议层文件无需修改。

## 实现方式

在 mcp-server-ts 中，模块化隔离通过目录结构实现：

- **业务层**（`tools/index.ts` + `tools/mockFunc.ts`）：工具入口和具体工具实现，开发者在此编写业务逻辑。
- **协议层**（`index.ts` / `stdio.ts` / `streamableHttp.ts` / `sse.ts`）：处理不同传输协议的配置和入口分发，开发者无需修改。
- **公共层**（`server.ts`）：三模式共享的服务创建和 tools 注册入口。

作者明确指出："各自模块就是调用 SDK 配置域名等操作，代码过长不展示了，但是这几个文件不用动。"

## 价值

降低 MCP 使用门槛，使不熟悉 MCP 协议细节的开发者也能快速创建服务。这与 [[多协议mcp-server框架]] 的设计目标一致——将协议复杂性与业务逻辑解耦。
