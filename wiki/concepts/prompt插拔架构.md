# prompt 插拔式架构

prompt 插拔式架构是本文第三部分提出的方法论：prompt 形式上是文本，**本质是给 LLM 执行的"代码"**，因此 prompt 设计需要功能抽象、模块设计、架构设计——"Prompt 设计就是'架构设计'"。目标是框架 prompt 统一运维、高度复用，业务定制部分极度灵活。

## 方法论四步

抽象场景 → 规划核心功能 → 沉淀专有 prompt → 开放业务定制部分

## 四个核心功能节点（agent）

- 意图识别
- 工具推理
- 反思推理
- 交互反馈

（注：另一处正文将节点记为"意图识别、工具推理、ReAct推理、总结交互"，疑同指，命名口径待统一。）

## 产品化落地

四套场景解决方案固化为四套模版，核心 agent 节点均"内置框架 prompt + 开放业务定制架构"，以此构建 [[智空间]] 的 [[助手市场]] 产品能力。以意图识别核心 Agent 为例的完整双层契约见 [[意图识别双层prompt结构]]。
