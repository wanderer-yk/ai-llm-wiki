# 多数据源统一检索（Knowledge Search）

多数据源统一检索是 [[AssistantAgent]] 的知识检索模块（Knowledge Search）：在统一检索接口下**并行**查询四类 Provider，结果经**聚合排序后前置注入 Prompt**（而非工具按需召回），支持可配置排序策略；业务价值为：企业知识库准确答案、答案溯源、降低人工客服压力。

## 四类 Provider

| Provider | 定位 | 覆盖内容 |
|---|---|---|
| 知识库 Provider | 主要 | FAQ/文档、历史问答、团队笔记 |
| 项目 Provider | 可选 | 源代码、配置文件、日志 |
| Web Provider | 可选 | 网络文章、技术论坛 |
| 自定义 Provider | SPI | 实现 `SearchProvider` 接口 |

`SearchProvider` SPI（包路径 `com.alibaba.assistant.agent.extension.search.spi`）含 `supports()` / `search()` / `getName()` 三方法，加 `@Component` 注解自动注册，返回 `List<SearchResultItem>`（完整 Java 示例见来源页）。

## 默认配置（原文逐字）

```yaml
spring:
  ai:
    alibaba:
      codeact:
        extension:
          search:
            enabled: true
            knowledge-search-enabled: true   # 知识库（默认 Mock 实现）
            project-search-enabled: false    # 项目代码（默认 Mock 实现）
            web-search-enabled: false        # Web 搜索（默认 Mock 实现）
            default-top-k: 5
            search-timeout-ms: 5000
```

- 三类数据源中**仅知识库检索默认开启**，项目与 Web 检索默认关闭。
- 默认实现均为 Mock，仅供演示测试；生产环境需实现 `SearchProvider` SPI 接入真实知识源（向量数据库、Elasticsearch、企业知识库 API 等）。
- 检索可用性由[[评估图|评估图 Layer 2]]的"搜索知识（有/无）"探测，决定 Prompt 是否注入知识片段。

## 与既有概念的关联

- "聚合排序后前置注入 Prompt"属**前置知识注入路线**，与有赞 [[静态动态双路径知识注入]]（静态信息写向量库 + 动态信息实时查询的双路径）互为参照。
- 可配置排序策略与 [[知识优先级机制]] 同为多源知识冲突治理手段，但聚合排序的具体策略与多 Provider 结果冲突裁决机制原文未披露。
- "Mock 默认 + SPI 生产切换"与有赞 [[三阶段平台演进路线]]（验证期 → 成长期 → 成熟期）同构，均属渐进式平台/能力演进策略。
