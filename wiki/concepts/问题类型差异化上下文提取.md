# 问题类型差异化上下文提取

[[六步智能提示词生成法]]第三步的核心策略。`ContextExtractor` 根据 Sonar 问题类型差异化配置提取策略，核心洞察为**不同问题类型对上下文的需求差异巨大**。

## 提取策略

| 问题类型 | 提取范围 | max_lines | 含 imports | 含类声明 |
|---------|---------|-----------|-----------|---------|
| NullPointer（空指针） | full_method | 150 | ✓ | ✓ |
| ResourceLeak（资源泄露） | full_method | 100 | ✓ | ✓ |
| SQLInjection（SQL注入） | full_method | 120 | ✓ | ✓ |
| NamingConvention（命名规范） | surrounding | 30 | ✗ | ✗ |
| General（通用） | surrounding | 50 | ✗ | ✗ |

高风险问题（空指针/资源泄露/SQL注入）需要完整的方法体、imports 和类声明以理解数据流和依赖关系；低风险问题（命名规范/通用）仅需问题行周围代码即可定位和修复。

## 降级机制

AST 解析失败时优雅降级：回退到问题行前后各 25 行的周围代码提取。超长上下文硬截断并附加"后续代码省略"注释。

## import 提取

硬编码扫描文件前 50 行提取 import 语句，确保高风险问题的依赖信息完整。

## 跨源关联

与有赞 [[ast加符号表联合分析]]（[[code-insight]]）互补：有赞侧重构建调用关系图谱做影响范围分析，本策略侧重方法级上下文精准提取用于提示词生成。两者都体现了 [[上下文工程]] 的核心思想——精准注入而非全量灌入。
