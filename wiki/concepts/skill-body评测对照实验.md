# Skill Body 评测对照实验

Body 评测的核心方法：**有/无 Skill 的对照实验**，四步法：

1. **设计 2-5 个测试任务**，须满足三特征：覆盖核心能力、输出可判断、复杂度接近真实。
2. **实验组/对照组双跑**：唯一变量是 Skill 有无或版本。
3. **看结果之前先定义评判标准**（避免结果影响标准）：客观标准脚本化（JSON schema 校验/字段存在/结构要求），主观标准清单化；写作风格、设计审美类高度主观 Skill 不必勉强定义细粒度标准，整体判断更有效。
4. **评分和对比**：逐用例翻看两组输出，记录三类数据（见下）。

## 输出目录结构（逐字保留）

```
eval-workspace/
├── iteration-1/
│   ├── test-case-auth-module/
│   │   ├── with-skill/
│   │   └── baseline/
│   ├── test-case-api-refactor/
│   │   ├── with-skill/
│   │   └── baseline/
│   └── ...
```

## Step 4 评分记录三类

1. **客观检查项的通过情况**：跑脚本，统计通过率。
2. **主观判断和具体反馈**：哪里好、哪里差、哪里出乎意料——反馈必须具体可执行："输出不够好"无行动指引，"遗漏 SQL 注入风险，建议增加 OWASP Top 10 检查清单"才指导改进。
3. **效率数据**：如可获取，记录 token 消耗和响应时间——质量提升不得以不可接受的效率代价为前提。

## 结果判断与对照组选择

最终判断须**维度化**：明确 Skill 版本在哪些维度比基线好/持平/退步（三态）。对照组选择取决于要回答的问题：新建 Skill → 对照裸跑（证明存在价值）；改进 Skill → 对照旧版（证明正向提升）。独立评分方的思路与美团 [[高阶模型审查低阶模型]]（Judge Model）同构。流程化封装见 [[skill迭代闭环]]。
