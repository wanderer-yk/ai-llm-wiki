# Skill 迭代闭环

Skill 开发的五步循环流程（每轮迭代，逐字保留）：

1. **跑对照实验**：在新的目录下同时跑所有测试用例的实验组和对照组。
2. **评分**：客观指标跑脚本，主观维度人工判断。
3. **分析反馈**：哪里好了、哪里退步了、哪里还不够。
4. **改 Skill**：基于反馈修改 SKILL.md 或脚本，遵循改进原则（[[skill改进四原则]]）。
5. **重跑**：用完整评测集验证改动效果。

## 对照组选择策略

- 新建 Skill → 对照裸跑，证明存在价值。
- 改进 Skill → 对照旧版，证明正向提升。

## 终止条件

反馈趋于空白 / 无更多改进手段 / 质量满意——**不追求完美**。Skill 如代码可持续迭代：实际使用中收集新的失败 case，随时回来改。

## 跨来源定位

本闭环是 [[skill评测三原则]] 的流程化落地，也是有赞 [[agent评测四要素]]（评测对象/数据集/指标/反馈闭环）中"反馈闭环"要素在 Skill 工件的完整实例。
