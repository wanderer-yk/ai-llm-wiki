# CLI 录制回放生成

CLI 录制回放生成是 [[opencli]] 框架中 `opencli record` 命令的自动化能力：采用「浏览器录制 - 智能回放」模式——启动浏览器后，捕获用户在目标 URL 上的交互行为及产生的网络请求；系统通过对请求序列进行评分排序与语义分析，自动生成可复用的 CLI 命令。它是继人工探索工作流（[[agent浏览器探索七步工作流]]）与 AI 原生生成流程之后，第三条将网站能力固化为 CLI 的路径。

## 当前局限性（源文档自述，原样要点）

- **请求体（Payload）缺失**：目前的录制引擎仅捕获请求元数据（url, method, body: responseBody），未能完整提取 POST/PUT 等写操作中的 Request Body。
- **生成能力受限**：由于缺乏关键参数载荷，自动化脚本生成逻辑目前仅能覆盖只读类接口（如列表查询、详情获取并输出 YAML），无法有效支撑写操作类接口（如创建、更新、删除）的命令生成，导致自动化闭环在「写入场景」中断。

## 意义

1. **罕见的诚实披露**：来源主动披露自身工具的硬边界（写路径断裂），这是该来源中对自身最不利也最可信的陈述，引用该工具能力时必须同时携带此边界条件。
2. **读写闭环是分水岭**：只读接口可由录制自动生成，写操作目前需回退到手工 TypeScript 适配器；文中「帮我和候选人沟通」类案例（疑似写操作）的实际实现机制来源未明说，属隐含断点。
3. **与可调用性论断的张力**：[[软件竞争可调用性]] 愿景要求软件能被 Agent「稳定调用、验证、接进工作流」，而录制能力的读写断裂说明「调用面」的自动发现尚不完整——愿景与当前工程能力之间存在待收敛的差距。

## 互补关系

- 与 [[opencli五级认证策略]]：录制产物仍需按鉴权层级归类固化。
- 与 [[api优先浏览器自动化]]：录制是「API 优先」理念的自动化放大器，但受懒加载与 Request Body 缺失约束，不能替代主动探索。
