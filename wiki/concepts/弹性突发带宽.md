# 弹性突发带宽

弹性突发带宽是 [[tair]] 云原生架构的带宽弹性机制：当瞬时流量超过固定带宽时，系统**秒级自动扩展带宽**（单节点最高可达 288MB/s），流量回落后自动回收，按实际突发量计费；开启和关闭均不影响实例正常访问。该机制针对的是"带宽先于 CPU/内存成为瓶颈"的 Agent 类大对象读写场景。

## 为什么 Agent 场景需要带宽弹性

AI Agent 每次记忆读取涉及对话历史和业务上下文的传输，单次请求的数据远大于传统缓存场景中的简单 KV 读写。在业务高峰期（如千问春节红包活动），带宽很大可能先于 CPU 和内存成为瓶颈——出现"带宽侧的木桶效应"。

## 两层弹性机制

1. **集群带宽水平扩展**：通过增加 LB 数量扩展实例总带宽，单个 LB 带宽上限 20Gbps；分片数超过 8 个时可按需新增 LB，新增过程中不断开现有连接。
2. **弹性突发带宽**：以**分片为粒度**独立生效——某分片因热点 Key 出现带宽瓶颈时，仅该分片的带宽被自动扩展，不影响其他分片；既精准应对热点，又避免为全集群扩容的成本开销。

## 成本逻辑

相比提前购买高规格的固定带宽包，按需突发在成本上更省，特别适合 Agent 场景中不可预测的流量尖峰。（注：288MB/s 等参数为 Tair 团队自报，引用时应标注来源立场。）

## 关联

弹性突发带宽与 [[tair无感扩缩容]] 共同构成 Tair 应对 Agent 流量洪峰（如春节 10 倍峰值）的弹性方案：前者解决带宽维度瓶颈，后者解决吞吐与容量维度扩展。
