# 静默决策显性化

静默决策显性化指通过结构化 Trace 链路，将 Agent 在既有规则约束下做出的"看似异常、实为合规"的静默决策显性化，从而与真正的系统故障区分开，防止团队在 Prompt 上盲改或错误怀疑模型能力。这是《OpenClaw-Observability》"Done"案例复盘提炼出的核心教训。

## Done 案例五步链路还原（原文）

1. 识别需求平台链接
2. 提取项目 ID 和需求 ID
3. 内部规则判断（群聊无明确提问不应过度打扰）
4. 意识到无法访问企业内网
5. 选择简短回复（"Done"）

## 结论

**不是系统坏了、不是模型没理解，而是 Agent 在既有规则约束下的决策。** 若无结构化链路，团队只会在 Prompt 上盲改或怀疑模型能力；Trace 视图（[[观测三视图]]）使该案例"十秒定性"（自报口径）。

## 与可观测三目标的关系

对应 [[可观测三目标]] 中"说得清"的四类归因问题之一——"Prompt 约束触发静默策略"。归因框架的其余三类：模型选错工具、工具返回格式异常、上下文截断丢失关键信息。

## 价值主张

"不是让我们看到更多信息，而是更快地看到真正有效的信息"——可观测的价值在于更快定位有效信息，而非信息堆砌。
