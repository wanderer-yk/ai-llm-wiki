# 三层架构管住 AI 输出

**三层架构管住 AI 输出**是三石在 [[百度Geek说]]《网盘存量代码迁移实战》中提出的 AI 工程化分层方案：用 Skill 保证单点执行稳定（执行层）、用 SubAgent 控制长链路上下文膨胀（调度层）、用 Agent Team 支撑多类型任务并行（协作层）。三层的定位是"分层互补而非替代关系"——各自解决不同层次的问题，共同回答导读框三问：怎么稳定执行、怎么调度不失控、怎么协作提效。

## 层级定义

| 层级 | 技术 | 解决 | 位置 |
|------|------|------|------|
| 执行层 | Skill | 单点执行不稳定 | 所有具体任务的执行单元 |
| 调度层 | SubAgent | 长链路上下文膨胀 | 转化阶段的串行步骤调度 |
| 协作层 | Agent Team | 多类型任务串行效率低 | 提取阶段的并行分工 |

## 核心论断

- 整个方案的稳定性最终由 Skill 的规范质量决定，SubAgent 与 Agent Team 只是调度骨架（[[skill稳定性决定论]]）。
- 三层如何组合由唯一判据决定：任务之间有没有强依赖（[[强依赖选型判据]]）。
- 落地为两阶段迁移流程：提取阶段 Agent Team 四路并行，转化阶段 SubAgent 串行 + Memory 传递，Skill 兜底每个节点（[[两阶段迁移流程]]）。

## 与既有概念的关系

该架构是 [[工程结构优先论]]（"不仅靠更好的 Prompt，还需要一套能管住它的工程结构"）的具体化，与爱奇艺 [[harness-engineering]]（五要素工程化约束）和得物 [[约束非能力论]] 同主题域互证：都在用工程结构而非模型能力来管住 AI 输出。
