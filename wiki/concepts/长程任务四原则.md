# 长程任务四原则

百度Geek说《Harness Engineering》的核心原则层，与 [[长程任务三困难]] 一一对应，也是导读"四大核心设计"（任务拆解、并行执行、File As Progress 状态持久化、多层重试）的正文表述。

| 原则 | 对应困难 | 作用维度 | 落地技巧 |
|------|---------|---------|---------|
| **任务拆解** | 上下文耗尽 | 效果（控制复杂度）：大任务拆成单次会话可独立完成的子任务 | 6.1 任务粒度 |
| **并行执行** | 速度瓶颈 | 速度（压缩耗时） | 6.2 CLI 化并发调度 |
| **可续传** | 中断要重来 | 成本（消除沉没成本）：进度持久化到会话之外 | 6.3 File As Progress + 6.4 状态设计 |
| **有完成条件** | 行为不可控 | 效果（保障可信度）：明确且可程序化检查的成功标准；失败在当前 session 修复，设定修复轮次与停止边界（Retry 上限），标记 FAILED | 程序化产出物判定 |

四原则在 7.1（全量 Code Review）与 7.2（JS to TS 迁移）两个真实场景中获得完整落地映射，形成"理论→实践复现"闭环。
