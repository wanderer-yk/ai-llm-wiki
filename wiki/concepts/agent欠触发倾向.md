# Agent 欠触发倾向

来源给出的两个触发机制事实，解释了为什么 Skill 评测必须以"欠触发为默认假设"：

1. **Agent 基于自我能力评估决定是否找 Skill**：只在觉得自己搞不定时才去找 Skill——简单任务即使 Description 完美匹配也不会触发。
2. **Agent 天生偏向 under-triggering**：因此 Description 要主动把边界往外推（如 Figma 示例中显式列出"当用户上传 .fig 文件、要求设计规范/组件文档/设计转代码交付时使用"）。

## 对评测的推论

- **测试用例必须足够复杂**：否则测的是任务难度而不是 Skill 触发——Agent 不求助不是因为没匹配上，而是因为自认能搞定。
- 触发评测中"漏触发居多"时的调整方向：补充更多触发关键词和场景描述，把边界推得更宽（见 [[skill触发评测方法]] 的迭代决策表）。

与有赞 [[意图识别保守策略]] 的对照：一个在工具加载层主动外推（宁可多加载），一个在回答决策层主动收缩（宁可不容答），层级不同，构成跨来源对照素材。
