# Agent 架构四决策

vivo [[互联网搜索团队]] Wang Wenqian 于 2026 年 4 月提出的 Agent 架构分析框架，将 Agent 架构设计拆解为四个关键决策维度，每个决策都没有标准答案，但每个选择都有明确代价。

## 四个决策维度

### 1. 上下文管理

Agent 如何管理和传递上下文信息。三个层次：

- **[[追加式上下文]]** — 数组只增不减，token 线性增长（2K→80K）
- **[[上下文压缩策略]]** — 膨胀后的缓解机制（安全网而非解决方案）
- **[[任务隔离]]** — 以任务为单位隔离上下文的替代方案

### 2. 工具加载

Agent 如何加载和管理工具定义。核心矛盾：[[mcp]] 动态工具发现与 Anthropic Prompt Cache 稳定性之间存在不可调和的矛盾。

- 工具描述放 tools 字段（缓存命中率高但不灵活）
- 工具描述移入 prompt（灵活但需自实现解析）
- [[渐进式工具加载]]（按需追加到 messages 尾部）

### 3. 工具查找

工具规模达数百上千时如何高效定位工具。核心矛盾：接口维度（一个 API 一个工具）vs 功能维度（用户实际需求）。参见 [[skill功能聚合]]。

### 4. 主循环设计

Agent 的核心运行范式。参见 [[对话驱动vs任务驱动]]。

## 决策关联性

四个决策互相关联而非独立：

- 任务隔离影响上下文策略
- 工具加载方式决定 Skill 组织形式
- 主循环设计决定任务来源
- 上下文管理方式影响工具加载的缓存效率

理解关联和取舍是设计高效 Agent 的前提。
