# 即时上下文注入

即时上下文注入（Context Injection）是一种通过语法级符号在对话中即时挂载资源的上下文工程机制：把传统"被动工具调用"转化为"主动上下文预加载"。来源文章将其归于 [[hermes-agent]] 的 `@` 符号语法——用户或 Agent 写下 `@file:main.py` 即可注入文件内容，省去"意图识别 → 工具执行 → 结果返回"的中间环节，提升响应速度并降低多轮 Token 消耗。

## @ 注入语法表（7 种）

| 语法 | 作用 | 效果 |
|---|---|---|
| `@file:main.py` | 读取整个文件 | 注入 main.py 的完整内容 |
| `@file:src/utils.py:10-20` | 读取指定行 | 只注入第10-20行 |
| `@folder:src/` | 列出目录树 | 显示文件大小、修改时间 |
| `@diff` | Git 未暂存的更改 | 等同于 `git diff` |
| `@staged` | Git 已暂存的更改 | 等同于 `git diff --staged` |
| `@git:3` | 最近3次提交 | 包含完整补丁 |
| `@url:https://…` | 抓取网页内容 | 转为 Markdown |

## 设计要点

- 本质：从"Agent 判断需要什么再取"改为"在表达中直接声明需要什么"，将检索决策前移
- 与 [[bridge-rule]] 的"上下文桥接指路牌"同向：都缩短上下文获取路径，但 @ 注入是语法级即时挂载
- 与 [[渐进式披露替代向量检索]] 相似：以确定性语法替代语义检索中间层
- 与 [[结构化上下文组装]] 相容：注入内容由系统统一拼装进 System Prompt
- 对照组：来源口径下，[[openclaw]]、[[claude-code]] 的资源获取走被动工具调用路径

## 开放问题

- 大文件/大目录注入时的 Token 预算控制策略未披露
- 注入内容与 [[上下文压缩策略]] 的交互（注入的大资源是否参与压缩判定）未说明
