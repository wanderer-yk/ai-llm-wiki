# 硬性保护与软性保护

硬性保护与软性保护是 AutoResearch 类自循环系统两种质量保证路线：**硬性保护**用 git revert 在指标退化时强制回滚（Karpathy 原版、[[达尔文skill]]）；**软性保护**用多 Agent 交叉审核兜底而不做回退（[[smallnest-autoresearch]]）。

## 本文的设计分歧

[[smallnest-autoresearch]] 明确**没有做回退机制**，理由是"ClaudeCode/Codex 自己足够智能决定回退还是改进上一轮的变动"——即把回退决策交给 Agent 的自主判断，以 [[多agent交叉审核]] 的软性把关替代机械回滚。这与 Karpathy"只保留可测量的改进，其余全部回滚"（见 [[val-loss改善才commit]]）的硬保护哲学形成有意的设计分歧。

## 证据边界

该分歧**无对照实验数据**支撑：文章未比较"有回退 vs 无回退"的收敛速度或最终质量，"Agent 足够智能自行决策"属于论断而非实测结论，口径记录于 [[ai工程量化效果声明追踪]]。合理推测的影响维度包括：无回退时坏变动的累积风险、以及对审核反馈质量的更高依赖。

## 对照表

| 维度 | 硬性保护（Karpathy / 达尔文.skill） | 软性保护（smallnest/autoresearch） |
|------|------|------|
| 机制 | git revert 强制回滚 | 双 Agent 交叉审核 |
| 触发 | 指标退化即回滚 | 评分 < 9.0 进入下一轮，不回滚 |
| 依赖 | 单一可信 metric | 审核模型判断力 + 反馈质量 |
| 人的参与 | 全自主 / 每轮确认 | 循环外调优 program.md |
