# 四阶段优化循环

四阶段优化循环是 [[smallnest-autoresearch]] 把 [[autoresearchkarpathy-原版]] 的"训练实验循环"迁移到软件开发后确立的执行框架：一次 `run.sh` 调用被组织为环境准备 → 核心迭代 → 自动提交 → 记录归档四个阶段，其中"完全自主运行、不需人介入"的 Phase 2 占据几乎全部运行时间、被明确定位为系统价值核心。该循环与 [[karpathy]] 原版"修改 train.py → 跑 5 分钟实验 → val loss 改善才保留"的循环逐项对应，迁移逻辑详见 [[autoresearch软件开发迁移]]。

## 流程定义（原文保留）

```bash
Phase 1: 环境准备
  └─ 检查依赖 (gh, acpx, go)
  └─ 获取 Issue 信息
  └─ 创建分支 + acpx session
Phase 2: 迭代核心 (自主运行)
  └─ 奇数轮: Codex 审核 → Codex 实现 → 测试 → Claude 审核 → Claude 实现
  └─ 偶数轮: Claude 审核 → Claude 实现 → 测试 → Codex 审核 → Codex 实现
  └─ 评分 ≥ 9.0 → Phase 3
  └─ 评分 < 9.0 → 反馈驱动下一轮
  └─ 测试失败 → 反馈"测试失败"进入下一轮
Phase 3: 自动提交 (评分达标后)
  └─ git commit + push
  └─ gh pr create
  └─ gh pr merge
Phase 4: 记录归档
  └─ 写入 results.tsv
  └─ 更新 workflows/issue-N/log.md
```

## 各阶段要点

- **Phase 1 环境准备**：一次性完成，仅耗时数秒。检查 gh、acpx、go 依赖（[[acpx]] 是命令行操控 [[codex]] 与 [[claude-code]] 的 Agent 控制工具），获取经 [[issue选择策略]] 筛选的 Issue 信息，创建分支并建立 acpx session。
- **Phase 2 核心迭代**：按 [[奇偶轮角色互换]] 调度双 Agent 轮流实现与审核，每轮以 [[5维度量化评分]]（达标线 9.0/10）判定去留；未达标或测试失败时按 [[反馈驱动迭代]] 把审核反馈注入下一轮提示词。默认上限 42 轮。
- **Phase 3 自动提交**：`git commit + push`、`gh pr create`、`gh pr merge`。Agent 本身无推送权，全部发布动作由 run.sh 统一执行，体现执行权与发布权分离（见 [[agent权限边界清单]]）。
- **Phase 4 记录归档**：写入 results.tsv 并更新 workflows/issue-N/log.md 分目录日志，详见 [[results-tsv结构化归档]]。

## 跨来源印证与疑点

- "脚本统一执行 push/merge 等敏感动作"的编排方式与 [[24h打工人]] 的调度层、[[文件轮询架构]] 同构；Phase 4 的文件化落盘是 [[file-as-progress状态持久化]] 的直接实例。
- 正文的迭代示例（5.0 → 7.0 → 9.1 三轮收敛）为演示性数据而非实测统计；终止条件表与复杂度评估细则由文章图片承载、未能转为文字。整体效果声明的证据口径见 [[ai工程量化效果声明追踪]]。
