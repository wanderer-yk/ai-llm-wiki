# 代码采纳率

代码采纳率是 [[三层ai-coding度量体系]] 结果指标层的第二项核心指标，由天猫品牌行业前端团队提出，定义为 **AI 生成的代码最终被上线的比例**。其重要性论证：这是 AI 产出质量的核心指标——"生成一堆代码但都被删掉重写，说明 AI 没帮上忙"。

## 公式

```
代码采纳率 = AI 生成代码被上线的行数 / AI 生成代码总行数
```

## 三项关键计算机制

| 机制 | 解决的问题 | 做法 |
|------|-----------|------|
| 规范化比对算法 | 空格/引号/分号等格式差异导致 Diff 直接比对误判 | 预处理（去除注释、合并空白、统一引号和分号风格）后逐行比对；纯工程化实现、不依赖 AI、毫秒级 |
| Merge Commit 识别机制 | 发布记录中的 `repo_commit_id` 通常只是最后一次提交，完整变更不在其中 | 通过 GitLab API 获取 commit 历史，定位用户 commit 后向后查找第一个标题包含 "Merge commit" 的提交 |
| 多次出码合并处理 | 同一分支存在多次 AI 生成，逐次独立比对会遗漏贡献 | 同一 `(repo_project, branch)` 下所有 AI Diff 记录合并后再与 Merge Commit Diff 比对 |

## 多次出码场景示例（原文代码块）

```javascript
第1次出码（10:00）：+ console.log('step1');
第2次出码（11:00）：+ function test() {}
最终发布（14:00）：
  + console.log('step1');   // 来自第1次 AI
  + function test() {}       // 来自第2次 AI
  + const x = 1;             // 用户手写
```

示例结论：AI 新增 2 行，CR（Merge Commit）新增 3 行，被采纳 2 行，采纳率 = 66.67%。

## 已知矛盾：公式分母与示例分母不一致

公式声明分母为"AI 生成代码总行数"（示例中 AI 新增 2 行，应为 2/2 = 100%），但示例计算 2/3 = 66.67%，分母实为上线侧（CR/Merge Commit）新增总行数。两种口径疑似混用（文字公式口径 vs 实现口径），且文章收官未澄清。该矛盾已挂入查询页 [[ai工程量化效果声明追踪]] 永久跟踪。
