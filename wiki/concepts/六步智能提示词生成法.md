# 六步智能提示词生成法

[[回收团队]]刘雅斌提出的结构化提示词生成流程，设计哲学为"让 AI 精确理解问题，而非猜测问题"。将 [[sonar]] 扫描结果自动转换为 AI 可高效理解的结构化提示词的完整 6 步流水线。

## 六步流程

### ① Sonar 规则类型映射

`IssueTypeClassifier` 将 Sonar 具体 rule key 静态映射为七大高层问题类型（空指针/资源泄露/SQL注入/命令注入/命名规范/重复字符串/通用），未知规则归入 General 兜底。覆盖 8 条具体 Sonar 规则到 6 种类型。

### ② AST 精准方法定位

`JavaCodeParser` 使用 [[javalang]] 解析 Java 源码 AST，按行号区间匹配定位问题行所属方法，提取方法名、参数、返回值、修饰符等结构化上下文。AST 解析四大价值：精确定位、完整信息、语法理解（不受注释/字符串/Lambda 干扰）、99%+ 准确率。

### ③ 问题类型差异化上下文提取

参见 [[问题类型差异化上下文提取]]。`ContextExtractor` 根据问题类型差异化配置提取策略——高风险问题提取完整方法+imports+类声明（max_lines 100-150），低风险问题仅提取周围代码（max_lines 30-50）。AST 失败时优雅降级到问题行前后各 25 行。

### ④ 分层模板体系

参见 [[分层模板体系]]。`PromptTemplateEngine` 三层结构组装提示词：角色设定（"精通 Java 开发的资深工程师"）+ 通用编码规范（阿里巴巴 Java 开发手册 6 条核心规则）+ 问题类型专属修复要求。

### ⑤ Few-shot 示例库

参见 [[few-shot示例库]]。`ExampleRepository` 预置修复前后对比案例，按问题类型提供 Few-shot 学习示例，让 AI 通过案例学习修复模式。

### ⑥ MCP 服务整合

`IntelligentPromptGenerator.generate_for_issue()` 串联前五步，新增 Token 估算和元数据追踪。`auto_fix_sonar_issues` 通过 `@mcp.tool()` 装饰器暴露为 [[mcp]] 工具，使用 httpx 异步调用 Sonar API，逐一生成提示词。每个 issue 独立 try/except 容错。

## 设计哲学

核心思想与 [[上下文工程]] 一致——精准注入而非全量灌入。与 [[规格驱动ai开发]] 和 [[agentic-engineering]] 的结构化输入理念一脉相承：通过结构化输入消除 AI 的猜测空间。

## 最终提示词结构

角色设定 → 任务描述 → 编码规范 → Few-shot 示例 → 问题详情（规则 ID/类型/严重级别/描述/位置） → 待修复代码 → 修复要求 → 输出格式（严格约束为仅修复后的完整方法代码）

## 量化效果

- 成本降低 70%（精准上下文提取减少 Token 使用量）
- 准确率提升 30%（结构化提示词 + Few-shot 示例引导）
- 效率提升 3 倍（自动化流程）

> ⚠️ 量化数据未提供测量方法论和基线定义。

## 已知局限

- `IssueTypeClassifier` 映射 7 种类型，但 EXTRACTION_RULES 仅 5 种、ISSUE_TEMPLATES/EXAMPLES 仅覆盖 3 种（NullPointer/ResourceLeak/SQLInjection），CommandInjection/DuplicateString 无专用规则和模板
- Token 估算 `len(prompt) // 4` 对中文内容严重偏低
- 依赖极简化（mcp/httpx/javalang 共 3 包）降低部署成本
