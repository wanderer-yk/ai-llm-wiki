# RAG 经验召回引擎

## 定义

RAG 经验召回引擎是 [[货拉拉大前端]] AI Code Review 系统的核心模块之一，通过将历史事故复盘文档、最佳实践等知识向量化存储，在代码审查时基于余弦相似度检索匹配最相关的历史经验，注入审查 Prompt，使 AI 具备"看过线上事故"的业务直觉。

## 查询流程

```
代码变更简要（来自预处理流水线）
    → Embedding Model（向量化）
    → 余弦相似度匹配（与知识库中的事故复盘向量比对）
    → 相似度阈值过滤（< 0.85 的结果被丢弃）
    → Top 2 知识注入 Prompt
```

## 知识来源

向量库中的知识主要包括：
- **历史事故复盘文档**：线上事故的原因分析、修复方案、教训总结
- **最佳实践**：团队沉淀的编码规范、设计模式、防坑指南

这些知识的积累体现了 [[知识复利效应]]——随着历史事故不断沉淀，AI 的审查能力持续增强。

## 相似度阈值过滤

系统设定 **0.85** 的余弦相似度阈值，低于此值的召回结果被过滤。这一机制旨在减少噪音干扰，避免"似是而非"的历史案例导致模型幻觉和误报。

> **注意**：文章未说明 0.85 阈值的具体确定依据，这是一个开放问题。

## 幻觉风险与应对

文章明确指出 RAG 召回的固有风险：当召回的历史案例与当前代码变更"似是而非"时，会导致模型幻觉和误报。这与 [[rag技术瓶颈]] 中描述的 RAG 在精确匹配任务上的局限一致。

应对措施包括：
- 相似度阈值过滤（0.85）
- 仅取 Top 2 结果（限制注入上下文的噪音量）
- 反馈学习链路（开发者标记误报后微调检索策略，规划中）

## Prompt 构建

深度 Review 的 Prompt 由三部分融合：
1. **原始 Diff**（经 [[diff预处理流水线]] 处理后）
2. **语义简要**（语义重塑阶段生成的代码功能与改动意图描述）
3. **检索到的历史问题**（RAG 召回的 Top 2 知识）

## 实践效果

当历史复盘文档命中时，系统可提示"当前代码与历史事故逻辑模式相似度达 85%"，有效缩小人工审计盲区。

## 与其他知识检索方案的对比

- 与 [[向量检索rag]] 的关系：货拉拉 RAG 引擎是向量检索 RAG 在代码审查场景的具体应用
- 与有赞 [[知识优先级机制]] 的差异：有赞通过 Prompt 定义不同知识源的优先级规则解决信息冲突，货拉拉通过相似度阈值过滤减少噪音
- 与有赞 [[静态动态双路径知识注入]] 的差异：有赞区分静态信息（写向量库）和动态信息（实时查询），货拉拉的知识库均为静态历史文档
- 与马上消费 [[信源冲突裁决]] 的差异：马上消费提出四原则裁决机制处理多源信息冲突，货拉拉通过 Top 2 + 阈值过滤简化处理
