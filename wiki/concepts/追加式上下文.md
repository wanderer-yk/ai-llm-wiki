# 追加式上下文（Append-only Context）

Agent 上下文管理的基础模式：维护一个持续增长的对话历史数组（messages），每轮 LLM 调用重发完整历史。[[openclaw]] 和 [[claude-code]] 均采用此模式。

## 工作机制

```
messages = []
while True:
    messages.append(user_input)     # 追加用户输入
    response = llm.call(messages)   # 重发完整历史
    messages.append(response)       # 追加模型回复+工具调用
```

## Token 增长轨迹

- 第 1 轮：~2K tokens
- 第 2 轮：~8K tokens
- 第 N 轮（20 轮后）：~80K tokens

Opus 定价下，携带 80K 历史说一句"你好"需 $0.30。

## 优势

1. **缓存命中率高** — messages 数组只增不减，已有部分可被缓存
2. **实现简单** — 逻辑清晰，无需复杂的上下文裁剪
3. **上下文连贯** — 完整历史保证多轮对话信息不丢失

## 问题

1. **话题混杂** — 所有话题混合在一个上下文窗口，Agent 难以区分不同任务
2. **成本与复杂度脱钩** — 简单操作也需携带全部历史
3. **无限增长** — 需要压缩机制（[[上下文压缩策略]]）或架构替代方案（[[任务隔离]]）
