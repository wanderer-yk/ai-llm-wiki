# 工程三次进化框架

工程三次进化框架是 [[李伟山]] 在《从 Prompt、Context 到 Harness，工程的三次进化与终局之战》中提出的核心演进框架，将软件工程在 AI 时代的方法论演进划分为三个阶段：

| 进化阶段 | 解决的核心问题 | 精炼定义 |
|----------|---------------|---------|
| [[prompt-engineering-李伟山版\|Prompt Engineering]] | 我该跟模型说什么？ | 说清楚 |
| [[context-engineering-李伟山版\|Context Engineering]] | 模型在回答时该知道什么？ | 给够信息 |
| [[harness-engineering-李伟山版\|Harness Engineering]] | 整个 AI 系统该如何可靠地运转？ | 系统可靠 |

## 核心特征

根据 [[嵌套关系论-李伟山版]]，三者不是替代关系而是**层层包裹、相互依存的嵌套关系**：

- 无 Prompt → Context 无效（模型不知道该做什么）
- 无 Context → Harness 瞎跑（模型缺乏关键信息）
- 无 Harness → 沙滩城堡（系统层面无约束/验证/反馈）

三者缺一不可、层层递进，共同服务于 [[三次进化统一目标论]]——将 LLM 能力转化为可靠生产力。

## 演进动因

- **第一次→第二次**：随 GPT-3 → GPT-4 / Claude 3 模型语言理解能力提升，精心设计 Prompt 的边际效益递减，真正瓶颈转移到模型"不知道的关键信息"（上下文缺失）。
- **第二次→第三次**：即使 Prompt 和 Context 都做好，Agent 仍会出现未授权重构、虚假测试通过声明、命名不一致等失控行为——根源在系统层面缺乏约束/验证/反馈机制。
