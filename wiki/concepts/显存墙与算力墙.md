# 显存墙与算力墙

[[韩春]] 对 LLM 推理两大性能瓶颈的区分：

- **Memory Wall（显存墙）**：影响搬数据，制约推理 Decode 阶段；
- **Compute Bound（算力墙）**：影响矩阵计算，制约预训练/Prefill 阶段。

## 为何显存 I/O 是主要瓶颈

Transformer 层间本质**串行** + 参数量巨大 → 每层生成都需完整搬运参数 → 显存 I/O 成为瓶颈。作者转述"有种说法"：GPU 约 90% 时间在搬数据、10% 在矩阵运算（未独立核实）。

## 同构性

LLM 推理与 CPU 性能优化同构：内存 → HBM，CPU Cache（L1/L2，1-5ns）→ GPU Cache。B300 实测参数佐证：288GB HBM3E（8TB/s）不到 10 毫秒可把 70B FP8 模型全部参数搬入计算核心一次；MoE（如 deepseek-v3:671b 激活 67B 参数）引发高频跨卡通信，NVLink（1800GB/s）是多卡并行现实最优解。

关联：与 [[ai系统圣杯数据局部性]] 互为表里；该性能结构也是 [[llm天然工程约束]]（低吞吐、高计费、首字符慢）的硬件根源。
