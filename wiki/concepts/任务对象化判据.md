# 任务对象化判据

任务对象化判据是判断「持续执行是否已成为系统正式对象」的标准：`spawnAgent(prompt): Promise<string>` 只是「多开一个智能体」——返回一个 id，执行体游离在系统治理之外；只有当执行体具备 status/progress/output/notifications/cancel/resume 等完整生命周期接口（即 `Task` 对象）时，「持续执行」才从一次函数调用升格为可管理、可追踪、可恢复的系统正式对象。

```typescript
spawnAgent(prompt): Promise<string>
```

```typescript
interface Task {
  id: string
  status: 'pending' | 'running' | 'blocked' | 'done' | 'failed'
  progress: ProgressState
  output: StructuredOutput[]
  notifications: Notification[]
  cancel(): void
  resume(): void
}
```

该判据把多 Agent 落地问题从 prompt 工程转向接口设计：能否被统一生命周期治理，取决于执行体是否被对象化。它与 [[统一任务抽象先行]]、[[子agent即任务对象]] 一脉相承，是 [[执行收回论]] 的技术前提，与 [[SubAgent生命周期工具化]]、[[受控子Agent机制]] 跨源互证。
