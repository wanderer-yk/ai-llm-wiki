# 分阶段文档按需加载

本文"上下文管理"核心设计：Skill 链路跨四个 Phase、涉及口播稿规范、outline 格式、章节开发指引、主题 token、音频合成、录屏指南等多份复杂文档，若启动时全量灌入会"严重稀释"模型注意力。解法是**每份文档只在指定阶段读取**。

## 六份分阶段文档清单（逐字）

| 文件 | 读取时机 | 内容 |
|------|---------|------|
| SCRIPT-STYLE.md | Phase 1.2 必读 | 文章→口播稿规则、平台变体（双层自检：形式/风骨/念出来） |
| OUTLINE-FORMAT.md | Phase 1.2 必读 | outline.md 字段 spec、命名约定、章节切分、信息池规则 |
| CHAPTER-CRAFT.md | Phase 2.4 每章单一必读入口 | Part 0 十条原则 / Part 1 开工 5 问 / Part 2 关系→动作决策树 / Part 3 视觉工具箱 / Part 4 时长参考 / Part 5 反 AI 味反模式 / Part 6 代码硬规则 / Part 7 完工自检 / Part 8 反馈速查 |
| THEMES.md | 选/造/切主题时读 | 完整 token 契约 + 内置主题清单 + 创作新主题流程 |
| AUDIO.md | Phase 3 才读 | MiniMax CLI TTS 合成流程、增量合成、故障排查 |
| RECORDING.md | Phase 4 才读 | 录屏工具推荐、Auto 模式一镜到底、后期合成 |

## 谱系

与有赞 [[渐进式披露替代向量检索]]（目录结构即检索路径、YAML description 做摘要判断）思路同族：都不靠向量检索，而靠**结构化位置+按需加载**控制上下文供给。CHAPTER-CRAFT.md 的"每章单一必读入口"设计尤其体现了把复杂规范收敛为单文件的注意力保护思想。
