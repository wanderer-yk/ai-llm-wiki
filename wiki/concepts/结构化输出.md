# 结构化输出（Structured Output）

## 简介

LLM 天生是自由文本生成者，即使 Prompt 强调"直接回复编号"，仍会夹带解释，导致程序解析困难。结构化输出通过 Function Calling 机制约束 LLM 严格按格式输出，是[[ai狼人杀|AI 狼人杀]]等多人决策游戏的关键技术。

## 实现原理

基于 Function Calling 的完整流程：

1. **定义 POJO 类** — 如 `VoteModel`（含 targetPlayer 和 reason 字段）
2. **转为 JSON Schema** — 框架自动将 Java 类转为 JSON Schema
3. **注册为临时工具** — 以 `generate_response` 为名注册为临时 Function Calling 工具
4. **LLM 调用工具** — LLM 被引导以工具调用形式生成格式化响应
5. **自动验证转换** — 框架自动将响应转为 Java 对象
6. **失败重试** — 格式不符时自动修正重试
7. **清理工具** — 调用完成后清理临时工具

## 四大优势

| 优势 | 说明 |
|------|------|
| 类型安全 | IDE 自动补全 + 编译期检查，避免运行时类型错误 |
| 格式统一 | JSON Schema 强制约束，消除自由文本的歧义 |
| 自动重试 | 格式不符时框架自动修正，无需手动处理异常 |
| 开发高效 | 投票、查验、救人等不同场景复用同一套机制 |

## 在 AI 狼人杀中的应用

- **投票阶段**: 定义 `VoteModel` 类（targetPlayer + reason），结构化收集每位玩家的投票
- **神职技能**: 预言家查验、女巫救人/毒人等决策均通过结构化输出确保可靠解析
- **狼人击杀**: 夜间狼人讨论后通过结构化输出收集击杀目标
