# LLM 推理三阶段

**LLM 推理三阶段**是《业务逻辑的坍塌（下）》中以 Qwen2.5-7B 为实例给出的 LLM 一次推理的完整计算过程拆解：①Tokenization 与 Embedding 映射 → ②预填充（Pre-fill）与注意力计算（KV Cache 工程优化所在）→ ③生成首个 Token 后进入自回归循环。它是理解 KV Cache、显存占用与 [[显存墙与算力墙]] 的机制基础。

## 实例载体：Qwen2.5-7B 架构参数（按源文保留）

| 参数 | 值 |
|------|------|
| 词表大小 | 约 152000 |
| Embedding 维度 | 4096 |
| 层数 | 28 |
| FFN | 2 层，4096 → 18944（约 4 倍于 4096，不同模型不同）→ 4096 |

## 阶段一：Tokenization（分词）与 Embedding 映射

- 分词器将 Prompt 切成 Token，中文通常 1~2 个字为一个 Token；分词器与 Embedding 成对出现，在预训练完成后得到。
- 示例输入"你作为一个科普达人，请用小学生可以理解的方式，介绍下 LLM 的主要原理？"分词为约 20 个 Token；每个 Token 用一个 4096 维向量表示，得输入矩阵 **X=[20×4096]**（20 为句长，4096 为每个 Token 的特征数）。
- Embedding 维度越高能拟合的细节越好，但后续计算量急剧上升；加入位置编码后送入注意力计算阶段。

## 阶段二：预填充（Pre-fill）与注意力计算

- 训练阶段所得权重矩阵与 X 相乘得到 QKV 矩阵（均 [20×4096]）。
- **KV Cache 机制**：模型把 K 和 V 放入显存用于后续推理加速——Q 作为 Token 的查询用完即结束，而 K 和 V 在后续每次蹦出新 Token 需要重新计算时，可避免前序 Token 重复与权重矩阵相乘。
- 注意力计算在 [20×20] 矩阵内部进行：每个 Token 的 Q 与包括自己在内的其他 Token 的 K 相乘（计算相关性）后除以 √d 缩放（防止梯度消失，使进入 softmax 的数值保持可控），softmax 归一化为概率分布后再与 V 相乘（用概率权重提取 V 中携带的信息），输出仍为 [20×4096]——但已掺杂与前序 Token 间的关系。
- 非线性的两处来源：Attention 阶段通过 softmax 引入非线性（计算 Token 间相关性权重），FFN 阶段通过激活函数（如 SwiGLU）进一步增加非线性表达能力。
- 随后进行残差连接 Add（将输入叠加到输出，解决深层网络梯度消失）与归一化 Norm（将数据拉回标准分布，防止层数加深导致数值爆炸或消失），进入 FFN：第一层把 4096 升维至 18944（更高维度 = 投影到更高维空间，寻找切分平面的自由度更大），再降维回 4096。共循环 28 层。

## 阶段三：生成首个 Token

- 28 层循环后输出仍为 [20×4096]；模型只关心最后一行 [1×4096] 向量（对应句末"？"位置，包含全部输入的上下文信息）。
- 与输出映射矩阵相乘（可为阶段一中 Token→Embedding 映射矩阵的转置），将特征向量映射回词表空间，经 softmax 得到针对约 152000 词表的概率分布。
- 按采样方法（如参考 Temperature 设置）仲裁出下一个 Token，完成一次推理；如此往复，不断蹦出下一个 Token（自回归）。

## KV Cache 层次澄清

本概念的 KV Cache 是**推理层**机制（注意力 K/V 的显存缓存，属单次推理内的计算优化）；与 [[kv-cache时间窗优化]]（OpenClaw 上下文缓存的命中时间窗，属应用层上下文复用策略）是**不同层次的同名机制**，不可合并或互相归因。
