# 思考内化论

思考内化论是 [[沈询]] 对 ReAct 中"思考"角色的工程化界定：ReAct 中的"思考"如同人类的内化思考，是一种**可选输出**——它不必以文本形式显式呈现，其最终外显形式就是 toolcall。

## 与经典 ReAct 表述的差异

- **学术 ReAct**：通常要求显式的 Thought-Action-Observation 文本轨迹，每轮先输出 Thought 再输出 Action
- **Lynxe 工程实现**：思考过程隐藏，调用 LLM 时"思考是可选输出"，提示词直接要求"做出下一步的决策"，LLM 直接输出 toolcall
- 这不是对 ReAct 的否定，而是**工程实现变体**：推理能力隐式存在于 toolcall 的生成过程中

## 工程意义

- **输出解析简化**：无需解析自由文本 Thought，只需解析结构化 toolcall（与 [[结构化输出]] 的思路相通）
- **提示词可固定**：无需为 Thought 预留格式约束，模板跨轮次不变，仅历史上下文增长（见 [[react五要素]]）

## 待验证问题

思考隐藏化变体与显式 Thought 轨迹在任务成功率、可调试性、Token 成本上的效果差异，目前尚无对比数据，值得作为开放问题持续追踪。
