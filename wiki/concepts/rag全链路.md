# RAG 全链路

RAG 全链路是《RAG 全链路技术详解》（[[驰海]]，[[天猫品牌行业架构团队]]）提出的 RAG 系统工程化组织框架：将 RAG 从文档进入到大模型输出的完整生命周期拆解为七个环节，并为每个环节给出技术选型与优化手段，以「**可测、可调、可信赖**」为总目标。文章的核心口号级主张是「**RAG 技术的应用水平直接决定 Agent 的业务上限**」。

## 七环节框架

| 环节 | 技术要点 | 对应概念页 |
|------|----------|-----------|
| 文档加载 | 多格式解析＋元数据提取＋初步清洗（RAG「入口」，质量决定后续检索准确性，类 [[gigo原则]]） | — |
| 智能切分 | 规则/语义/结构化方法，含 Meta-Chunking 原理 | [[ppl语义切分]] |
| 索引构建 | embedding 模型选型与向量生成（Transformer 前向全流程） | [[embedding索引构建原理]] |
| 检索优化 | Query改写、HyDE/Doc2Query、标签过滤、重排序 | [[Query改写]]、[[hyde]]、[[doc2query]]、[[多查询生成]]、[[提取标签]]、[[重排序rerank]] |
| 生成调优 | Prompt 设计、参数控制、SFT 微调 | [[生成调优技术]]、[[生成阶段问题清单]] |
| 进阶 Graph RAG | 多跳推理与全局摘要 | [[多跳问题]]、[[全局理解]]、[[社区检测]] |
| Ragas 自动化评估 | 指标体系＋测试集生成 | [[ragas评估指标]]、[[评测集生成]] |

## 问题背景与工作原理类比

- **三大挑战**（品牌行业 AI 运营战役实测观察）：知识库构建缺乏标准／检索召回精度达不到预期／缺乏量化评测体系。
- **开卷考试类比**：RAG 先检索相关实时/私有信息作为参考背景与问题一起提供给大模型，基于可靠证据生成更准确、实时且可溯源的回答，可有效减少 LLM 在知识密集型任务上的幻觉。

## 与既有概念的关系

本框架是 [[rag技术瓶颈]]、[[向量检索rag]]、[[rag知识表示演进论]] 等既有概念的工程化组织视角：检索环节的诸技术（HyDE/Doc2Query/ReRank）是对向量检索固有弱点的针对性补强；评估环节以 [[ragas|Ragas]] 落地「可测」支柱，与 [[agent评测四要素]]、[[评测集优先于知识库]] 形成评测方法论谱系的 RAG 专用分支。
