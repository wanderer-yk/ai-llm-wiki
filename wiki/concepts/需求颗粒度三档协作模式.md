# 需求颗粒度三档协作模式

需求颗粒度三档协作模式是 [[阳凯]] 在得物技术 Spec Coding 实践中提出的「按需求复杂度选择人机协作方式」的决策框架：小颗粒需求直接对话即扫即改，中颗粒标准化需求用 Rules/Skills 预设规范生成，中大颗粒复杂需求走 [[openspec]] 标准流（SDD，即 [[规格驱动ai开发]]）。其核心理由链是：业务越复杂，AI 越易幻觉与需求偏移；Spec 强制先设计后编码，且 proposal→design→specs→tasks 留痕具维护价值。

## 三档策略（原表保留）

| 颗粒度 | 场景 | 策略 | 理由 |
|--------|------|------|------|
| 小颗粒 | 改文案、修显隐逻辑、调 CSS 间距 | Cursor Chat 对话即扫即改 | 沟通成本低于编写规范成本 |
| 中颗粒标准化 | 标准 CRUD 页面、简单业务组件 | Cursor Rules 或 Skills 预设规范（如 pro-table.mdc） | 有强烈"模式感"：识别场景→读取示例→生成类型→完成 UI |
| 中大颗粒复杂 | 重构核心逻辑、复杂业务模块、无参考代码新功能 | OpenSpec 标准流（SDD） | 业务复杂时 AI 易幻觉/需求偏移；Spec 强制先设计后编码，留痕具维护价值 |

## 跨团队母题

该模式与天猫 [[场景严苛度分级]]、zhiyuanfu [[自动化决策层级]] 构成「按场景/颗粒度选协作模式」的跨团队母题：三者都拒绝「一种流程适配所有需求」，主张以确定性成本最低的方式匹配需求复杂度，重需求才启用重流程（SDD/Spec 工作流）。

## 关联

- 是 [[AI顶级执行者比喻]] 中「极度服从」特征的管理对策——对高复杂度需求不能直接下指令；
- 与 [[AI失效三模式]] 的「任务目标模糊」应对（proposal 强制 Why）衔接；
- 依赖 [[三层规范体系]] 作为中颗粒档的规范基础设施。
