# 双轨校验

百度Geek说《Harness Engineering》理念四条之三：子任务完成判定同时依赖两条校验轨道——**程序化校验**与 **Evaluator 校验**。

## 轨道一：程序化校验

三大优点：
- **零 Token 消耗**；
- **结果完全确定**（同样的输入永远同样的判定）；
- **可无限次重复**（不疲劳、不妥协）。

适用于客观维度：编译是否通过、JSON 是否可解析、产出是否符合 schema、文件是否存在。

## 轨道二：Evaluator 校验

主观维度（如审查意见质量）程序化校验覆盖不了，需独立会话的 Evaluator Agent 批判性评估（→ [[批判性evaluator校验]]）。独立会话的必要性来自 [[自我说服效应]]；进一步可[[跨模型评估]]降低偏见。

## 实证（7.2 JS to TS）

**Babel AST 对比**确保逻辑结构不变 + **tsc 类型检查**确保编译通过——双轨都过才标 DONE。这一"双过才通过"的硬性判据与 [[验证门禁化]] 理念同向。
