# 运行泥球反模式

运行泥球反模式指把权限、后台任务、扩展、失败恢复全部塞进单主循环的做法：短期开发快，长期会生长成不可维护的「运行泥球」。它是 [[复杂度安放位置论]] 所诊断的「复杂度错位」的极端形态。

Claude Code 的总架构——「一个控制面 + 一条受约束执行链 + 一套长期任务系统」（见 [[三主干链路]]）——正是对该反模式的系统性规避。

与 [[agent-loop]] 的关系：agent loop 作为最小运行骨架没有错；错的是随系统成长，把一切新增复杂度持续塞进同一个循环而不做安放。此对照进一步强化了 agent-loop 概念中「Agent 不是一个大脑拖着一堆工具」的边界。
