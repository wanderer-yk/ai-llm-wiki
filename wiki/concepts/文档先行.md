# 文档先行

文档先行是天猫新品营销技术团队的第二核心思想："文档是 AI Coding 的第一要素，PRD 即单测，文档即代码，优先修改文档而不是代码。"其要点包括：文档不要求大而全，重点是对大致方向的描述与部分易混淆部分的详细说明——与归因因素 2 的"小文档起步+按偏离迭代补充"文内互证。

## Spec-kit 实测校准（逐字）

"基于 Spec-kit 的模型，理想状态下是有一份可以和代码 100% 互相转换的文档，但是现在实测下来很难达到这种理想状态（没有可以完美描述项目的文档，文档也没法恰好转换到代码），最好的策略还是够用就行。"

这是对 [[github-spec-kit]] 与 [[规格驱动ai开发]] 族（[[specflow]]/[[openspec]]/[[trade-spec]]）的重要校准：肯定 Spec Coding 的理想态，指出实测落差，主张以"够用就行"为度——属内部细化而非否定。

## 操作形态

- [[PRD即单测]]：通过 spec 工具将功能文档转换为"近似单元测试的功能文档"，必要时转化为实际单元测试
- [[明确需求内容]] 三条实践路径（标准化 PRD 模版 / 需求不涉及实现 / spec 工具单测化）
- 案例二实证：AI 扩写 PRD 后"清晰的 prd 保证功能符合预期"

## 互证

- 需求驱动型案例的"能用就行初版+仅原始需求"虽功能勉强达标，代码质量却暴露 600 行阈值灾难——反向支持文档先行
- 冷启动投入 ↔ [[反人性文档论]]；跨团队渐进式披露 ↔ [[渐进式披露替代向量检索]]（有赞）
