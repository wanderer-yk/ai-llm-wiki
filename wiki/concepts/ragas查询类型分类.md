# ragas查询类型分类

ragas查询类型分类（Query types in RAG）是 [[ragas]] 测试集生成用来刻画查询空间的双正交维度框架：按**跳数**分为单跳查询与多跳查询，按**抽象度**分为具体查询与抽象查询，形成 2×2 矩阵。该分类是 [[评测集生成]] 的骨架——生成测试集时先确定题型分布，再经由知识图谱构建与 [[场景采样两阶段解耦]] 落地为具体题目。

## 两个维度

**按跳数：**
- **单跳查询（Single-Hop Query）**：仅需从单个文档或来源中检索信息即可提供相关的回答；
- **多跳查询（Multi-Hop Query）**：涉及多个推理步骤，需要来自两个或更多来源的信息。系统必须从不同的文档中检索信息，并将这些信息点串联起来，才能生成准确的回答。

**按抽象度：**
- **具体查询（Specific Query）**：基于事实、检索出来的知识直接就能用（作者灰色斜体注解：侧重精确性）；
- **抽象查询（Abstract Query）**：仍指向单一概念，但需要从源材料中提取更具抽象性或解释性的说明（作者注：侧重整合广泛的思想，需对检索知识进行抽象总结——标注为"个人理解"）。

## 2×2 矩阵（爱因斯坦示例）

| | 具体查询 | 抽象查询 |
|---|---|---|
| **单跳** | 相对论的发表年份 | 相对论如何改变了人类对时空的理解 |
| **多跳** | 哪位科学家影响了爱因斯坦关于相对论的研究，他们提出了什么理论 | 自爱因斯坦最初发表论文以来，关于相对论的科学理论是如何演变的 |

多跳-具体示例要求同时检索影响者及其理论，信息可能分布在两个不同来源；多跳-抽象示例则需要检索跨越不同时间、不同来源的多条信息，形成"广泛且具解读性"的回答。

## 生成难度不对称

- **单跳问题生成相对简单**："随便找一个文档块，让 LLM 根据这个块提个问题就行"；
- **多跳问题生成困难**："你必须先找到包含 A、B 关系的文档块 1，以及包含 B、C 关系的文档块 2"，才能让 LLM 串联生成跨越知识点的问题（示例：A 影响 B、B 发明 C，问：谁影响了 C 的发明者？）。

正是这一不对称催生了 Ragas 在测试集生成内部的知识图谱构建管线（Document Splitter → Extractors → Relationship builder，详见 [[ragas]] 与 [[评测集生成]]）。

## 与既有概念的关系

- [[多跳问题]] — 同一术语在《RAG 全链路技术详解》中五次复用（Graph RAG 检索挑战 → 评测维度 → 生成机制难度），"检索侧多跳难 = 生成侧多跳难"的同构性是全文贯穿性洞察；
- [[场景生成]] — 查询类型矩阵之上再叠加节点/长度/风格/人设四参数，构成完整的查询分布覆盖能力；
- 本矩阵分类与 [[评测集优先于知识库]]（小红书 PMO：评测集是 Agent 的单元测试）的定位形成跨源共振，与 [[评测agent乐观偏差]] 的张力留待综合页裁决。
