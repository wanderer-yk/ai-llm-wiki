# 反馈回灌闭环

反馈回灌闭环是问诊 Agent 体系的进化引擎：将“质量评估—反馈回流—知识优化”连成完整管线，目标是让系统成为“可衡量、可迭代、可持续进化”的**越用越聪明的活体**。作者由此提出哲学总结：**Agent 不是静态一次性产物，而是依托数据反馈持续生长的有机体**。

## 完整管线（原文 ASCII 图）

```text
线上问答 → 评分 Agent 打分 → 聚焦低分样本（≤6）→ 人工复核 → 根因归因
                              ↓
              更新排查文档 / 补充公共知识 / 优化提示词 → 回灌至训练集
```

## 三大收益

1. **知识沉淀加速**：每次坏样本复核都转化为文档/知识更新；
2. **模型行为收敛**：防错—纠错—免疫的正向演进；
3. **运营透明可控**：质量可度量、趋势可监控。

## 真实案例

日志格式变更导致诊断失败 → 案例被转化为技能文档中的新版日志说明——一条完整的“失败 → 文档更新”闭环实例，体现 [[sop-doc可召回排查文档]] 的维护对象下沉优势。

## 现实节奏与演进目标

**当前纠偏依赖月度复盘**（重要事实：闭环的现实运转节奏为月度，而非实时）；下一步目标为**分钟级异常检测与自动告警**——与同账号 [202604011800] OpenClaw Observability 基于 DuckDB 的全链路可观测体系直接互补。

## 开放问题

“回灌至训练集”的确切含义未说明——是提示词/文档迭代还是模型微调，待澄清。

## 「回灌至训练集」歧义登记（review-e8fae445，2026-10-12）

原文管线图写「回灌至训练集」，但正文描述的回灌动作仅为更新排查文档/补充公共知识/优化提示词——**是模型微调（真训练集回灌）还是仅文档/提示词层迭代（借用说法）未明**。两种解读对应完全不同的工程成本与数据飞轮含金量。本文按保守口径（文档/提示词层迭代）理解，待作者后续文章或 Deep Research 定谳；与 [[数据自迭代]]（含 AI 质检反馈）的可比性受此影响。
