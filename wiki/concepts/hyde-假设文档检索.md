# HyDE 假设文档检索

HyDE（Hypothetical Document Embeddings，用假设文档增强检索）是一种查询转换检索技术：先让 AI 编一个「假答案」，再用这个「假答案」去搜「真内容」。其本质是将「问题-文档匹配」转换为「文档-文档匹配」，针对的是**非对称检索问题**——用户问题短、疑问语气，知识库文档长、陈述性，两者在向量空间中的语义特征不完全对等（例：「为什么天空是蓝色的？」vs「瑞利散射是指……导致波长较短的蓝色光散射更强……」）。

## 工作流程四步

1. **接收提问**：用户输入一个问题（Query）。
2. **生成虚构文档（Hypothetical Document）**：系统调用 LLM 并给出指令「请写一段话来回答这个问题」；模型**不查资料**、凭「直觉」或内部知识编造答案，「即便这个答案里包含错误的信息也没关系」——容错性是刻意设计而非缺陷。
3. **向量化（Embedding）**：将虚构答案转为向量。
4. **匹配检索**：用「虚构答案的向量」去数据库找最相似的真实文档。

## 面团发酵完整例句

用户问「为什么面团放一会儿会变大？」→ 知识库内容含「酵母发酵」「二氧化碳释放」「面筋网络」「厌氧呼吸」等专业原理 → LLM 写伪答案（酵母菌发酵分解糖分产生 CO2，被面筋蛋白包裹成微小气泡）→ 以伪答案做向量检索，命中论文《真菌代谢对谷物蛋白弹性的影响》（共享「二氧化碳」「酵母代谢」「面筋网络弹性」词汇，向量高度重合）→ 模型总结最终回答并引用该论文——实证「短口语问题 vs 专业论文」的文档-文档匹配效果。

## 关联

HyDE 与 [[doc2query]]（反向 HyDE，文档→查询）方向相反、时机互补（后者离线执行不影响实时响应时间）；与 [[多查询生成]] 同属查询扩展技术族。代价是每次查询多一次 LLM 调用，其延迟/成本权衡源文未量化。相关背景：[[向量检索rag]]。
