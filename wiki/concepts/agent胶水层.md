# agent胶水层

Agent 开发很大程度上是在构建一个胶水层（Context 层）——一端把模糊需求、碎片知识、非结构化对话翻译成 LLM 能理解的上下文，另一端把 LLM 的非确定输出翻译成工程系统能处理的结构。这是 [[韩春]]《业务逻辑的"坍塌"（上）》的标题主论点：胶水层的设计质量直接决定 Agent 应用的生产力与鲁棒性。

## 坍塌机制：复杂度下沉与状态上浮

应用层业务逻辑"变薄成胶水代码"的机制：

1. **复杂逻辑计算下沉模型内部**（黑盒化）——LLM 在训练期内化业务知识；
2. **交互与状态管理上浮 Prompt/Context 层**（自然语言化）；
3. 两端挤压之下，应用层只剩下双向翻译的胶水代码。

## 深层原因：业务逻辑前置训练阶段

Agent 代码量大降的深层原因是业务逻辑已前置到模型训练阶段（甚至不限于后训练与 Context 工程）。对照示例：过去 Java `@Service OrderService` + `@Transactional processOrder` 的六步显式编排（验证订单→检查库存→扣减库存→处理支付→保存订单→发送通知），在 AI 时代可收敛为 `async def process_order(order_text: str) -> str` 单 prompt 调 `llm.chat(prompt)`。因此争论 Java 要不要追 Python 生态意义不大（见 [[java声量缺失论]]）。
