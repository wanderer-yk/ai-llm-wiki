# 观测评测闭环

观测评测闭环指将 Agent 可观测体系产生的结构化追踪数据作为评测平台的标准化输入，使"观测"与"评测"打通为持续质量闭环的工程实践。本页表述来自 [[阿里商旅]] [[aligo]] 文章"观测"章的第四个目标——"打通观测-评测流程：结构化追踪数据为测评平台提供标准化输入"。

## 动机：观测三挑战

| 挑战 | 内容 |
|---------|------|
| 问题定位困难 | 10+ 智能体协作，难定位问题智能体/LLM 调用/工具调用 |
| 性能优化缺乏数据支撑 | 看不到响应时间、Token 消耗、工具调用频次 |
| 效果评估缺少量化指标 | 缺完整对话日志与结构化数据，无法 A/B 测试 |

## 四目标

全链路追踪（用户输入到最终输出，含 LLM 调用、工具使用、记忆管理）；多维度观测（Trace / Session / User）；打通观测-评测流程；支持问题快速定位（可视化调用链 + 详细输入输出日志）。

## 实现组合

- **观测基座**：[[langfuse]]（开源，胜 LangSmith 商业方案；理由为开源透明、数据安全、成本控制、可扩展性，满足商旅 SaaS + 本地化部署）。
- **评测基座**：AI 测评系统——通义千问自动评分（准确性 + 相关性两维度，LLM-as-judge）、测试任务/用例/数据全生命周期管理与资产沉淀、可视化报告（多维评分、成功率、问题归因、版本对比）。

## 跨团队对照

- [[全链路可观测体系]]、[[观测三视图]]、[[四层观测架构]]（OpenClaw Observability）：同以 Trace 为核心的多维观测。
- [[agent可观测性六维度]]（zhiyuanfu）：goal/step/tool/failure/recovery/cost 的最低可观测性清单。
- [[agent评测四要素]]（有赞）：评测对象/数据集/指标/反馈闭环框架——阿里商旅的"观测供数给评测"正是反馈闭环的数据上游。
- [[评测集优先于知识库]]（小红书）、[[高阶模型审查低阶模型]]（美团）：评测驱动质量的其他路线。

阿里商旅的独特贡献在于**把观测与评测明确声明为一个流水线的上下游**，而非两套独立设施。
