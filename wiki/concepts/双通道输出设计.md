# 双通道输出设计

百度Geek说《Harness Engineering》6.2/6.3 节的输出设计：调度脚本的输出分**人/Agent 两条通道**，各取所需。

## 通道一：终端输出（给人看）

一眼可扫的进度概览：进度计数、速度、ETA、失败摘要。示例（见来源页结构化数据）：

```bash
[Progress] 45/120 DONE | 10 IN_PROGRESS | 3 FAILED | 62 TODO
[Speed] avg 35s/task | elapsed 28min | ETA ~22min
[Failed] group_12 (timeout), group_27 (compile error), group_33 (timeout)
```

dispatch 脚本**无需在终端重复状态信息**——人看的扫一眼即可。

## 通道二：状态文件（给 Agent 读）

结构化、可解析的**完整状态**：任务 ID、状态、产出路径、失败原因。Agent 恢复与续传只依赖这条通道（→ [[file-as-progress状态持久化]]）。

## 关联

人与 Agent 对同一状态有不同消费方式，这一区分与 [[agent可观测性六维度]] 的可观测性要求同向：状态既要人可审，也要机器可判。
