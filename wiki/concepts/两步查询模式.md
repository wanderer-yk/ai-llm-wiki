# 两步查询模式

"两步查询模式"是 [[umodel|UModel]] SERVE 阶段的关键查询工程模式：**graph-match 图遍历仅返回 entity_id，业务字段经 `.entity` 批量接口分离拉取**——拓扑层负责关系推理，实体层负责字段读取，两者分离以优化查询路径与 token 开销。

## 原文 SPL 示例

```bash
Step 1: .topo | graph-match (n1:code@code.module {__entity_id__: '<id>'})
              -[e]->(n2) project n1, e, n2
Step 2: .entity with(domain='code', name='code.module', ids=['id1','id2',..])
```

## 聚合直查补充

聚合统计类查询（如"谁被导入最多"）不经过 graph-match，直接 SQL 查 `__topo` logstore：

```sql
SELECT __dest_entity_id__, count(1) as import_count
FROM log WHERE __relation_type__ = 'imports'
GROUP BY __dest_entity_id__
ORDER BY import_count DESC LIMIT 20
```

## 在系统中的位置

- 该模式由 [[code-wiki]] CLI 的 [[意图化子命令设计]] 屏蔽，Agent 无需感知 graph-match 与 SLS SQL 的差异。
- 与 [[token预算优化输出格式]]（brief < 500 tokens）共同构成查询侧的 token 预算控制。
- 规模自报：约 11000 实体、19000 条边下，单次查询端到端延迟百毫秒（内部自报口径）。
