# skill创建透明度

**skill创建透明度**是 [[hermes-agent]] 相关文章 [[sources/[202604230830]深入源码HermesAgent如何实现SelfImproving|[202604230830]深入源码HermesAgent如何实现SelfImproving]] 作者三剑在"Skill 自动进化的下一步"章节提出的改进方向之一（**作者展望，非 Hermes 已实现特性**）：Agent 自动创建 Skill 的过程目前对用户完全静默，用户既不知情也无参与感；改进方向是在 Skill 创建完成后向用户发出简短通知，让用户能够审核并纠正 Agent 自主沉淀的知识资产。

## 现状问题（作者自评）

文章自评：目前 Skill 的创建是静默发生的——Agent 在后台通过 `skill_manage` 工具（触发条件见 [[skill自动创建触发条件]]）自主创建 Skill 文件，用户事后才发现。作者认为这带来两个问题：

1. **无参与感**：用户对 Agent"学会了什么"缺乏感知，难以建立信任；
2. **无法及时纠正**：若 Agent 沉淀的 Skill 内容有偏差（错误步骤、以偏概全的 Pitfalls），静默创建意味着错误会潜伏到下次复用时才暴露。

## 展望方向

创建后简短通知 → 用户可审核、可纠正。即在静默自动化（创建效率）与人审介入（内容质量）之间补上"通知"这一最小交互环节。

## 与相关概念的关系

- **与 [[human-in-the-loop]] 同族**：都是把人的判断嵌入 Agent 自主流程，但粒度不同——通知审核是事后轻量介入，美团的 human-in-the-loop 测试 SOP 是流程级深度参与。
- **与 [[验证门禁化]] 互补**：Hermes 已有硬性安全门禁（[[skill安全扫描统一门禁]] 拦截恶意内容），创建透明度补的是"内容正确性"维度——安全扫描管"是否恶意"，用户审核管"是否正确"。
- **改进对象是 [[skill自动创建触发条件]]**：schema 声明式触发解决"何时创建"，创建透明度解决"创建后让人知道"。
- **与 [[团队治理写操作二次确认]] 形成产品梯度**：开源版展望"通知+纠正"，RDSHermes（厂商自述）宣称已落地"写操作二次确认+审计"。
