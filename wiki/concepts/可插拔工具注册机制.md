# 可插拔工具注册机制

可插拔工具注册机制是[[aiagentdemo]]项目的工具层架构：所有工具实现统一的 `InnerTool` 接口，Spring 启动时自动扫描 Bean 并注册到 AgentCore，新增工具只需实现接口、无需修改已有代码（开闭原则）。

```java
public interface InnerTool {
    List<ToolCallback> loadToolCallbacks();
}
```

`ToolCallbackBuilder` 负责将工具名、描述、JSON Schema 参数定义、执行函数组装为标准 ToolCallback——即 [[spring-ai]] 的标准工具单元，最终由框架内建的 [[agent-loop]]（ToolCallAdvisor do-while）消费。

## 工具接入的统一性

该机制的价值在于把异构来源的能力收敛到同一注册口：

| 来源 | 注册方式 |
|------|------|
| 本地业务工具（get_weather 等） | 实现 InnerTool 接口 |
| RAG 能力 | 封装为 `knowledge_search` 工具（[[RAG工具化双路径]]） |
| SubAgent 生命周期 | create/chat_with/destroy 三工具（[[SubAgent生命周期工具化]]） |
| Skill | SkillManager 扫描 `classpath:skill/*.md` 转 ToolCallback |
| 外部 MCP 工具 | `{mcp_tool_name}` 从 MCP Server 发现并注册 |
| 外部 AI 应用 | `call_ideas_{name}` 调用 IdeaLab 平台 |

这正是 [[function-calling大地基论]] 的架构投影：一切能力最终都以 ToolCallback 形式进入 LLM 的工具清单。

## 跨源对照

- [[mcp工具封装模式]]（转转）：`@mcp.tool()` 装饰器将多步流水线封装为单一工具——同为「复杂能力 → 单一可调用工具」的封装，但转转面向 MCP 协议、本文面向进程内 Spring Bean；
- MCP 工具自动发现（连接时批量发现注册）与 vivo [[渐进式工具加载]]（会话中按需追加到 messages 尾部）构成工具加载时机的两极。
