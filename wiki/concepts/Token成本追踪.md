# Token 成本追踪

Token 成本追踪是 [[三层ai-coding度量体系]] 结果指标层的第三项指标，由天猫品牌行业前端团队提出，定义为**单需求关联的 Token 消耗总量**。其定位是 ROI 视角：Token 是 AI Coding 的主要投入，追踪成本可评估 AI 投入 ROI，并验证 Prompt 优化、知识库完善等运营策略的实际效果。统计基于团队内部"统一网关"的底层调用数据。

## 多维度聚合统计（原文表格，跨 chunk 拼合完整版）

| 维度 | 计算方式 | 用途 |
|------|----------|------|
| Task | 单次对话 Token 消耗 | 评估单次对话效率 |
| 迭代 | 关联到该迭代的所有 Task Token 总和 | 评估迭代级的 AI 投入 |
| 需求 | 关联到该需求的所有 Task Token 总和 | 评估需求级的 AI 成本 |

## 允许重复计算聚合策略

由于 Task 与需求/迭代是多对多关系（一个 Task 可能关联多个需求），各维度**独立聚合**关联 Task 的 Token 总和。这意味着各维度汇总值之和 ≠ 实际总消耗，但符合业务分析需要——"产品经理关心的是『这个需求花了多少 Token』，而不是『这个 Token 被几个需求共享』"。这是以业务分析可用性优先于会计精确性的显式设计取舍。

## 高消耗低采纳异常模式

将 Token 成本与 [[代码采纳率]] 交叉识别：消耗高而采纳率低的任务/需求是首要排查对象。这是结果层两项指标的首次显式联动。

## 三大应用价值

1. **趋势分析**：单需求成本下降趋势可验证 Prompt 优化、知识库完善等运营策略的效果
2. **异常识别**：结合采纳率识别「高消耗低采纳」异常模式
3. **ROI 评估**：Token 成本与需求交付价值的比值

## 需求维度明细面板

每行字段：关联仓库 | 需求描述 | 负责人 | Token 消耗量，支持按消耗量排序以定位高成本需求（来源配图数值不可提取）。

团队以该指标回应 [[数据对齐团队认知论]] 的主张：成本数据使"AI 投入值不值"从争论变为可决策问题。
