# AI Coding 第一性原理

AI Coding 第一性原理是 [[kiritomoe]] 提出的评估和决策 AI 编码任务的四维度框架，发表于《[[qoder]] Quest 1.0》文章中。

## 四个维度

### 1. 价值 — 这件事是否需要做

评估任务本身的必要性。作者指出，交付到生产的代码，往往最后 20% 的功能需要花费 80% 的时间，需要极力避免功能未走完。

### 2. 优先级 — 这件事有多重要

在 AI 能够快速执行的时代，判断"做什么"比"怎么做"更重要。这与 [[task-driven对goal-driven]] 和 [[agentic-engineering]] 中"人定义目标"的理念一致。

### 3. 认知边界 — 突破个人技术栈

利用 AI 突破个人固有技术栈限制。例如 Java 后端工程师通过 AI 开发前端或使用 Rust/Python。核心原则：**不应让人类知识储备成为 AI 的上限**。

### 4. 品味 — 人类偏见决策方案

详见 [[品味作为人机核心差异]]。品味的本质是基于经验和踩坑带来的"选择不做什么"的边界感与审慎。

## 核心论断

> 一件事情只要具备可验证性，AI 就一定能搞定，但这也带来了选择的焦虑。

这一论断的含义是：AI 大幅降低了执行门槛，使得几乎所有可验证的任务都能被完成，但人类面临的挑战从"能不能做"转变为"该不该做"和"先做什么"。

## Token 效率法则

作者提出不关注模型单价，转向追求 Token 效率及最终产物质量的理念。这一观点与 [[sota模型专属优化]] 策略呼应——为最强模型优化意味着更高的单次 Token 成本，但通过更高的 Token 效率和更好的产出质量获得总体收益。

## 跨领域关联

- 价值/优先级维度与 [[task-driven对goal-driven]] 的认知跃迁框架一致
- 认知边界突破与 [[ai-native研发模式]] "AI 从打字员到施工队长"呼应
- 品味维度为 [[agentic-engineering]] 中"人定义质量标准"提供了更深层的解释
