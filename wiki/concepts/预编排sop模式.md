# 预编排SOP模式

预编排 SOP 模式是淘天集团搜索团队在 Multi-Agent 编排上做出的一项关键架构决策：**放弃 react 式 plan-execute（Plan Agent 实时生成执行计划），转向固化 SOP**——意图 Agent 仅负责路由，子 Agent 的执行流程由人工配置或离线生成，「以有限灵活性换取高确定性」。

## 为什么放弃 plan-execute

对 plan-execute 范式的三点批判（负面证据，供 [[plan-and-execute模式]] 页参考）：

1. **误差逐级放大**：链路过长时，每级规划误差向下传递并累积（呼应 [[概率级联故障]]）；
2. **高延迟高 Token**：反复调用大模型生成与修正计划，成本不可控；
3. **幻觉难以追溯**：动态生成的执行路径出错后难以定位根因。

## 范式对照

| 维度 | react 式 plan-execute | 预编排 SOP 模式 |
|---|---|---|
| 计划生成 | Plan Agent 实时生成 | 人工配置或离线生成 |
| 意图 Agent 角色 | 全链路规划 | 仅路由 |
| 灵活性 | 高 | 有限（刻意收敛） |
| 确定性 | 低 | 高 |

## 跨源共振

预编排 SOP 与有赞「[[workflow优先于agent]]」（客服场景优先确定性 Workflow）形成跨源共振——两家团队在互不知情的情况下收敛出同一判断：**生产环境以固化流程优先，动态规划仅保留在必要环节**。差异在于：有赞以「宁可不做」为兜底，淘天以规则/小模型兜底。
