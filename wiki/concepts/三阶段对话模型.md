# 三阶段对话模型

**三阶段对话模型**是 [[得物技术]] 团队使用 [[claude-code]] 的标准流程：**需求定义 → 边界明确 → 迭代反馈**。它是针对「需求-响应」模式三大核心矛盾（[[语义鸿沟]] / [[约束衰减]] / [[目标偏移]]）的系统化解法，替代早期的单轮「需求-响应」模式。

## 阶段一：需求定义

用「**用户故事 + 验收标准**」格式描述需求，治 [[语义鸿沟]]。验收标准细到优先级筛选、权限校验、负载上限提示语、通知内容、审计字段。示例骨架：

```
【用户故事】
作为商家运营，我需要一个商家信息查询接口，
查询结果需要根据我的数据权限进行过滤
【验收标准】
 - 支持按商家ID、商家名称、商家状态进行查询
 - 支持分页查询，默认每页20条，最大100条
 - 查询结果需要根据当前用户的数据范围进行过滤
 - 商家敏感信息(手机号、身份证号)需脱敏处理
 ...（完整模板见来源页）
```

## 阶段二：边界明确

核心技巧是区分「**必须遵守**」与「**建议参考**」两层约束（详见 [[必须遵守vs建议参考约束分层]]），治表达不清与规范漂移。

## 阶段三：迭代反馈

核心是 [[增量验证]]：分模块实现逐个验证、关键节点主动暂停、持续同步技术方案，防一次性生成后的方向性返工。

## 认知科学原理

- [[工作记忆限制理论]]：7±2 信息块类比 AI 上下文负荷，故分阶段对话、单次聚焦单模块
- [[渐进式知识构建]]：先整体框架后细节，类同带新人的「架构图→模块间交互→具体实现」路径
