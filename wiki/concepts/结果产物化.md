# 结果产物化

由 vivo [[ding-junjie]] 提出，是 [[agent-canvas沙盘机制]] 四步路径的第一步。核心思想：将 Agent 输出从短暂的对话日志升级为**可审阅、可比较、可存档的正式产物**。

## 六类正式产物

1. **配置快照** — 变更前的完整状态记录
2. **数据前后对比** — 关键指标的变更前后数值
3. **变更提案** — 结构化的变更意图和方案说明
4. **审批记录** — 谁在什么时候基于什么信息做出了什么决定
5. **指标验证报告** — 变更效果的量化验证结果
6. **生效记录和补偿方案** — 实际执行结果和异常情况下的兜底方案

## 核心论断

> "很多 agent 系统最终沉淀的只有对话和日志，不足以支撑审阅、审批和回溯。"

产物化是审核和回滚的抓手——没有产物就没有审阅的对象、没有回滚的锚点。

## 与 Wiki 其他概念的关系

- 与爱奇艺 Specflow 的 [[ssot单文档策略]]（plan.md 作为唯一产物载体）思路相通，都强调 Agent 工作结果的物质化和持久化。
- 与有赞共享技术的 [[knowledge-wiki]]（`.wiki/` + Git submodule 知识版本管理）在"所有变化都有产物有历史"理念上一致。
- 产物化是 [[agent可观测性六维度]] 中"failure"和"recovery"维度的基础——没有产物记录就无法回溯失败原因和设计恢复策略。
