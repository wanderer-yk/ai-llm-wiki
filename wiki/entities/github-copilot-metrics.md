# GitHub Copilot Metrics

## 身份说明

GitHub Copilot Metrics 是 GitHub 官方面向组织提供的 AI 编码使用度量能力：聚合统计 GitHub Copilot 的代码补全建议采纳率、使用活跃度、按语言与 IDE 的使用分布等厂商侧指标，供企业评估 AI 编码工具的部署与使用情况。（以上身份描述为公开可验证的背景信息，非源自本文；下文对其局限性的分析均出自本文来源。）

## 在天猫度量篇中的角色

天猫 AICoding 度量篇（见 [[sources/[202603251545]拒绝感觉有效用数据证明AICoding的真实团队价值天猫AICoding实践系列-20260929|度量篇]]）将 GitHub Copilot Metrics 作为**"厂商聚合指标"的典型参照物**：这类由工具厂商提供的开箱即用指标，代表业界普遍"以 [[代码采纳率]] 证明 AI Coding 价值"的口径。天猫团队论证该口径不足以证明真实团队价值，并以自建的 [[跨系统数据关联机制]] 与之对照，双方对比详见 [[Copilot Metrics与天猫跨系统数据关联对比]]。

## 局限性（按源文论证，归属天猫度量篇语境）

1. **停留在工具层单点指标**：按 [[三层ai-coding度量体系]] 视角，其指标止步于工具层，无法证明工程层结果与业务层价值；
2. **数据孤岛**：聚合口径与团队需求系统、代码仓、质量数据脱节，缺乏多源数据按主体/时间关联的能力；
3. **采纳率失真**：其核心指标采纳率存在 [[碰巧正确vs稳定正确]] 问题——AI 产出单次通过 ≠ 稳定正确，采纳 ≠ 正确 ≠ 价值；
4. **追踪终点过短**：追踪止于生成/采纳环节，未按 [[追踪终点延伸论]] 延伸到下游质量与业务结果。

## 边界说明

以上局限均为天猫团队在其自报实践语境中的论证，用于说明"为什么厂商聚合指标不够用"，不构成对该产品功能的完整客观评测，也不应迁移为对其他团队度量方案的判断。
