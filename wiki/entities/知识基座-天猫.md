# 知识基座（天猫）

知识基座是 [[天猫品牌行业前端团队]]（[[珈文]]）构建的 AI 全栈研发知识基座系统，旨在让 AI 越用越懂业务。区别于一般知识库，它强调团队经验的持续沉淀与自动注入，核心特色能力为云端统一下发 + 信号驱动智能沉淀 + 业务域物理隔离。

## 核心架构

### 三组件系统

- **Client 终端**：AI 编码插件，开发者在 VS Code 中打开仓库时自动识别业务域、动态拉取配置
- **知识库服务（MCP Server）**：提供 `search-knowledge` 和 `knowledge-search-experience` 检索接口
- **管理端**：维护各业务域配置规则，支持 JSON 实时校验编辑

### 四通道数据流

1. **配置下发**：Client→配置中心，独立同步通道确保规则变更实时触达
2. **知识库调用**：通过 MCP 协议获取物料规范
3. **数据上报**：埋点统计
4. **内容同步**：管理端→知识库服务

### 配置匹配四层优先级

业务域显式指定 > Git Group/Repo 静态匹配 > 人群工号圈选 > 全局默认配置

## 三大核心机制

### 1. 信号驱动的智能沉淀

基于 [[99-1会话价值分布]] 洞察，通过 [[8步沉淀闭环]] 自动捕获隐性经验。信号识别包括关键词信号（报错/否定）和行为信号（工具调用模式）。知识提炼产出三类标准化知识：pitfall（踩坑与修复）、decision（方案选型）、faq（高频问答）。

质量评估五维度：confidence、accuracy、reusability、completeness、actionability。三级审核优先级：confidence ≥ 0.9 且 overall ≥ 4 直接入库；0.7-0.9 人工快速确认；< 0.7 深度审核。

### 2. 云端统一下发

基于 Git Group/Repo 信息自动匹配业务域，三核心原则：仓库维度（配置跟仓库走）、增量更新（保留自定义）、自动写入（打开即检测）。配置自动写入 `.plans`/`context.json`/`mcp.json`/`AGENTS.md` 等项目文件。

### 3. [[业务域物理隔离|多来源知识汇聚]]

每个业务域独立维护四类配置文件：`agent.md`（Agent 行为定义）、`mcp.json`（MCP Server 配置）、`domain.yaml`（业务域规则）、`skills/`（技能包）。通过 [[分层加载策略]]（基础知识全局加载 + 专项知识按需检索）和 [[多来源知识汇聚]] 直接对接集团内部已有知识源。

## 落地规模

- **覆盖范围**：3 个业务域（业务域C / 某电商平台行业供应链 / 业务域B）
- **人员**：近 40 名后端工程师
- **周期**：2 个月
- **需求量**：月均 20-30 个前端需求
- **发布平台**：工作台 A/C/D + 运营平台

## 召回效果

- 1 个月自动捕获 128 条经验（pitfall 51% / faq 32% / decision 17%）
- 平均置信度 0.92，89% 可直接入库或抽查审核
- 召回率 85%，平均返回 2.3 条，pitfall 召回率 88%
- 零结果查询占 15%（作为知识缺口信号）
- 当前知识量 < 1000，使用关键词检索，正向 RAG 向量检索（LanceDB）迁移

## 与其他知识库系统对比

知识基座采用中心化云端统一下发，与 [[knowledge-wiki]]（有赞 `.wiki/` + Git submodule 分布式架构）和 [[活文档机制]]（腾讯 archive 命令代码内同步）构成三种不同的知识管理范式。

## 未来方向

[[全链路ai驱动]] 是终局目标——AI 不仅生成代码，也自动判断知识应沉淀到哪一层（通用组件文档/业务领域知识/实践经验总结），通过语义理解自动分类和路由。
