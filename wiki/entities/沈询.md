## 核心观点

### 第一篇：ReAct 相关（2026-02-24）

- **ReAct = 边想边做**：观察→思考→行动循环，而非事先规划全部流程
- **ReAct 实现五要素**：历史上下文 + 当前环境信息 + LLM Thinking + toolcall + 观察结果（见 [[react五要素]]）
- **思考是可选输出**：思考如人的内化思考，最终外显形式就是 toolcall（见 [[思考内化论]]）

### 第二篇：Agent vs 传统编程 vs Workflow 相关（2026-02-25）

- **[[决策权三分法]]**：传统编程/Workflow/Agent 的本质区别在于决策者分别是程序员/产品开发/AI
- **[[编程与工作流同源替代论]]**：Workflow 与编程同源，已被代码凭复用性和扩展性胜出；Agent 是决策权下放后的新范式
- **[[业务自闭环]]**：Agent 使“发现→测试→解决”形成业务侧闭环，“几分钟”（自报无口径，见下方存疑声明）
- **[[ai增强与agent体验二分选型]]**：既有系统增强用代码 + toolcall，创新产品用 Agent

### 第三篇：Function Calling / MCP / Skills 相关（2026-02-26）

- **MCP 与 Skills 竞争大于互补**（[[mcp与skills竞争关系论]]）：明确反驳流行的“互补说”，主张两者是同一问题（整合多既有系统完成复杂多步任务）的两种解法，选此失彼
- **Function Calling 桥梁论**（[[function-calling桥梁论]]）：FC 是非结构化自然语言需求与结构化系统调用之间的桥梁，是 MCP 与 Skills 存在的前置条件
- **任务流程定义困难问题**（[[任务流程定义困难问题]]）：模型自主调度不精确与全代码化丧失动态性的两难，是 Skills 与 Func-Agent 的共同起源
- **一切都是函数**（[[一切都是函数]]）：“函数才是第一公民”，Func-Agent 设计哲学
- **Skills 两大未解问题**（[[skills两大未解问题]]）：description 不结构化、只能聊天式接驳
- 第三篇还沉淀了 [[mcp薄协议转换层]]、[[skills-sub-agent包装论]]、[[skills四阶段运行流程]] 等概念
