# Dify

智能体开发平台（低代码/无代码），支持可视化构建 AI 应用流程。有赞共享技术团队在 AI 客服建设中内部独立部署使用。

## 在有赞 AI 客服中的角色

### 验证期（PMF 验证）

- 帮助团队从内部黑客马拉松出发快速验证 AI 客服的产品市场匹配
- 可视化拖拽式流程设计，大幅降低原型搭建门槛
- 适合快速迭代和概念验证

### 发现的生产环境瓶颈

| 问题 | 具体表现 |
|------|----------|
| 性能瓶颈 | 简单 Python 代码节点执行耗时 40-100ms |
| 检索实时性不足 | 知识检索组件无法满足客服实时响应要求 |
| 运维规范缺失 | 低代码平台缺乏企业级运维支撑 |

### 成长期（混合架构）

- 核心链路逐步迁移至工程化代码，但 Dify 仍保留用于特定场景
- 历史对话知识提取在工程化代码中调试困难时，切回 Dify 取得突破
- 使用 [[spring-ai-alibaba-studio]] 将 Dify 流程导出为标准 Spring AI 工程代码

### 踩坑经验

- [[qwen]] 模型对 Dify 内置记忆机制敏感，导致幻觉加剧
- 团队因此自行维护全局历史变量替代平台记忆机制，解决了幻觉问题

## 方法论贡献

Dify 的使用经验催生了 [[三阶段平台演进路线]] 方法论：验证期用低代码平台快速 MVP → 成长期混合架构过渡 → 成熟期全工程化。这一方法论对其他 AI 应用落地具有参考价值。

## 来自得物技术篇的证据（2026-01）

- **得物跨团队落地证据（2026-01）**：机器人问答功能中 Dify 作为第三方 API 集成——DifyClient 封装、重试降级策略、integration_log 表留痕。与有赞「内部独立部署平台」场景互补：Dify 既可作平台也可作被调用的外部服务。
