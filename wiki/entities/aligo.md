# AliGo

AliGo 是 [[阿里商旅]] 旗下的 AI 差旅助手产品：用户输入行程时间地点后自动规划行程、推荐交通方式，串联"出差事项收集 → 行程规划 → 一键下单"业务闭环。本文所述架构、意图识别、上下文工程、Prompt 状态机、知识库、观测与评测均为其实现。

## 架构演进

- **v1（workflow + 单智能体）**：Prompt Token 急剧增长致注意力机制明显衰减，点选需求经百余次 Prompt 调优准确率仅约 50%；线上频发"事项识别异常请重试""事项收集结论不输出"。
- **v2（基于 [[agentscope]] 的多智能体）**：以主规划智能体 main_plan_agent 为核心协调 10+ 专业化子智能体（主规划/意图识别/行程规划/信息查询/RAG 知识库等），采用 Handoffs（交接）+ Routing（纯路由）混合模式——行程规划、知识库查询走 Routing，信息查询走 Handoffs。技术栈为 Python AI 核心 + Java 服务层（鉴权/MTop/MCP 服务）。

## 关键机制

- **意图识别智能体四职责**：多意图识别和分类、智能体调度决策、query 改写、显示推理（"推理过程 + JSON 决策"两段式输出）；模型推荐 Qwen3-Next-80B-A3B-Instruct（[[qwen]]）。
- **快慢车道**：规则引擎快车道命中即直通路由，大模型慢车道处理复杂语义。
- **[[动态prompt生成机制]]**：运行时按规则引擎 `classifier.classify()` 结果选择简单/复杂意图 Prompt 模板，本质是"为 AI 构建状态机"。
- **实时思考链与流式输出**：ReActAgent Hooks + TaskCollector（PENDING/DOING/DONE/FAILED 生命周期）+ SSE 输出流，用 UX 透明化对冲多智能体的延迟代价。
- **上下文工程四组件**：全局上下文管理 / 会话记忆管理 / 动态 Prompt（状态机）/ 工具注册管理；三表存储（消息存储表/会话管理表/对话记录表）；默认隔离 + 按业务关系与最小权限原则动态共享（见 [[上下文工程]]）。
- **设计哲学**：[[工程确定性与ai灵活性平衡]]——工程侧协同模型圈定注意力焦点与业务边界，边界内交由 AI 自主处理。

## 周边生态

- **知识库**：[[aligo企业级知识库]]，基座为 [[MaxKB]]。
- **观测**：[[langfuse]]，Trace/Session/User 三维观测，打通观测-评测流程（[[观测评测闭环]]）。
- **评测**：AI 测评系统，通义千问自动评分（准确性 + 相关性）、测试全生命周期管理、可视化报告与版本对比。

## 效果与奖项

- 事项收集准确率 50% → 90%+；升级前不可解决 bug 列表 100% 解决；12 月代码化版本上线后体感与指标逐步变好。
