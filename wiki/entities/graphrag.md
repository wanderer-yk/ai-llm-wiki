# GraphRAG

GraphRAG 是微软于 2024 年提出的知识图谱增强 RAG 方法（独立可验证的公开背景；本 Wiki 证据来自 [[跨端技术团队]] 文章及其引文 [[edge-2024-graphrag|GraphRAG 论文]]，arXiv:2404.16130）。其核心思路一句话概括：把"基于文本片段的平面检索"升级为"基于实体-关系网络的结构化检索"——类比从散乱卡片到整理好的思维导图。

## 索引构建四步流水线

1. **文本分块与实体抽取**：TextUnit 分块 + LLM 实体关系抽取，产出三元组（如 (WebView, 是, 渲染容器)）。
2. **图构建与合并**：跨文档同实体合并，消除"信息孤岛"。
3. **社区发现**：Leiden 算法（Louvain 改进版），保证社区内部连通、避免"断裂社区"；社区树顶层为全局主题（如"跨端渲染架构"），底层为具体细节（如"WebView 离线包加载策略"）。
4. **社区摘要生成**：LLM 为各层级社区生成摘要。

## Local / Global 双查询模式

- **Local Search**：embedding 定位实体→沿图谱边扩展→原文+社区报告拼装上下文，适合具体问题。
- **Global Search**：遍历社区摘要做 Map-Reduce 汇总，适合宏观综合问题；传统 RAG 缺社区层级无法实现此能力。

## 跨端技术团队实测（44 篇文档，Streamlit 可视化）

效果兑现：复杂问答与全局理解显著提升，跨多篇文档综合信息的问题回答明显更全面、更有条理（定性表述，无量化数字）。

## 四大致命工程问题

实测确认四个困境使其"在答疑场景几乎不可用"：①索引构建成本极高（GPT-4 级别依赖，"费用不菲"）②不支持增量更新（"最致命"，社区边界重划→摘要重生成，实践中多数团队定期全量重建）③查询延迟过高（Global Search 5 分钟+）④对抽取质量高度敏感（弱模型→图谱噪音→检索质量反而不如传统 RAG）。详见 [[graphrag工程化四困境]]。

## 场景定位与衍生

- **场景定位**：高成本、极致质量的离线分析场景（与 LightRAG 的在线实时答疑定位相对），完整对照见 [[graphrag与lightrag对比]]。
- **核心启示**（据来源文章）：图结构确实有效解决上下文断裂与跨文档推理，但工程化方案太重。
- **前沿衍生**：MiniRAG——图增强 RAG 在小模型（SLMs）上的尝试，异构图索引（文本片段节点+语义概念节点）+拓扑增强检索，面向端侧等资源受限场景（来源文章仅综述未实践）。

## ## 第二口径：《RAG全链路技术详解》（2026-05）

- 建图四步第二口径：文本切分 → LLM 提取实体/关系三元组 → 汇聚去重消歧建全局图 → **社区检测（Leiden 算法聚合+LLM 生成社区总结）**；与既有四步流水线互证，Leiden/社区总结为本源增量细节。
- 检索两模式流程化：局部=关键词定位实体→n 跳邻居→结构化喂 LLM；全局=宏观主题检索预生成社区摘要→汇总回答。
- 代表性框架清单点名 Microsoft GraphRAG / LlamaIndex / LightRAG。本源为正面完整教学口径，与 [[graphrag工程化四困境]] 的落地困难视角构成跨源张力。
