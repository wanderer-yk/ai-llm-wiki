# 24h打工人

[[zhiyuanfu]] 命名并设计的 24 小时无人值守 AI 开发系统。能自动完成 bug 分析、技术方案生成、任务拆解、并发执行代码修改、通知 review。

## 核心架构

**四字概括：文件+轮询。** 文件系统存储 + 轮询调度 + JSON 状态管理。

### 三大组件
- **FileQueue** — 文件队列，任务写入/读取
- **ToolProber** — 工具探测，自动探测可用 CLI 工具，配额耗尽时冷却+换工具
- **JsonStateManager** — JSON 状态持久化

### 调度四职能
1. **接收任务** — 写入文件队列
2. **分发执行** — 轮询调用 CLI（[[codex]]/[[gemini-cli]]/[[claude-code]]）
3. **状态管理** — 持久化输入输出
4. **失败切换** — 配额耗尽自动换工具+冷却 5 分钟

### 并发策略
- **组间并发** — 不同项目目录同时执行
- **组内串行** — 同项目排队防冲突
- **失败隔离** — 单任务故障不扩散

## SDD 文件体系

每个需求产出完整文件链路：
```
storage/feedbacks/{date}/{id}/
├── sdd/
│   ├── spec.md     (规格)
│   ├── plan.md     (方案)
│   └── tasks.md    (任务清单)
└── debug/
    ├── prompts     (Prompt 记录)
    └── agent.log   (Agent 日志)
```

## 关键设计决策

- 选 CLI 而非 API：阶段性选择，[[cli优于api的阶段论]]
- 文件系统+JSON 起步优于数据库：出 bug 可让 AI 直接读文件排查
- 不是重新造 Agent，而是造管理 Agent 的调度层

## 自举案例

系统通过自身反馈系统提交 bug → 触发 SDD 流程 → 自动定位修复 → 企微通知完成。真实案例：RadioGroup 组件 onChange 未绑定，系统自动完成全流程修复。前提是三项基础设施：设计文档 + SDD 流程 + constitution.md。

## 系统地基

SDD 五层文件体系构成完整地基：spec.md → plan.md → tasks.md → constitution.md → eval/trace/policy。
