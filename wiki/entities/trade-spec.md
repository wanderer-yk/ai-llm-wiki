# Trade Spec

Trade Spec 是淘天集团[[交易业务技术团队]]构建的内部 Spec 平台的正式名称（别名：Spec 平台、交易Spec平台；文中的「trade spec」commit 埋点标识与之对应），用于在淘系交易域实践「范式编程」（[[规格驱动ai开发]]/SDD 的本文别名）。其核心价值一句话：「通过提案、技术方案、代码生成的全链路规范化，培养适合交易场景的 AI 专家」——即不是训练通用代码生成 AI，而是通过持续知识沉淀培养懂交易业务的 AI 领域专家。核心基建自述：知识库召回、知识点配置、疑问点机制和 SOTA 模型 Agent 集成。

## 架构组成

- **研发链路（已实现六环节）**：需求 PRD 输入 → Proposal 整合 → 技术方案生成 → 生码执行 → 研发评审 → 流水线集成。
- **双通道 Agent**：SOTA 通道（Python 自建 Agent，基于 [[claude-agent-sdk]]/[[claude-sonnet-4-5]]，触及能力边界）+ [[aone-agent]] 通道（内部模型/安全红线/[[aone]] OpenAPI 集成，守住安全底线）。
- **沙箱**：[[aonesandbox]] 承载，弹内测试网模式；集团生产网禁止运行沙箱类服务。
- **知识体系**：知识底座（SOTA模型+subAgent 生成仓库 wiki，[[deepwiki]] 落选）；双路召回（KBase 语义检索=广度 + 索引导航式召回=精度）；知识点机制（概念澄清 + 「业务术语→代码位置」定位；触发关键词按需召回）。
- **技术方案模版**：proposal.md（Why & What，人机对齐业务价值）/ design.md（系统结构、关键决策、数据模型或 API 接口变更）/ tasks.md（实施任务清单）；proposal 与 design 构成两阶段流水线。
- **提示词工程**：Hooks 事件驱动（保证关键动作触发）+ Skills 渐进式披露（300 多行→50 行核心指令；「知识库召回」技能封装多工具编排；一次提案 5 个 Skills 披露）+ 疑问点机制（JSON 输出的软澄清，把「生成后返工」前置为「生成前对齐」）。
- **产品界面 6 功能区**：变更列表区、PRD 输入区（支持[[钉钉文档]]链接导入）、提案展示区、技术方案区、知识库配置区、执行状态区（[[aone]] 变更链接 + CR 入口）。

## 评测与演进

评测体系为质量/效率/使用度三维度：生成质量以 F1-score 度量（基线 F1-方案 94.44%/F1-代码 62.66%，2026-01；详见 [[生码F1-score定义]]）；效率基线含研发效率提升比 40%；易用度基线覆盖 2 领域/WAU 8 人/人均 2 次/满意度 4.5。演进路径见 [[阶段性目标表]]（近期跑通核心闭环→中期规模化→远期 [[AI-Friendly编程环境]]），长期愿景见 [[AI领域专家搭档愿景]]。

## 跨源定位

与 [[specflow]]（爱奇艺）、[[openspec]]（腾讯采用）、[[github-spec-kit]] 构成 SDD 工具家族同构谱系；其「OpenSpec 为主、结合 SpecKit 部分特性」的选型结论与三工具 8 维对比（7:1）为 SDD 工具选型提供了第三份独立证据。
